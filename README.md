# HoBo

> Write your app once. HoBo decides how to host it — and gets out of the way when you want control. Built for humans and the agents that work for them.

**HoBo** is a developer-centric, cloud-agnostic platform whose programmable surface is **WIT/WASM** (the Component Model / wasmCloud), plus an intermediary cloud control plane ("the Yard"). **TypeScript is the first reference implementation, not a requirement** — any Component-Model language can author against the same WIT worlds. Describe your app once through PaaS / SaaS / CaaS / IaaS abstractions; a provider pattern (ports & adapters) maps it onto real providers — agnostic by default, optimizable on demand via typed provider-specific options. The runtime is AI-native: actor-model + choreography sagas over a replayable event store, with durable workflows and agents as first-class authenticated users.

> **Status: design phase.** No **HoBo product** implementation code yet — this repository holds the design plans and requirements. (The only code present is third-party AI agent-tooling under `.agents/`, `.claude/`, and `scripts/` — see [Working in this repo with AI agents](#working-in-this-repo-with-ai-agents).) See [`docs/design/`](./docs/design/README.md).

## Design plans

The design is split into independently iterable numbered plans (`00`–`48`, a few tombstoned) under [`docs/design/`](./docs/design/README.md). Suggested reading order: **[0 Vision](./docs/design/vision.md#plan-00) → [10 Architecture overview](./docs/design/architecture.md#plan-10) → [19 Worked example](./docs/design/worked-example.md#plan-19)**, then the two deep plans **[2 SDK/API ⭐](./docs/design/sdk-api.md#plan-02)** and **[6 AI-native & agent auth ⭐](./docs/design/ai-native-agent-auth.md#plan-06)**. HoBo is an **AI-native meta-cloud** that is **security-first, AI-native, platform-engineering built-in, and patchable** — with built-in **Operator Agents** ([40](./docs/design/operators-sre.md#plan-40)), a **generated stack** across data/business/message/intelligence/UI ([41](./docs/design/forge-generated-stack.md#plan-41)), **patchability** beyond portability ([43](./docs/design/forge-generated-stack.md#plan-43)), and **SRE incident management & self-healing** ([44](./docs/design/operators-sre.md#plan-44)). Data is **materialized from event streams and subscribed to** (RX-style), not queried from a DB ([32](./docs/design/data-plane.md#plan-32)/[ADR-0050](./docs/design/adr/03-data-plane.md#adr-0050)). Scope is bounded to the meta-cloud — no SaaS-business functions ([ADR-0064](./docs/design/adr/08-scope-and-requirements.md#adr-0064)); app generation (UI included) is in scope.

Design inspiration: the API *feels like* [Vercel Workflows](https://workflow-sdk.dev/) for its durable `workflow`/`step` ergonomics, but the durable runtime is **HoBo-native and provided per Camp**. HoBo is positioned as a cloud-agnostic, AI-native alternative to closed agent-native PaaS offerings.

## Requirements (BRD / PRD / TRD)

The formal requirements layer lives in [`docs/requirements/`](./docs/requirements/README.md): a [BRD](./docs/requirements/BRD.md) (business), [PRD](./docs/requirements/PRD.md) (product), and [TRD](./docs/requirements/TRD.md) (technical) with stable `BR`/`FR`/`NFR`/`TR` IDs and an end-to-end [traceability matrix](./docs/requirements/TRD.md#traceability-matrix). Decisions made while authoring them are logged as [ADRs 0018+](./docs/design/adr/README.md).

## Working in this repo with AI agents

This repo is wired for **Claude Code**, **Cursor**, and **Codex** with seven agent tools — **improve** (audit→plans), **superpowers** + **mattpocock/skills** (methodology/grilling), **caveman** (output compression), **ponytail** (minimalist-solution / anti-over-engineering), **headroom** (context compression, MCP), and **gbrain** (knowledge-graph memory, MCP). See [`AGENTS.md`](./AGENTS.md) and [`docs/agent-tooling.md`](./docs/agent-tooling.md); install with [`scripts/setup-agent-tools.sh`](./scripts/setup-agent-tools.sh). Note: gbrain needs an embedding API key and sends content to that provider.
