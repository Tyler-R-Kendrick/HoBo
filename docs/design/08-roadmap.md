# Plan 8 — v1 delivery plan / build sequence

> Part of the [HoBo Design Plan Suite](./README.md). **HoBo ships as a single v1**: the entire designed surface — every plan in this suite — is v1 scope. There is no v2/v3/… release split and no "post-v1" bucket ([ADR-0063](./adr/ADR-0063-single-v1-scope.md)). To deliver a large v1 quickly and effectively, the build is **dependency-ordered into stages** — you can't build multi-provider before the core, or Forge before conformance — but each stage is part of the *one* v1, not a separate version. Each stage names its acceptance gate ("done when…").

> **Stepwise breakdown:** each build stage below is expanded — workstreams + acceptance gate — in [Per-stage build detail (stages 0–6)](#per-stage-build-detail-stages-06) further down this doc ([Stage 0](#stage-0--foundations) · [Stage 1](#stage-1--sdk-on-the-local-runtime) · [Stage 2](#stage-2--first-real-deploy) · [Stage 3](#stage-3--ai-native-core) · [Stage 4](#stage-4--multi-provider--wiring-depth) · [Stage 5](#stage-5--forge) · [Stage 6](#stage-6--ha-finops-ux--governance-planes)). ## Success metrics (north-star signals — v1 targets)
- **Time-to-first-deploy** (scaffold → running on a real cloud) — target minutes, not hours.
- **"Same Bindle, N clouds"** — number of providers a single unedited example deploys to.
- **Zero-secret rate** — % of provider access via brokered/federated tokens vs static keys (target ~100%).
- **Agent-completable lifecycle** — % of deploy/operate tasks an agent can do via MCP unaided.
- **Forge yield** — % of requested providers auto-generated that pass conformance.
- **Recovery** — deploy resume time after node loss; projection-rebuild time.

## Sequencing rationale
One v1, built in dependency order. Stages 0–2 stand up the *agnostic deploy* core on one cloud (with governance gating it from the first deploy); stage 3 makes it *AI-native*; stage 4 proves *true multi-provider*; stage 5 adds *extensibility without a community* (Forge); stage 6 hardens for production and lands the breadth (HA, FinOps, full UX, SRE, the `notify` port + governance enforcement + AI-safety + Registry distribution). The risky/novel bets (Forge, multi-region HA) build on a demonstrably solid core, but all of it is v1 — the stages are *how* we deliver a large v1 quickly, not a schedule of separate releases.

## Per-stage build detail (stages 0–6)
The numbered workstreams below are the dependency-ordered build sequence of the single v1 — **not** separate releases. Each stage is independently demoable and must keep prior acceptance gates green (no regressions). Conventions: **port = WIT interface** ([Plan 20](./20-wasm-wasi-runtime.md), reference [Plan 24](./24-wit-interfaces-reference.md)) · **provider = capability provider** · **bind = link** · **service = wasm component (default), OCI-container fallback**; every adapter ships against `@hobo/conformance` and examples double as E2E fixtures.

### Stage 0 — Foundations
Realizes [Plan 1](./01-monorepo.md), [Plan 11](./11-event-model.md), [Plan 20](./20-wasm-wasi-runtime.md), [Plan 24](./24-wit-interfaces-reference.md), [Plan 9](./09-verification-open-questions.md). **Objective:** stand up the monorepo, the core contracts (types, ports-as-WIT, event envelope, Capability Manifest schema), the built-in local runtime, and the conformance harness. **Depends on:** nothing (greenfield). Also seeds Resource Definition + Matching types, the Driver interface ([Plan 25](./25-resource-definitions-matching.md)/[Plan 27](./27-drivers-packs-profiles.md)) and a Driver conformance slot.
1. **Monorepo & tooling** — pnpm/Turborepo workspace, strict `tsconfig`, Biome, Vitest, Changesets; package skeletons from [Plan 1](./01-monorepo.md); enforce the dependency rule (adapters depend only on `core` interfaces); CI typecheck→lint→unit→conformance→build + SBOM/vuln-scan stub ([Plan 12](./12-security-multitenancy.md)).
2. **`@hobo/core` contracts** — EventEnvelope + append/read/idempotency rules ([Plan 11](./11-event-model.md)); port interfaces as TS mirrors of canonical WIT ([Plan 24](./24-wit-interfaces-reference.md)); Capability Manifest schema (`capabilities/auth/cost.json`) + validators ([Plan 6](./06-ai-native-agent-auth.md)); DI/container + the durable `Runtime` interface.
3. **`@hobo/wit` (the ports)** — author the `hobo:*` WIT interfaces + vendor/pin reused `wasi:*` ([Plan 24](./24-wit-interfaces-reference.md)); `jco guest-types` → typed TS bindings.
4. **`@hobo/runtime-local` (built-in engine)** — EventStore (append log + subscriptions/snapshots), Queue (at-least-once + dedup), Streamer, ActorHost (single-writer lease + fencing), deterministic Clock; `testRuntime()` mode for [Plan 9](./09-verification-open-questions.md).
5. **`@hobo/conformance` (trust boundary)** — harness that runs a suite against any adapter; first suites = the five runtime ports; wire conformance into CI as a required gate.
- **Acceptance gate:** `runtime-local` passes all runtime-port conformance in CI; an event log appends and replays to identical state; `jco`-generated types compile; dependency-boundary lint passes.
- **Key risk/hook:** wasm host of record (Wasmtime vs jco-in-Node) — decide here, it colors stage 1; `hobo:*` naming/versioning vs upstream `wasi:*` churn; built-in-engine scope vs external runtime in prod ([Plan 5](./05-reliability-ha.md)).

### Stage 1 — SDK on the local runtime
Realizes [Plan 2](./02-sdk-api.md), [Plan 21](./21-resources-catalog.md), [Plan 22](./22-wiring-manifest.md), [Plan 20](./20-wasm-wasi-runtime.md), [Plan 15](./15-cli-dx.md). **Objective:** author an app IfC-style, run it as a wasm component on `runtime-local` (workflows/actors/sagas/agents), collect resources into a manifest — all offline, with replay. **Depends on:** stage 0. Resources gain a `class`; local Planner resolves Resource Definitions by Matching ([Plan 25](./25-resource-definitions-matching.md)) and `hobo dev` exercises Deltas→Sets + env types ([Plan 26](./26-environments-deltas.md)).
1. **Authoring & resources (`@hobo/sdk`)** — resource builders for the full catalog ([Plan 21](./21-resources-catalog.md)); the `.allow(verbs)` model (IAM + links + token scope); handler/trigger registration; the explicit `bindle()` topology escape hatch.
2. **IfC resource-collection → manifest IR** — resource-collection mode (capture resources + `.allow()` without running handlers, [Plan 21](./21-resources-catalog.md)); emit the manifest IR ([Plan 22](./22-wiring-manifest.md)), content-address + record `bindle.ManifestProduced` ([Plan 11](./11-event-model.md)); lazy Aspire-style bindings → typed `ctx.bindings.<name>`.
3. **Runtime primitives (`@hobo/runtime`)** — `step`/`workflow`/`emit`/`sleep`/`cron`/hooks/streams; `actor`/grain + `saga`; `agent()` skeleton + `stub()` placeholders ([Plan 23](./23-stubbable-ai-implementations.md)); determinism (seeded RNG/clock) verified by replay.
4. **Components (`@hobo/componentize`, `@hobo/build-wasm`)** — TS service → wasm component via jco/componentize; run on the local wasm host wired to `runtime-local` providers; produce/load OCI artifacts locally.
5. **CLI & local dashboard (`@hobo/cli`)** — `hobo new`/`dev`/`collect`/`inspect`/`logs`/`stub`; local dashboard MVP (topology, run inspector, resource browsers, triggers) ([Plan 7](./07-ui-dashboard.md)).
- **Acceptance gate:** `hello-bindle` runs offline as a wasm component exercising workflow+actor+saga+stubbed port; `hobo collect` matches a manifest fixture; replay==live-state determinism test green; dashboard shows topology + a run trace + triggers.
- **Key risk/hook:** directive (`"use workflow"`) compiler transform vs runtime wrappers ([Plan 2](./02-sdk-api.md)); IfC collection fidelity for non-TS; jco/StarlingMonkey build ergonomics + cold-start.

### Stage 2 — First real deploy
Realizes [Plan 3](./03-providers-iac.md), [Plan 4](./04-control-plane.md), [Plan 10](./10-architecture-overview.md), [Plan 11](./11-event-model.md). **Objective:** take a collected manifest and deploy it to one real cloud through a minimal Yard, with the event-sourced deployment lifecycle + crash-resume. **Depends on:** stage 1. The Planner resolves via Resource Definitions + Matching ([Plan 25](./25-resource-definitions-matching.md)), IaC apply is the `terraform` Driver ([Plan 27](./27-drivers-packs-profiles.md)), deployment runs Delta→Set ([Plan 26](./26-environments-deltas.md)); the **Gatekeeper** lands at Delta→Set — `contract-engine` + `can-deploy` ([Plan 29](./29-contracts-compatibility.md)) and `policy-engine` ([Plan 30](./30-policy-plane.md)) block an unsafe first deploy with an explainable, event-sourced reason.
1. **IaC adapter (`@hobo/iac-pulumi`)** — wrap the Pulumi Automation API (preview/apply/destroy/refresh); per-resource stack model + state backend + outputs ([Plan 3](./03-providers-iac.md)).
2. **First CloudProvider (Cloudflare *or* Fly)** — a few capability ports (`web`/`service`, `kv`, `objectStore`) as a capability provider; equivalence-class mappings + `.with(...)`; publish its Capability Manifest ([Plan 6](./06-ai-native-agent-auth.md)) + link wiring ([Plan 20](./20-wasm-wasi-runtime.md)).
3. **Production runtime (`@hobo/runtime-postgres`)** — the five runtime ports on Postgres (graphile-worker queue, NOTIFY/LISTEN streams, snapshots); pass runtime-port conformance.
4. **Yard (first cut) (`@hobo/cloud`)** — Gateway (RPC+REST, authn/z, commands→events); Planner (manifest IR → `DeploymentPlan` DAG, [Plan 3](./03-providers-iac.md)); Orchestrator + ResourceActors (reconciliation FSM + choreography, [Plan 4](./04-control-plane.md)); Executors (Firecracker-sandboxed IaC apply + build, scoped creds); event store = Postgres runtime; OCI artifact push.
5. **CLI deploy path** — `hobo plan`/`deploy`/`destroy`/`inspect deploy`; `hobo login` (dev SVID stub).
- **Acceptance gate:** `hello-bindle` deploys to one real cloud and serves traffic; kill the Yard mid-deploy → resumes from the event log; a provisioning failure → saga compensation rolls back in reverse-dependency order; the deployment timeline projection reconstructs the run.
- **Key risk/hook:** default first provider (Cloudflare vs Fly vs local Docker); per-resource vs grouped IaC stacks + drift policy ([Plan 3](./03-providers-iac.md)); deployed wasm host target.

### Stage 3 — AI-native core
Realizes [Plan 6](./06-ai-native-agent-auth.md), [Plan 12](./12-security-multitenancy.md), [Plan 14](./14-observability.md). **Objective:** agents become first-class principals — keyless identity + token brokering, a Capability Manifest registry, durable agents, an MCP control surface — so an agent deploys with zero static secrets + a full audit trail. **Depends on:** stage 2. Also lands the **HoBo Relay** (outbound-only private-network deploys) + the **GitOps publisher** ([Plan 28](./28-relay-gitops-pipelines.md)), both leaning on the SVID work; the Registry begins accepting Forge-generated Definitions/Packs.
1. **Identity (`@hobo/identity`)** — SVID issuance (SPIFFE-style JWT-SVID, attestation + rotation, [Plan 6](./06-ai-native-agent-auth.md)); OIDC provider (federation); token broker (SVID → resource-scoped provider token via OIDC federation/OBO/MCP-OAuth2.1); `identity.*`/`token.*` → CredentialAudit projection ([Plan 14](./14-observability.md)).
2. **Registry (`@hobo/registry`)** — ingest/verify provider Capability Manifest, index capabilities/auth/cost; capability search API + plugin records (provenance, conformance report).
3. **`.allow()` → scope wiring** — connect `.allow()` ([Plan 21](./21-resources-catalog.md)) to least-privilege IAM + wasm links + brokered token scope (one declaration, three effects); policy gates for high-risk actions ([Plan 12](./12-security-multitenancy.md)).
4. **Durable agents (`@hobo/runtime` `agent()`)** — model/instructions/tools, tools execute as steps, runs event-sourced + replayable; inject `ctx.identity` + `ctx.token(...)` + guardrails (`spendCapUsd`).
5. **MCP control surface (`@hobo/mcp`)** — tools (`list/get_bindle`, `plan`, `deploy`/`promote`/`rollback`/`destroy`, `inspect_run`/`tail_logs`, `search_registry`, `request_token`, `get_drift`/`heal`); MCP auth via SVID; publish `llms.txt`/`docs.json`.
- **Acceptance gate:** an agent deploys a bindle via MCP using only brokered short-lived tokens (no static secrets), `token.*` events exist + run replayable; a high-risk action blocks on a policy gate until approved; Registry serves capabilities from an ingested Manifest, `request_token` returns a scope bounded by `.allow()`.
- **Key risk/hook:** Capability Manifest as an open spec (MCP-auth/OAuth-OBO/SPIFFE/AIP); delegation chains (agent→sub-agent); policy language for guardrails/ABAC (typed TS vs Rego/CEL).

### Stage 4 — Multi-provider + wiring depth
Realizes [Plan 3](./03-providers-iac.md), [Plan 13](./13-networking-connectivity.md), [Plan 22](./22-wiring-manifest.md), [Plan 2](./02-sdk-api.md). **Objective:** prove the agnostic thesis — the same bindle deploys to multiple clouds via mapping rules, with cross-provider connectivity + typed provider-specific optimization, no app edits. **Depends on:** stage 2 (benefits from stage 3 for cross-cloud identity/links). Resource Definitions shine here (per-`envType`/`class` definitions, [Plan 25](./25-resource-definitions-matching.md)/[Plan 26](./26-environments-deltas.md)); add echo/container/custom-webhook Drivers + Packs + Relay + GitOps publisher ([Plan 27](./27-drivers-packs-profiles.md)/[Plan 28](./28-relay-gitops-pipelines.md)); deepen the contract plane (observed/promoted contracts, version-skew `can-deploy`, [Plan 29](./29-contracts-compatibility.md)) + capability contracts + region/data-classification obligations ([Plan 30](./30-policy-plane.md)/[Plan 12](./12-security-multitenancy.md)).
1. **Additional CloudProviders (AWS, Azure)** — capability ports for the full catalog on AWS + Azure; equivalence classes per port; per-provider Capability Manifest + typed `.with(...)` builders.
2. **Mapping rules & resolution** — the three mapping styles in `hobo.config.ts` (whole-app/per-tier/per-binding, [Plan 2](./02-sdk-api.md)); Planner resolution order + `prefer`/`require` negotiation (rationale on `deployment.Planned`); `.with(...)` inert for non-resolved providers.
3. **Cross-provider networking ([Plan 13](./13-networking-connectivity.md))** — service identity via SVIDs; links resolve across providers; connectivity tiers (native private → interconnect → overlay mesh → public + mTLS); annotate `bind` edges with tier + estimated egress.
4. **Wiring/manifest parity ([Plan 22](./22-wiring-manifest.md))** — Aspire-style reference/config injection for the container/wasm-host fallback; uniform `AddContainer`-style config applied to components + containers.
- **Acceptance gate:** `multi-cloud-shop` deploys the same bindle to two providers via mapping rules; cross-cloud services connect over mTLS keyed by SVIDs; a `require`d-but-unoffered capability → `deployment.PlanRejected` with a precise reason; switching a resource's provider touches only `hobo.config.ts`.
- **Key risk/hook:** overlay-mesh tech (WireGuard vs eBPF/Cilium vs Tailscale-style); Planner objective when multiple providers satisfy (cost vs latency vs stay-on-one-cloud, [Plan 16](./16-cost-finops.md)); Crossplane coexistence.

### Stage 5 — Forge
Realizes [Plan 6](./06-ai-native-agent-auth.md), [Plan 23](./23-stubbable-ai-implementations.md), [Plan 9](./09-verification-open-questions.md). **Objective:** break the human bottleneck on breadth — AI generates providers (new backends) + implementations (components behind WIT ports), certified by conformance + trace replay, promoted through gates. **Depends on:** stage 3 (identity/registry/sandbox) + stage 4 (reference adapters). The promotion gate is explicit — conformance(contract) + eval thresholds + policy ([Plan 23](./23-stubbable-ai-implementations.md)/[Plan 29](./29-contracts-compatibility.md)/[Plan 30](./30-policy-plane.md)) with champion/challenger + shadow traffic; Forge can also generate Resource Definitions/Packs ([Plan 25](./25-resource-definitions-matching.md)/[Plan 27](./27-drivers-packs-profiles.md)).
1. **Full conformance coverage** — `@hobo/conformance` suites per WIT interface (every capability port, the trust boundary, [Plan 9](./09-verification-open-questions.md)); coverage report; gate publishing on per-interface pass.
2. **Forge: provider generation** — ingest backend docs/OpenAPI/Terraform-provider/Capability-Manifest → candidate `@hobo/provider-x`; sandbox (Firecracker + wasm sandbox, no egress) → run conformance; on pass sign+publish to the Registry with provenance + report (`forge.PluginCertified`), on fail feed errors back ([Plan 6](./06-ai-native-agent-auth.md)).
3. **Stubs & implementation generation** — stub system (any WIT port backed by a recording/typed stub, [Plan 23](./23-stubbable-ai-implementations.md)); Forge generates stub→full implementation from WIT + conformance + recorded traces, validated sandboxed + replay-as-tests.
4. **Auto-evolve & gated live-fix** — policy engine classifies low-risk(auto) vs high-risk(human-approval hook) ([Plan 12](./12-security-multitenancy.md)); auto-evolve on new traces/SLO/cost; live-fix via the gated canary/rollback saga ([Plan 5](./05-reliability-ha.md)), failing trace → permanent regression test; record every generation/validation/gate/apply as events ([Plan 11](./11-event-model.md)).
- **Acceptance gate:** `hobo forge <provider-url>` yields a certified provider that passes conformance + appears (signed) in the Registry; a stubbed port gets an AI-generated implementation that passes conformance + reproduces recorded traces, promoted through a gate; a simulated SLO regression triggers a gated live-fix that auto-rolls-back on failure + keeps the failing trace as a test.
- **Key risk/hook:** "low-risk auto" threshold ([Plan 5](./05-reliability-ha.md)/[Plan 12](./12-security-multitenancy.md)); Forge model/eval design + human-certification threshold for high-trust ports; plugin signing/provenance (SLSA) + supply-chain trust ([Plan 12](./12-security-multitenancy.md)).

### Stage 6 — HA, FinOps, UX & governance planes

1. **Reliability & HA ([Plan 5](./05-reliability-ha.md))** — actor leases + fencing tokens + placement/failover; control-plane HA (quorum event-store replication, leader election); provider resilience (circuit breakers, retry budgets, bulkheads); drift loop (resync + `heal`/`propose`/`ignore`).
