# Plan 9 — Verification, testing & open questions

> Part of the [HoBo Design Plan Suite](./README.md). How we prove each plan works when implemented, and the cross-cutting questions still open.

> **v3 (Humanitec):** add **Driver** conformance suites ([Plan 27](./27-drivers-packs-profiles.md)) and a **matching test** (given context + a set of Resource Definitions, assert the expected one wins and a `match.Decided` event records the score, [Plan 25](./25-resource-definitions-matching.md)) and a **Delta→Set** test (a delta applied yields the expected immutable Set, [Plan 26](./26-environments-deltas.md)). The matching test also asserts **determinism** (same inputs → same winner on replay), the **stable tiebreak + `PlanWarning`** on a true tie, and a **`require`-miss → `deployment.PlanRejected`** ([ADR-0033](./adr/ADR-0033-deterministic-matching-and-planner-selection.md)).

> **v4 (gates):** **conformance** here is the *provider* contract (does an impl satisfy a port); the *consumer-driven* compatibility check (`can-deploy`, [Plan 29](./29-contracts-compatibility.md)) is distinct — add a **compatibility test** (producer/consumer version skew → `compat.GateFailed`), a **policy-decision test** ([Plan 30](./30-policy-plane.md): assert effect + obligations for a given request), and an **eval-gate test** ([Plan 23](./23-stubbable-ai-implementations.md)). `hobo verify` composes all of these.

> **v2 update.** Conformance is now **per WIT world** ([Plan 20](./20-wasm-wasi-runtime.md)) and is the gate for both human- and Forge-generated **providers and implementations** ([Plan 23](./23-stubbable-ai-implementations.md)). Add: a **stub/replay test** (run with stubs, then assert an AI-generated impl reproduces recorded traces + passes conformance) and an **IfC-collection test** (collected manifest matches a fixture). New open questions: wasm host of record, `hobo:*` WIT versioning, IfC fidelity for non-TS languages, and the "low-risk auto live-fix" threshold.

## Testing strategy (the pyramid)
1. **Unit** — pure functions (the Planner, upcasters, capability negotiation) tested in isolation. The Planner being pure ([Plan 3](./03-providers-iac.md)) makes provider-resolution fully unit-testable without a cloud.
2. **Conformance (contract) tests** — `@hobo/conformance` is the centerpiece (below).
3. **Integration** — SDK + built-in runtime + a real-but-local provider (containers) exercise deploy→run→inspect.
4. **E2E** — full Yard + one real cloud provider, gated and periodic (cost-aware).
5. **Determinism/replay** — every durable run asserts `replay == live state`.

## `@hobo/conformance` — the trust boundary
A shared, executable contract test suite per **port** (runtime ports and Provider capability ports). It is what lets human- *and* Forge-generated adapters be trusted ([Plan 6](./06-ai-native-agent-auth.md)).
- **Per runtime port:** EventStore (append/read/optimistic-concurrency/idempotent-dedup), Queue (at-least-once + dedup), Streamer, ActorHost (lease + fencing under contention), Clock (durable timers, deterministic replay).
- **Per Provider capability:** e.g. `database` must provision, accept connections via the agnostic client, honor `require`/`prefer`, `refresh()` report drift, and `destroy()` cleanly — same assertions whether AWS, Azure, or a Forge-generated provider.
- **Gate:** an adapter may only claim a port/capability it passes; CI blocks publishing otherwise; the Forge runs this suite sandboxed before certifying.
- **`local` vs `camp` tag (local-dev fidelity, [ADR-0042](./adr/ADR-0042-local-dev-fidelity.md)):** every conformance check is tagged `local` (passes offline on `runtime-local` — simulate/real behaviors) or `camp` (passes only against a real provider — IAM/mTLS/quotas/drift). `hobo dev` runs `local`; a Camp run runs `camp`; **`hobo verify` reports coverage = `local ∪ camp` and refuses a prod-ready claim while `camp` checks are unrun** — so a green local run is honest about what it didn't test.

## Per-plan verification
- **SDK ([2](./02-sdk-api.md))** — `examples/hello-bindle` runs on `runtime-local`: a workflow + actor + saga execute; killing/restarting resumes; **replay reproduces identical state** (determinism test); types compile with provider options. **Codegen test** ([ADR-0037](./adr/ADR-0037-sdk-codegen-surface.md)): from a fixture bindle, the generated `_generated/` types compile, `ctx.bindings.db` is typed to the resolved client, a typed `useQuery` reflects the query shape, and **`hobo codegen --check` fails on a hand-edited drift**.
- **Providers/IaC ([3](./03-providers-iac.md))** — `examples/multi-cloud-shop` deploys the *same* Bindle to two providers via mapping rules; assert provider-specific `.with(...)` options only affect the resolved provider; Planner rejects an unsatisfiable `require` with a precise reason.
- **Control plane/HA ([4](./04-control-plane.md),[5](./05-reliability-ha.md))** — kill the Yard mid-deploy → resumes from the log; inject a provisioning failure past the no-go threshold → saga compensation rolls back in reverse-dependency order; partition an actor owner → fencing rejects its stale writes; canary regression → auto-rollback.
- **Event model ([11](./11-event-model.md))** — rebuild every projection from zero == live projection (proves the log is authoritative); old events replay through upcasters.
- **Agent auth ([6](./06-ai-native-agent-auth.md))** — an agent obtains a short-lived provider token via OIDC federation (no static secrets), provisions a resource, and the `token.*` events exist + the run is replayable; a high-risk action blocks on a policy gate.
- **End-user auth ([36](./36-end-user-auth.md))** — a JWT from a fixture IdP is verified via JWKS → `ctx.user` carries the claims; an **expired/wrong-issuer/tampered** token is rejected; a **policy/`.allow()` rule keyed on user claims** gates a query/mutation (allow + deny); **revocation** (`session.Revoked`) blocks subsequent requests **and re-pushes affected reactive queries** ([32](./32-reactive-live-queries.md)); the **thin built-in dev provider works offline** ([ADR-0036](./adr/ADR-0036-air-gapped-sovereign-mode.md)).
- **Security ([12](./12-security-multitenancy.md))** — cross-tenant read attempts fail at the Gateway and the store; an Executor has no egress beyond its scoped target; an unsigned plugin is refused by the Registry.
- **Networking ([13](./13-networking-connectivity.md))** — cross-provider services connect over mTLS keyed by SVIDs; the topology graph reports the correct connectivity tier + egress.
- **Cost ([16](./16-cost-finops.md))** — `hobo plan` estimate is within tolerance of a known fixture; a budget breach blocks or requires approval.
- **MCP/DX ([15](./15-cli-dx.md))** — a real agent drives `plan`→`deploy`→`inspect_run` through `@hobo/mcp`; `hobo dev` runs the agnostic path with zero cloud.
- **WASM/WASI runtime ([20](./20-wasm-wasi-runtime.md),[24](./24-wit-worlds-reference.md))** — a TS service builds to a component via jco; conformance runs **per WIT world**; swapping a provider behind a port is a link change (no recompile); deny-by-default holds (an un-linked capability call fails).
- **Resources/IfC ([21](./21-resources-catalog.md),[22](./22-wiring-manifest.md))** — `hobo collect` emits a **manifest** matching a fixture; `.allow()` produces exactly the expected IAM + link + token-scope triple; a missing verb is denied on all three.
- **Stubbable/AI ([23](./23-stubbable-ai-implementations.md))** — run with a `stub()` behind a port, record traces, then assert a Forge-generated implementation **passes conformance and reproduces the recorded traces**; a simulated SLO regression drives a **gated** live-fix that auto-rolls-back on failure.

### Surfaced by the ecosystem review ([`../../technologies/`](../../technologies/README.md) · [`../../standards/`](../../standards/README.md) · [`../../patterns/`](../../patterns/README.md))
> Mapping the documented ecosystem against HoBo's design surfaced six items. Two are **new capabilities** with no current owner (#24 feature flags, #26 alerting depth), three are **standards-alignment / refinements** of existing planes (#25 SLO-as-code, #27 boundary standards, #29 code-mutation persistence), and one is a **new verification tier** (#28 chaos). None contradict the design; each is additive. Prioritized for the remediation loop.
24. **Feature flags / progressive delivery** — HoBo has deploy-time gates + canary/progressive rollout ([Plan 5](./05-reliability-ha.md)/[Plan 26](./26-environments-deltas.md)) and policy obligations ([Plan 30](./30-policy-plane.md)), but **no runtime feature-flag capability** (decouple *release* from *deploy*: targeting, gradual %, kill-switch, experiments). No Plan owns it. Candidate: an **OpenFeature-compatible `feature-flag` port** ([`../../standards/openfeature.md`](../../standards/openfeature.md)/[`../../patterns/feature-flags.md`](../../patterns/feature-flags.md)), flags optionally policy-gated + event-sourced. **NEW capability.**
25. **SLO-as-code + error-budget gating** — HoBo ships built-in SLOs + burn-rate alerts ([Plan 14](./14-observability.md) §SLOs) + NFR baselines ([ADR-0021](./adr/ADR-0021-nfr-baselines-slos.md)), but SLOs aren't **declared as code** and **error budgets don't drive gates**. Candidate: an **[OpenSLO](../../standards/openslo.md)-aligned** SLO/SLI/error-budget declaration whose burn-rate feeds `can-deploy`/policy ([Plan 29](./29-contracts-compatibility.md)/[Plan 30](./30-policy-plane.md): "freeze deploys when the budget is exhausted"). **Refinement.**
26. **Alerting model depth** — alert *routing* exists as a provider capability ([Plan 14](./14-observability.md) §35) but not a full **[AlertManager](../../technologies/prometheus-alertmanager.md)-style** model (grouping, dedup, **silencing**, **inhibition**, routing tree, notification receivers). Candidate: an alerting/notification sub-model over HoBo events, event-sourced (`alert.*`). **NEW capability (refines Plan 14).**
27. **Boundary standards alignment** — HoBo is OTel/OpenInference-native ([Plan 14](./14-observability.md)) but its **`EventEnvelope`** ([Plan 11](./11-event-model.md)) isn't **[CloudEvents](../../standards/cloudevents.md)**-compatible at the boundary, and the audit log isn't normalized to **[OCSF](../../standards/ocsf.md)** for SIEM. Candidate: CloudEvents-compatible envelope export + an OCSF audit-export mapping ([Plan 12](./12-security-multitenancy.md)) + confirm OTLP-native export. **Alignment.**
28. **Chaos / continuous-resilience tier** — HoBo has fault-injection *tests* ([Plan 9](./09-verification-open-questions.md) per-plan) + a failure taxonomy ([Plan 5](./05-reliability-ha.md)), but no first-class **[chaos-engineering](../../patterns/chaos-engineering.md)** tier (steady-state hypothesis, blast-radius control, game days, continuous/automated injection). Candidate: a `chaos` verification tier + capability; determinism/replay makes failure reproduction cheap. **NEW verification tier.**
29. **Persisted code-mutation mechanism** — Plan 23's training loop *promotes* AI-rewritten implementations (`impl.Promoted`/`training.Promoted`) but the **mechanism to persist runtime/AI-generated code mutations back to source** is thin ([`../../patterns/runtime-code-mutation-persistence.md`](../../patterns/runtime-code-mutation-persistence.md)): AST-aware edits, generated-vs-hand-written regions, signed provenance, gated PR. Candidate: specify it as the bridge between `"use training"` promotion ([Plan 23](./23-stubbable-ai-implementations.md)/[ADR-0025](./adr/ADR-0025-use-training-directive-and-training-engine.md)) and the `_generated/` codegen surface ([ADR-0037](./adr/ADR-0037-sdk-codegen-surface.md)). **Refinement.**
