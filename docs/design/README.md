## Context

**Problem.** Shipping software still forces application developers to become part-time platform engineers: picking clouds, wiring IaC, designing for HA, and operating infra. Tools today force a bad trade — either an opinionated closed PaaS (simple but locked-in, e.g. **Lakebed**) or raw multi-cloud IaC (powerful but heavy). Neither is built for the world that's coming, where **AI agents are the primary builders and deployers**.

**What HoBo is.** An *intermediary cloud control plane* with a developer-centric, cloud-agnostic programmable surface that is **WIT/WASM** (the Component Model / wasmCloud) — **TypeScript is the first reference implementation, not a requirement**; any Component-Model language authors against the same WIT worlds ([ADR-0069](./adr/01-architecture-core.md#adr-0069)). Developers describe their app once through **PaaS / SaaS / CaaS / IaaS abstractions**; a **provider pattern** (ports & adapters) maps those abstractions onto real providers. You can map the whole app to a single provider ("just host this on Azure, figure it out"), split tiers across providers, or pin specific boundaries to specific providers — and drop to typed **provider-specific options** when you want to optimize. IaC tools (Pulumi, Crossplane, Terraform/OpenTofu) and image/VM tools (Dagger, Packer, Vagrant, Firecracker) are themselves pluggable via the same ports/adapters pattern.

**Why it wins.** Write cloud-agnostic code that ships anywhere; reach for provider-native power only when you want to. The API *feels like* [Vercel Workflows](https://workflow-sdk.dev/) for its durable `workflow`/`step` ergonomics, but the durable runtime is **HoBo-native and provided per [Camp](#glossary--naming-thematic-all-tunable)** (no dependency on any single vendor's runtime). The whole system is **AI-native**: actor-model + choreography sagas over a replayable event store, agents as first-class authenticated users, a machine-readable **auth/capability standard** so agents self-provision credentials with zero developer effort, and AI-generated provider plugins instead of relying on a community to write them.

**Intended outcome.** A self-hostable (or hosted) **hobo-cloud** orchestrator + an SDK such that a developer (or an agent) can `hobo deploy` an app and have it land on real infrastructure — agnostic by default, optimizable on demand.

### Decisions locked (from clarifying Q&A)
1. **Substrate:** TS-native control-plane core (actor runtime + Pulumi Automation API to drive IaC); Kubernetes/Crossplane is *one optional* execution adapter, not the foundation.
2. **Durable core:** HoBo defines its own **runtime ports** (EventStore + Queue + Streamer + ActorHost + Clock) — the durable runtime a **Camp** provides — and ships a **built-in lightweight engine** (`runtime-local`), plus backends for Temporal / Restate / DBOS / Cloudflare DO.
3. **SDK feel:** **Layered blend** — topology/resource layer + provider mapping + actor runtime + Vercel-style `workflow`/`step`/`agent` primitives + provider-specific options escape hatch.
4. **Deepest in this round:** **SDK/API design** and **AI-native + agent auth**. Architecture overview and a UI sketch are included; control-plane internals and providers are at solid (not maximal) depth and flagged for later iteration.

### Competitive frame vs Lakebed (what we deliberately do differently)
| Dimension | Lakebed | HoBo |
|---|---|---|
| Unit of deploy | "Capsule" (one full-stack TS app on their runtime) | **Bindle** (app topology mapped to *any* provider mix) |
| Cloud model | Single closed hosted runtime | **Cloud-agnostic** ports/adapters, multi-provider, self-hostable |
| IaC | Hidden, none exposed | Pluggable **IaC providers** (Pulumi/Crossplane/Terraform/OpenTofu) |
| Runtime model | Synchronous RPC (queries/mutations) | **Actors + durable workflows + choreography sagas** over a replayable event store |
| Agents | Agent-readable contracts; basic guest/Google auth | **Agents as first-class authenticated principals**; auto-token issuance via a capability standard; durable AI agents; MCP control surface |
| Extensibility | Community / first-party | **AI-generated provider plugins** gated by conformance tests |

> Lakebed's strengths we should match: ruthless simplicity, machine-readable contracts (`llms.txt`/`llms-full.txt`, `docs.json`), instant `npx` onboarding, server-authority. HoBo must not become "powerful but unusable."

## Glossary & naming (thematic, all tunable)

HoBo's metaphor is the itinerant worker who travels light and shares a standardized sign language. Names below are proposals; technical meaning is what matters.

- **Layered scopes** — HoBo config nests: **`Junction` ⊃ `Yard` ⊃ `Camp` ⊃ `Bindle`** — *connected-across-clouds* (cross-cloud / hybrid; connects Yards) ⊃ *governed-per-provider* (one provider's cross-Camp policy + that provider's control plane) ⊃ *where-on-which-provider* (a provider-specific target + its runtime) ⊃ *what-the-app-is* (app config).
- **Bindle** — **app-level config**: an app's declared topology + bindings, provider-agnostic. (Lakebed "capsule" analog.) Deployed *into* Camps.
- **Camp** — a **provider-specific deployment target**; canonical id `<env>-<provider>` (e.g. `prod-aws`). A Camp **independently selects** a **runtime backend** (the runtime ports below) **and** an infra **Provider** — they can be different vendors (e.g. `provider-aws` + a Temporal runtime). A **Bindle deploys to one *or more* Camps**; a multi-cloud `production` is Camps in several Yards (one Yard per provider), connected by a **Junction** ([ADR-0028](./adr/05-config-matching-environments.md#adr-0028)). The local dev Camp ships a built-in runtime (`runtime-local`). Belongs to a Yard.
- **Environment group** — the member Camps of one logical environment (e.g. `production` = {`prod-aws`,`prod-azure`}); `hobo … --env production` promotes/rolls-back across them as a **saga** (`env.*` events) over the per-Camp Sets — a **Yard saga** within one provider, a **Junction saga** when the group spans providers. An orchestration grouping, **not** a config layer ([ADR-0028](./adr/05-config-matching-environments.md#adr-0028)).
- **Runtime ports** — the durable-runtime capability ports a **Camp** provides: EventStore + Queue + Streamer + ActorHost + Clock. Backends are pluggable (`runtime-local` built-in; `runtime-postgres` / `-temporal` / `-restate` / `-cloudflare`). The substrate is a property of a Camp. **Disambiguation — three senses of "runtime":** `@hobo/runtime` = the SDK **primitives** package (`workflow`/`step`/`actor`/…); the **`Runtime` interface** (`@hobo/core`) = the five ports a backend implements; **`runtime-*`** = the **backends** that implement them.
- **Provider** — an adapter that implements infra **ports** (cloud / IaC / build/VM) for a specific backend.
- **Port** — a capability interface (e.g. `Database`, `Compute`, `ObjectStore`, `Vm`) that providers implement.
- **Capability Manifest / Signs** — the machine-readable **auth + capability standard** (the `auth.md` analog). Providers publish "signs" describing what they offer and how an agent obtains a token. The thematic anchor: hobo signs were a real standardized symbol language for finding resources & safe routes — exactly what agents need.
- **Hobo Code** *(future, [Plan 21](./authoring-resources-wiring.md#plan-21))* — the planned HoBo **configuration + code DSL**: one human-readable surface to declare **Yards, Camps, Bindles** and their resources/wiring *and* the workflow/step/agent code, deliberately designed to be **optimal for AI generation, training & optimization** (small, regular, low-ambiguity grammar with a stable AST). It compiles to the same **Manifest IR** + SDK constructs the TypeScript surface produces — a sibling authoring front-end, not a replacement. Status: reserved/forward-looking; design TBD.
- **The Yard** — hobo-cloud: the control plane / orchestrator **and the provider-specific cross-Camp scope** — **one Yard groups the Camps under ONE provider** and holds that provider's cross-Camp policy, provider-global networking/vWAN, global gateways (e.g. Azure Front Door), and runs that provider's control plane (`Camp ⊂ Yard`). A rail-yard where bindles are routed to real hosting on that provider. **Multi-region within one provider** is several Camps under *one* Yard (no second Yard); **multi-cloud / hybrid** is several **Yards** (one per provider) connected by a **Junction**.
- **Junction** — the **cross-cloud / hybrid scope**: it connects provider-specific **Yards** so a single estate spans multiple clouds ([ADR-0043](./adr/07-portability-extensibility.md#adr-0043)). It federates **identity trust + signed policy packs + signed registry bundles** across autonomous Yards — **not** a controller and **not** shared state (each Yard keeps its own log/control-plane/data; residency preserved). Like a rail junction where independent lines meet, it's where otherwise-separate yards interconnect as peers. The broadest scope (`Yard ⊂ Junction`); a single-cloud estate needs no Junction.
- **Config & secrets (secretless-first)** — apps read config/secrets via `ctx.config`; values resolve to **references per Camp**, never literals in the Bindle / Camp config / event log. Resolution prefers workload identity (SVID) → brokered short-lived tokens / OIDC federation ([Plan 6](./ai-native-agent-auth.md#plan-06)/[Plan 12](./security-networking.md#plan-12)/[Plan 21](./authoring-resources-wiring.md#plan-21)); static secrets are a bounded, audited, opt-in fallback ([ADR-0023](./adr/02-identity-security.md#adr-0023)).
- **Forge** — the AI pipeline that generates & certifies new Provider plugins.
- **Grain** — a virtual actor (Orleans term, kept for familiarity); the default concurrency primitive.
- **Planner** — the pure function that turns a Bindle + mapping into a `DeploymentPlan` DAG.
- **ResourceActor** — a controller-style grain that reconciles one resource's desired↔actual state.
- **Executor** — a Firecracker-sandboxed runner that applies IaC / builds images with short-lived scoped creds.
- **Run** — one durable execution of a workflow/agent (a `run.*` event stream).
- **Identity / SVID** — a workload identity (SPIFFE-style) issued by the Yard to agents/services for keyless auth.
- **Component** — a WASM/WASI component; the default unit a HoBo service compiles to (OCI-container fallback otherwise).
- **WIT interface** — the canonical form of a HoBo **port**: a WebAssembly Interface Types contract a component imports/exports.
- **Capability provider** — a Provider as a wasm capability adapter implementing a WIT interface's exports for a backend.
- **`component-host`** — the **port that executes components** (WASI interface impls + link table + lifecycle); **a property of a Camp** ([ADR-0031](./adr/01-architecture-core.md#adr-0031)). Host of record: **Wasmtime** locally/`runtime-local`; **v1 prod default = wasm-in-container** (reuses the OCI pipeline → zero new infra); **SpinKube / wasmCloud-lattice / provider-native** are opt-in per-Camp adapters certified by the host conformance suite.
- **Link** — the late-bound binding from a component's imported interface to a provider's export (the `bind`/escape-hatch made concrete).
- **`.allow(...)`** — inline capability-permission on a resource; drives least-privilege IAM **+** wasm capability links **+** agent token scope.
- **IfC** — Infrastructure-from-Code: the default authoring mode where resources are declared inline and collected by running the component.
- **Manifest (IR)** — the deployment intermediate representation emitted by resource-collection and consumed by the Planner.
- **Stub** — a typed, recording placeholder behind a WIT port so an app runs before implementations exist (basis for AI implement/evolve).
- **Resource Definition** — a platform-engineer rule for *how* a port is realized in a context (provider + driver + options), selected by Matching. Mapping is sugar over default definitions.
- **Matching Criteria** — the selector that picks one Resource Definition for a deploy context (env-type/app/env/class/id). Selection is a **deterministic, replayable** pure function: filter on hard `require` capability, then **rank lexicographically** — specificity → explicit `priority` → **objective** → stable tiebreak — recorded in `match.Decided` ([ADR-0033](./adr/05-config-matching-environments.md#adr-0033)). **Planner objective** — the soft ranking tiebreak (`cost`|`latency`|`single-provider`|`carbon`|`maximize-credits`, **default min-cost within constraints**, configurable per Yard/Camp); AI/solvers are advisory off-path. The **Dispatcher** ([ADR-0071](./adr/05-config-matching-environments.md#adr-0071), below) is this selector applied credit-aware at placement/dispatch/traffic.
- **Driver** — the execution mechanism a definition uses to realize a resource: `terraform`/`template`/`echo`/`container`/`custom-webhook`.
- **Deployment Set** — the immutable resolved config of a Camp at a point in time (the manifest IR). **Delta** — a mutable diff applied to a Set (draft→promote).
- **Environment Type** — an environment classification (`production`/`ephemeral`/…) a Camp carries; the primary matching dimension. *Not a separate layer:* a multi-cloud `production` spans Camps across several Yards, connected by a Junction.
- **Workload Profile** — how a service is realized (wasm-component/container/serverless/VM). **Resource Pack** — a shareable bundle of Resource Definitions.
- **Relay** — an outbound-only proxy inside a private network so a hosted Yard deploys there with no inbound ([Plan 25](./platform-engineering.md#plan-25)). Distinct from **Operator Agents** (the Crew, [Plan 40](./operators-sre.md#plan-40)) and from agents-as-principals ([Plan 6](./ai-native-agent-auth.md#plan-06)) — "Agent" is reserved for autonomous principals; the proxy is the Relay.
- **Four-lens taxonomy** — **Contract** = must never break · **Eval** = should improve · **Policy** = may/may not be allowed · **Trace** = what actually happened.
- **Contract** — a typed expectation on a graph edge (HTTP/event/binding/`.allow()` scope/SLO/semantic/agent-tool), in mode *declared/inferred/observed/promoted*. **`can-deploy`** — the compatibility-matrix gate checking a change against versions already running per environment.
- **Policy decision** — `{ effect: allow/deny/warn/mutate/require-approval, obligations, evidence }`; an **Obligation** = "allow but require X" realized as a durable HoBo effect/saga.
- **Eval / rubric** — scored quality thresholds (with champion/challenger + shadow traffic) gating an AI-impl promotion. **Gatekeeper** — the composite gate (contracts + policy + evals + conformance + cost) behind `hobo verify`.
- **`"use training"`** — SDK directive (peer to `"use workflow"`/`"use step"`) marking a method an **AI-rewritable semantic function**; HoBo continuously optimizes its prompt/code against a rubric ([Plan 23](./forge-generated-stack.md#plan-23)/[Plan 2](./sdk-api.md#plan-02)). **Training-engine** — the WIT port the optimizer sits behind (built-in default; Microsoft Agent Lightning / Trace as optional *internal* providers, never on the SDK surface).
- **Trajectory** — one trainable-method invocation captured as an **OpenInference** (OTel-native AI-span convention) span tree + I/O + the **reward** from live-evals; the unit the training-engine learns from. **Live-eval** — a rubric scored continuously on live/shadow traffic, supplying both the training reward signal and performance telemetry.
- **Forge generation** — the Forge's candidate-synthesis loop ([Plan 23](./forge-generated-stack.md#plan-23)): **scaffold → LLM-fill → validate(sandboxed, no-egress) → repair(via the `training-engine`, bounded budget) → certify(sign + pinned provenance)**, gated by `@hobo/conformance`. **Contract-first inputs** — the WIT port + conformance suite + Capability Manifest are *authoritative*; OpenAPI/Terraform/docs + traces are sanitized *material*. One loop generates **providers, implementations, and Resource Definitions/Packs**; cold-start counterpart to live `"use training"` ([Plan 23](./forge-generated-stack.md#plan-23)).
- **Feature flag (`feature-flag` port / `useFlag()`)** — runtime flags that decouple *release* from *deploy* ([Plan 29](./contracts-policy-flags.md#plan-29)/[ADR-0044](./adr/04-governance-verification.md#adr-0044)): an **OpenFeature-compatible** port (built-in store default; OpenFeature providers as adapters), flags declared in the Bindle (IfC), **in-process deterministic** evaluation with targeting from `ctx.user`/`ctx.identity`, changes **event-sourced** (`flag.*`) + **optionally policy-gated** + **reactive** (`useFlag`/`useQuery` re-eval). Composes with canary (deploy dial) as the release dial for progressive delivery.
- **SLO-as-code / error-budget gating** — declarative ([OpenSLO](../../standards/openslo.md)-aligned) SLOs/SLIs/error-budgets whose **burn-rate is a policy input** ([ADR-0045](./adr/04-governance-verification.md#adr-0045)): a policy can freeze deploys or auto-revert a rollout/flag when the budget burns. Alerting uses an **AlertManager-style** model (grouping/silencing/inhibition/routing, event-sourced `alert.*`).
- **Chaos tier** — a first-class verification tier ([ADR-0047](./adr/04-governance-verification.md#adr-0047)): hypothesis-driven, blast-radius-bounded, policy-gated fault injection at HoBo's own seams (`chaos.*` events); event-sourcing/replay turns a discovered failure into a regression test.
- **Boundary standards** — HoBo keeps its native `EventEnvelope` internally but **speaks open standards at the boundary** ([ADR-0046](./adr/04-governance-verification.md#adr-0046)): **CloudEvents** export, **OCSF** audit export, **OTLP**-native telemetry.
- **Local-dev fidelity** — the bounded, honest "works locally → works in prod" promise ([ADR-0042](./adr/07-portability-extensibility.md#adr-0042)): each prod behavior is **simulate** (correctness-determining — real locally), **mock** (environmental — honest seam), or **camp-only** (irreducibly-real), keyed on "does a wrong local answer hide a real bug?". Capabilities carry a fidelity label; conformance checks are tagged `local|camp`; **`hobo verify` reports coverage = local ∪ camp** and won't claim prod-readiness for mocked-only behaviors.
- **Migration / `hobo import` (adopt-in-place)** — onboarding an existing estate without a greenfield rewrite ([ADR-0041](./adr/07-portability-extensibility.md#adr-0041)): `hobo import terraform|pulumi|opentofu|lakebed|faas` reads existing IaC state into the graph as **`adopted`** nodes (managed by id/state, no re-provision; reuses CDKTF-import + Pulumi Automation API), an **`external` resource kind** references not-yet-adopted infra so a HoBo-managed resource can `bind` across the boundary (strangler-fig), and importers are **Forge-generatable** (round-trip-conformance-gated). Emits `resource.Adopted`.
- **Cross-Camp state consistency** — when a Bindle spans Camps ([ADR-0028](./adr/05-config-matching-environments.md#adr-0028)), each piece of state declares a **replication topology** ([ADR-0040](./adr/05-config-matching-environments.md#adr-0040)): **single-writer-Camp** (default), **active-active-eventual** (CRDT), or **pinned-single-Camp**. The **event log is the replication backbone** (owner writes → replicated read-stream → bounded-staleness projections; provider-store CDC deferred). Surface: **labeled bounded-staleness reads**, reads-your-writes in the writer Camp, **write-goes-home** for consistency-requiring writes, cross-Camp reactive via the owner/replicated reactor. No silent strong cross-cloud consistency (CAP-honest).
- **Metering / quota / showback (cost attribution)** — FinOps over the existing log ([Plan 5](./reliability-observability-cost.md#plan-05)/[ADR-0039](./adr/04-governance-verification.md#adr-0039)): a **`MeteringView`** projection folds usage/cost counters off the existing log (no new instrumentation); **quotas + a runaway-spend circuit-breaker** are policy-plane decisions/obligations ([Plan 29](./contracts-policy-flags.md#plan-29)/[Plan 5](./reliability-observability-cost.md#plan-05)); **showback** (cost by tenant→Camp→Bindle→run/agent) is **cost visibility, not money** — HoBo ships no billing ([ADR-0064](./adr/08-scope-and-requirements.md#adr-0064)).
- **`costAvailabilityProfile` / cost-driven graceful degradation** — availability *through* cost controls ([Plan 5](./reliability-observability-cost.md#plan-05)/[ADR-0039](./adr/04-governance-verification.md#adr-0039)): a profile binds a **budget** to an **`availabilitySlo`** with **ordered degradation tiers** + per-resource `priority`/criticality. As **spend velocity** approaches the cap, the policy plane returns **`allow-degraded`** + an obligation and a durable saga (`spend.Degradation*`) sheds QoS by priority — scale-to-zero non-critical, feature-flag shed, cache-TTL/expensive-query shed, request-priority `503`+`Retry-After`, canary hold — with the runaway-spend breaker as the **last resort** (not a synonym). The Planner objective becomes **min-cost subject to the availability floor** ([ADR-0033](./adr/05-config-matching-environments.md#adr-0033)). Cost-induced degradation is a first-class incident class ([Plan 40](./operators-sre.md#plan-40)); composes with canary/auto-rollback ([Plan 5](./reliability-observability-cost.md#plan-05)) rather than hard-failing.
- **The Dispatcher / credit-aware cost routing** — the credit/budget-aware generalization of the deterministic selector ([ADR-0033](./adr/05-config-matching-environments.md#adr-0033)/[ADR-0071](./adr/05-config-matching-environments.md#adr-0071)): the *same* gather→filter→rank→record pipeline applied at three decision points — **placement** (`match.Decided`), **dispatch** of a job to a **`runner`**/**`build-machine`** (`dispatch.Decided`), and **traffic** (`domain.RoutingChanged`, stateless/replicable only, dwell-timed) — over **only the registered providers**. A **`CreditLedgerView`** projection ([Plan 5](./reliability-observability-cost.md#plan-05)) folds per-provider free-tier allotments/reset windows + promo/committed credits + budget caps + spend-to-date off the log (`credit.Registered`/`Reset`/`Exhausted` + `meter.*`/`spend.*`) into an **effective marginal cost** (`0` while free headroom remains, list price after); the **`maximize-credits`** objective ranks by it, so credit/budget rotation across clouds is **emergent**, not hardcoded. Deterministic + replayable (ledger recorded into the decision; AI advisory off-path); composes with the spend circuit-breaker + `costAvailabilityProfile` ([ADR-0039](./adr/04-governance-verification.md#adr-0039)). Operates per **Yard** (provider-internal) and **Junction** (cross-cloud).
- **`runner` / `build-machine`** — execution-host provider categories ([Plan 4](./control-plane.md#plan-04)/[ADR-0071](./adr/05-config-matching-environments.md#adr-0071)): a **`runner`** (`hobo:runner`) runs CI/action jobs and a **`build-machine`** (`hobo:build-machine`, deepening the [ADR-0005](./adr/01-architecture-core.md#adr-0005) BuildProvider) is the host a build runs on. Adapters: **self-hosted (Executors behind the Relay, default) · GitHub · Blacksmith · Depot**. The Dispatcher cost-routes each job/build across the registered set; pin via `.with(...)` to opt out.
- **PortabilityReport** — a plan-time, event-sourced **portability scorecard** emitted with `deployment.Planned` (`deployment.PortabilityReported`, [Plan 21](./authoring-resources-wiring.md#plan-21)/[ADR-0024](./adr/07-portability-extensibility.md#adr-0024)): portability % (resources with ≥2-cloud equivalence-class capability), **lock-in sources with severity** (`.with()` blocks, raw escape hatches, host-`.with()`, paradigm mismatches), per-resource provider-equivalence-class (+ why others were rejected), and upgrade readiness (host/`wasi:*` versions). Data portability is **paradigm-class-scoped** (a Bindle is portable *within* a projection-sink paradigm class, [ADR-0052](./adr/03-data-plane.md#adr-0052)).
- **Component-host portability** — the `component-host` is a **conformance-gated, version-pinned** portability boundary ([Plan 20](./wasm-runtime-wit.md#plan-20)/[ADR-0031](./adr/01-architecture-core.md#adr-0031)): a `@hobo/conformance/component-host` suite (deterministic-clock replay, `wasi:*` round-trip, link semantics, capability-handle isolation) proves a host equivalent before a Camp may select it; the host kind+version is pinned in the manifest IR; host-`.with()` options are flagged as host lock-in by `hobo doctor`. A component proven on Wasmtime behaves identically on wasm-in-container/SpinKube under trace replay.
- **Derivative upgrade paths** — long-lived derivatives ([Plan 23](./forge-generated-stack.md#plan-23)) get a **versioned, conformance-gated upgrade path** ([ADR-0057](./adr/07-portability-extensibility.md#adr-0057)): independently semver'd seams, a signed **`derivative.json`** (core range + seam impls/versions + pinned upcasters), the **`hobo derivative upgrade`** ceremony (check compat → run upcasters → re-run seam conformance → report; `derivative.Upgrade*` events), and core **breaking-change manifests** with upcaster hints — so a fork stays maintainable across core releases instead of becoming abandon-ware.
- **End-user auth (`auth()` / `ctx.user`)** — authentication for an app's *human* users ([Plan 6](./ai-native-agent-auth.md#plan-06)/[ADR-0038](./adr/02-identity-security.md#adr-0038)), distinct from but **unified with** agent/workload auth ([Plan 6](./ai-native-agent-auth.md#plan-06)): a **federate + verify** port (`hobo:auth`) that validates OIDC/JWT from any IdP via the existing JWKS machinery — **swappable adapters: WorkOS · Auth0 · Supabase Auth · Microsoft Entra ID** (+ Google/GitHub/Clerk/customJwt), only registered ones considered, Forge-extensible ([ADR-0073](./adr/07-portability-extensibility.md#adr-0073)) — plus a thin built-in for dev. An end-user is a **`PrincipalRef`** exposed as `ctx.user`; authorization is the **same policy plane + `.allow()`** keyed on user claims; sessions are stateless-JWKS-verify + event-sourced (`session.*`) for revocation. Client: `useAuth()`/`signIn`/`signOut`.
- **SDK codegen (`_generated/`)** — HoBo's end-to-end types are **generated**, deterministically, from WIT interfaces (jco guest-types) + Zod schemas + `.allow()` + the bindle graph into a **checked-in `.hobo/generated/` (or `src/_generated/`)** directory ([ADR-0037](./adr/05-config-matching-environments.md#adr-0037)/[Plan 2 §Generated code](./sdk-api.md#plan-02)): typed `ctx.bindings`, `useQuery()`/search, workflow/step signatures, `.with()` options, and an `api` function-tree. Runs in `hobo dev` (watch) / `hobo build`; **`hobo codegen --check`** is the CI drift gate (editor types with no build step; offline/air-gap friendly).
- **Swappable integration ports** — the meta-cloud's external touchpoints are uniform swappable ports ([ADR-0073](./adr/07-portability-extensibility.md#adr-0073)): port + default adapter set, **only registered adapters considered** ([ADR-0033](./adr/05-config-matching-environments.md#adr-0033)/[ADR-0071](./adr/05-config-matching-environments.md#adr-0071)), secretless-brokered, policy-gated, conformance-gated + Forge-generatable, **never gating portability** ([ADR-0024](./adr/07-portability-extensibility.md#adr-0024)). **Full ports:** `hobo:auth` (WorkOS/Auth0/Supabase Auth/Entra…, [ADR-0038](./adr/02-identity-security.md#adr-0038)) and **`hobo:artifact-repo`** (npm/NuGet/PyPI/OCI/Maven/cargo — build-input pulls + output publishes with SLSA provenance, air-gap-mirrorable, Dispatcher-routable across mirrors). **Named operator-facing seams** (Forge-generatable, full surface later): `issue-tracker` (JIRA/GitHub Issues/Linear) + `knowledge` (Confluence/Obsidian/Wikis) — the Crew's integration surface, reusing the `notify`/receiver-port pattern; *not* app-business features ([ADR-0064](./adr/08-scope-and-requirements.md#adr-0064)).
- **WIT-first SDK (`hobo:sdk` + idiom layers)** — the SDK is provided *through* WIT ([ADR-0072](./adr/01-architecture-core.md#adr-0072)/[Plan 20](./wasm-runtime-wit.md#plan-20)): a canonical **`hobo:sdk` world** pins the SDK contract — the runtime **primitives** (`workflow`/`step`/`actor`/`saga`/`agent`/`command`/`subscribe`) + capability/data interfaces. Each language SDK is **built against WIT** (`wit-bindgen`/jco → mechanical bindings) **+ a thin idiom layer** adding language-native ergonomics (the fluent/IfC surface, builders, decorators) and **no new semantics** — proven by **`@hobo/conformance/sdk`** (idiom layer lowers to identical WIT calls + manifest IR). Idiom layers are **hand-authored or SWE-operator/Forge-generated** ([Plan 40](./operators-sre.md#plan-40)/[Plan 23](./forge-generated-stack.md#plan-23)), and **reverse compiling** (component → its WIT world) scaffolds a new language's skeleton. `@hobo/sdk` (TS), the other language SDKs, and **Hobo Code** are all front-ends over this one contract; TS is the *first* idiom layer, not the source of truth — sharpens the [ADR-0069](./adr/01-architecture-core.md#adr-0069) thin-SDK rule.
- **Air-gapped / sovereign mode** — a first-class **zero-egress self-hosted Yard profile** ([ADR-0036](./adr/07-portability-extensibility.md#adr-0036)): artifacts via **signed offline bundle import** (verified against the same signature+provenance+conformance trust boundary), **in-boundary trust roots** (Identity/internal-CA/KMS) and **local models** with graceful degradation, no telemetry phone-home, and a **capability-degradation matrix**. The deterministic core (deploy/match/migrate/route) needs no model or network. The HoBo **Agent** covers the *connected-private* case; this covers the *disconnected* case. Single in-boundary Yard (federation deferred, [Q20](./verification.md#plan-09)).
- **`domain` / custom domains** — a first-class resource fronting an environment group's member Camps ([Plan 12](./security-networking.md#plan-12)/[ADR-0035](./adr/07-portability-extensibility.md#adr-0035)): **Yard-level** within one provider (provider-global gateway), **Junction-level** when the group spans providers. **Policy-driven DNS routing** (failover/weighted/latency via a provider-agnostic **`dns` capability**, reusing the gateway flip + health), **ACME DNS-01 certs** issued/rotated secretlessly (provider-managed certs as an adapter). One domain, N clouds; routing decisions are event-sourced (`domain.*`).
- **`search` port** — a first-class retrieval resource unifying **full-text + vector + hybrid (RRF)** ([Plan 32](./data-plane.md#plan-32)/[ADR-0034](./adr/03-data-plane.md#adr-0034)), realized by an equivalence class (pgvector+PG-FTS ↔ OpenSearch/Azure AI Search/Pinecone, Matching-selected). Indexes are **declarative** (migration-gated, [Plan 32](./data-plane.md#plan-32)); full-text/filtered search is a **reactive materialization** citizen (re-push on `data.Changed`), vector search is a **step** (the query escape hatch). **`embed` capability** — secretless embedding behind `search`, realized per Camp (local/in-boundary model for dev/air-gap; hosted API for prod), BYO vectors as the escape hatch.
- **App-data migration** — schema evolution + cross-cloud data move for the developer's `sql` resource ([Plan 32](./data-plane.md#plan-32)): **declarative desired-schema + auto-diff** authoring (raw SQL escape hatch), an **expand → backfill → contract** apply model gated by `can-deploy`/`compat.Gate*`, **pre-contract snapshot + restore** rollback (no `.down`), and **export→import within a provider equivalence class** for cross-cloud moves. *Distinct from* HoBo's own control-plane **event-log upcasters** ([Plan 11](./event-model.md#plan-11), forward-only, never rewrite history). Events `migration.*` ([ADR-0032](./adr/03-data-plane.md#adr-0032)).
- **`subscribe` / materializations (RX, default) · `query()`/`"use query"` (snapshot escape hatch)** — the **default read surface is a subscription** to a **materialization**: an observable folded from subscribed event types that replays to the current `seq` then pushes live ([Plan 32](./data-plane.md#plan-32)/[ADR-0050](./adr/03-data-plane.md#adr-0050)). Client: `useSubscription()`. `query()`/`"use query"`/`useQuery()` are retained **sugar/snapshots** for one-shot or latest-value reads. **Reactor** — the data-plane grain that advances a subscription at a new monotonic `seq` and pushes the result/delta over the `Streamer` + gateway. **Read-set** — the event types/streams/change-feed topics a materialization touched, re-tracked each recompute. **Change-feed capability** — an opt-in sink capability ([Plan 21](./authoring-resources-wiring.md#plan-21)/[Plan 20](./wasm-runtime-wit.md#plan-20)) that normalizes a *cache's* change stream into `data.Changed` so a cached materialization stays reactive (the native log-backed one always is). Consistency: **per-subscription consistent snapshot @ `seq`** + reads-your-writes ([ADR-0050](./adr/03-data-plane.md#adr-0050)).
- **Projection / Projection Sink** — the persistence-agnostic data plane ([Plan 32](./data-plane.md#plan-32)/[ADR-0050](./adr/03-data-plane.md#adr-0050)): app **domain data is event-sourced by default** ([Plan 11](./event-model.md#plan-11)) and a **projection is a subscribable materialization** (subscribe event streams → deterministic fold → a **WIT-record** read model, observed live — [Plan 32](./data-plane.md#plan-32)/[ADR-0050](./adr/03-data-plane.md#adr-0050)). A database is an **optional projection sink = a queryable cache** of a materialization, **materialized into an architect-chosen backend via a schema mapping** for point/search/analytics reads — *not* the default query target. The developer owns the logical record + materialization; the **data architect owns the mapping + cache**, selected by **Matching** ([Plan 25](./platform-engineering.md#plan-25)). Rebuildable-from-zero (the log, not the sink, is authoritative); a *cached* read is reactive **iff** the sink advertises `change-feed` (the native log-backed materialization always is). Sinks are paradigm-tagged (relational/document/kv/graph/vector/object-lake/OLAP — v1 ships native+relational+document+vector; rest roadmap, [ADR-0052](./adr/03-data-plane.md#adr-0052)). Escape hatch: adopt an existing DB as **authoritative-external** ([ADR-0041](./adr/07-portability-extensibility.md#adr-0041)).
- **`command` / `subscribe` / `repo` / `view`** — the data-access surface ([Plan 32](./data-plane.md#plan-32)). **Write** = `command(type, handler)` running inside its **aggregate** boundary → `ctx.emit(event)` (the domain write path; returns its `seq` for reads-your-writes). **Read (default)** = `subscribe(materialization)` / `useSubscription()` — a live observable folded from event streams ([Plan 32](./data-plane.md#plan-32)/[ADR-0050](./adr/03-data-plane.md#adr-0050)). **Read (escape hatches)** = `repo<T>("name").get` (point lookup) + `view("name").where(...).search(...)` (snapshot/search over the sink cache), both backend-neutral by logical name + the shared [Plan 32](./data-plane.md#plan-32) predicate DSL. A typed, compile-time-checked, non-portable **`.raw(driver => …)`** escape hatch is flagged as portability debt.
- **Aggregate (write-model boundary)** — the consistency boundary a `command` writes through, **realized as an [actor](./sdk-api.md#plan-02)** (single-writer lease + fencing): the handler checks invariants against the aggregate's **write-model fold** (`ctx.state`), then emits under optimistic `seq` ([ADR-0053](./adr/03-data-plane.md#adr-0053)). The complement of a **projection** (read-model fold) — **two folds, one log** (CQRS). Writes are serializable **per aggregate**, not globally; cross-aggregate flows are **sagas**. Not a new primitive — an aggregate is an actor whose handlers emit domain events.
- **Domain schema (WIT-record canonical)** — domain DTOs are authored as **WIT records** ([ADR-0051](./adr/03-data-plane.md#adr-0051)); **TS types + protobuf event encodings + Zod validators are generated** from them ([ADR-0037](./adr/05-config-matching-environments.md#adr-0037)). One record family is the upstream for event payloads, projection shapes, and backend mappings; protobuf is an encoding, not the authoring language.
- **Operator Agents (the Crew)** — a roster of **built-in autonomous Yard services** ([Plan 40](./operators-sre.md#plan-40)/[ADR-0054](./adr/06-ai-generation-operators.md#adr-0054)) — **SRE · Endpoint Monitor · GitOps · Platform Engineer · UX Designer · SWE** — each a named **principal** (SVID + per-agent policy/spend caps, [Plan 6](./ai-native-agent-auth.md#plan-06)), event-sourced, MCP-surfaced, composing existing subsystems, with its reasoning engine behind a port (built-in default; optional externals like HolmesGPT), all sandboxed under enforced AI governance ([ADR-0061](./adr/04-governance-verification.md#adr-0061)). Reads autonomous, writes policy-gated. The AI-native realization of "AI SRE / GitOps / policy / software & UX." *Distinct from the [Relay](./platform-engineering.md#plan-25) (proxy) and from agents-as-users ([Plan 6](./ai-native-agent-auth.md#plan-06)).*
- **The generated stack** — HoBo AI-**generates, self-heals, and persists** the app across five layers — **data · business · message · intelligence · UI** ([Plan 23](./forge-generated-stack.md#plan-23)/[ADR-0055](./adr/06-ai-generation-operators.md#adr-0055)) — over one event log + WIT ports, under one conformance/policy/eval trust boundary, persisted by one mechanism (region-scoped AST edits + provenance, [ADR-0048](./adr/06-ai-generation-operators.md#adr-0048)). Self-heals unequally per layer (rebuild / live-fix / re-train / regenerate), degrading to *propose* where auto isn't safe.
- **App/UI generation** — the **UI layer** of the generated stack ([Plan 23](./forge-generated-stack.md#plan-23)/[ADR-0056](./adr/06-ai-generation-operators.md#adr-0056)): HoBo generates the developer's app UI from intent + **design.md** via the **`ui-render`** port (OpenUI / json-render / mcp-apps), owned by the **UX Designer** operator, typed from the domain and reactive to materializations. *(Distinct from the [Plan 7](./developer-experience.md#plan-07) control-plane dashboard.)*
- **Patchability** — HoBo's promise beyond portability ([Plan 23](./forge-generated-stack.md#plan-23)/[ADR-0057](./adr/07-portability-extensibility.md#adr-0057)): **derivative implementations** (swap any engine / add any adapter / fork the Yard behind the same ports), **enumerated extension seams** (providers · drivers · runtimes · engines · Resource Packs · agent-skills · projection sinks · integration ports: auth/artifact-repo/issue-tracker/knowledge, [ADR-0073](./adr/07-portability-extensibility.md#adr-0073)), and **persisted patches** ([ADR-0048](./adr/06-ai-generation-operators.md#adr-0048)) — all made trustworthy by the same **conformance** bridge that underpins portability ([ADR-0024](./adr/07-portability-extensibility.md#adr-0024)). *Portability = the same app runs on N backends; patchability = you can derive your own HoBo and keep it.*
- **Incident / runbook** — the SRE-management layer ([Plan 40](./operators-sre.md#plan-40)/[ADR-0058](./adr/06-ai-generation-operators.md#adr-0058)). An **Incident** is a first-class **aggregate** (`incident:<id>`) that correlates `alert.*`/`slo.BudgetBurned`/drift/`compat.GateFailed` into one governed object with a status/owner/SLA timeline (`incident.*`). The **SRE operator** ([Plan 40](./operators-sre.md#plan-40)) runs a documented **decision tree** — diagnose → classify (a unified runtime+contract **failure-taxonomy → safe-fix** map) → **auto-fix** (low-risk live-fix canary) / **propose** (gated Delta) / **escalate** (page on-call). A **runbook** codifies response (trigger → diagnosis → gated fix actions), event-sourced (`runbook.*`) on the Pipelines engine ([Plan 25](./platform-engineering.md#plan-25)); HolmesGPT/StackStorm are optional engines behind ports. **MTTD/MTTR** are OpenSLO SLOs; escalation is a **policy obligation with a deadline**; **postmortems are generated by replay**.
- **The `notify` port (`hobo:notify`)** — a thin **cloud-messaging port** in the resource catalog ([Plan 21](./authoring-resources-wiring.md#plan-21)/[Plan 20](./wasm-runtime-wit.md#plan-20)), *not* a standalone plane ([ADR-0059](./adr/03-data-plane.md#adr-0059)/[ADR-0064](./adr/08-scope-and-requirements.md#adr-0064)): an `email`/`sms`/`push`/`webhookOut` family behind one port, **reusing the ADR-0045 receiver port + provider adapters** (one transport, two consumers — ops alerting vs app comms). Recipients are **`PrincipalRef`s** ([Plan 6](./ai-native-agent-auth.md#plan-06)), templates are **typed WIT records** ([ADR-0051](./adr/03-data-plane.md#adr-0051)), providers (SES/Twilio/FCM/signed-webhook) are **secretless-brokered**, a `send` is an idempotent `step`, delivery is **event-sourced** (`notification.*`) → auditable + reactive ([Plan 32](./data-plane.md#plan-32)); rate/quiet-hours/consent are generic **policy obligations** ([Plan 29](./contracts-policy-flags.md#plan-29)), not a campaign/marketing product.
- **Compliance & data governance** — a governance plane over the existing planes ([Plan 46](./governance-planes.md#plan-46)/[ADR-0060](./adr/04-governance-verification.md#adr-0060)): **classification labels** on resources + WIT-record fields (`data.Classified`) feed the policy `dataClassifications`/`region` context so **residency + retention are enforced as obligations** at `can-deploy` *and* runtime ([Plan 29](./contracts-policy-flags.md#plan-29)/[Plan 29](./contracts-policy-flags.md#plan-29), reusing [ADR-0040](./adr/05-config-matching-environments.md#adr-0040)/[ADR-0036](./adr/07-portability-extensibility.md#adr-0036)). **Right-to-erasure** = **crypto-shredding** (`hobo:crypto` per-subject key destruction + tombstone) + **projection purge** ([Plan 32](./data-plane.md#plan-32)) — honoring the forward-only log (no event rewritten). The enforcement is the plane; an **OCSF attestation export** ([ADR-0046](./adr/04-governance-verification.md#adr-0046)) lets external GRC tools consume the audit facts (no compliance-program / DPA-registry product — [ADR-0064](./adr/08-scope-and-requirements.md#adr-0064)).
- **AI safety & model governance** — the trust story for HoBo's AI-native core ([Plan 46](./governance-planes.md#plan-46)/[ADR-0061](./adr/04-governance-verification.md#adr-0061)): the **Registry pattern applied to models/prompts/eval-datasets** (versioned, signed, provenance; `model.*`); a **`guardrail` capability** (moderation/PII/jailbreak/grounding) as a **policy-gated step** wrapping `agent()`/`"use training"`/generated outputs, engines behind a port (built-in/Llama Guard/local); **red-teaming** as a **chaos-tier sibling** ([ADR-0047](./adr/04-governance-verification.md#adr-0047)) whose findings become regression tests; **eval-dataset governance** (extends PII-not-trained, [ADR-0025](./adr/06-ai-generation-operators.md#adr-0025)); **model cards** exported as facts (no responsible-AI *program* — [ADR-0064](./adr/08-scope-and-requirements.md#adr-0064)); the **four lenses** applied to model/prompt promotion.
- **Registry distribution** — the publish/discover/install/trust lifecycle ([ADR-0062](./adr/07-portability-extensibility.md#adr-0062)) over the Registry + Packs ([Plan 25](./platform-engineering.md#plan-25)) + signing/conformance: **publish** (sign + `@hobo/conformance`-certify + provenance; uncertified ⇒ unlisted) → **discover** (capability-indexed, agent-drivable via MCP) → **install** (`hobo add`, **Matching-bound — install ≠ force**) → **trust** (provenance tier + publisher identity + ratings; a policy pack can require a minimum tier), **never gating portability** ([ADR-0024](./adr/07-portability-extensibility.md#adr-0024), the Forge guarantees an equivalent). Listings = providers/Packs/policy-packs/agent-skills/runbooks/Hobo-Code/guardrails (`listing.*`); versioning/deprecate/yank. **No monetization** (no free/paid/rev-share, no `billing` port — [ADR-0064](./adr/08-scope-and-requirements.md#adr-0064)).
