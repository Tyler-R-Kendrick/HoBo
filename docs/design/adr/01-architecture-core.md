# Core architecture, scope model & runtime substrate — consolidated decisions

> Consolidated ADR decisions for **core architecture, scope model & runtime substrate**. Each section is one architecture decision; see [`README.md`](./README.md) for the full ADR index.

## ADR-0001
**TS-native control-plane core (Kubernetes optional).**

The control-plane core is TS-native (actor runtime + Pulumi Automation API); Crossplane is one optional execution adapter. This gives maximal TS cohesion and self-host simplicity, at the cost of owning reconciliation/HA that k8s would otherwise provide ([Plan 4](../control-plane.md#plan-04), [Plan 5](../reliability-observability-cost.md#plan-05)).

## ADR-0002
**Pluggable durable ports + a built-in engine (the Camp runtime).**

HoBo defines runtime ports (EventStore+Queue+Streamer+ActorHost+Clock), provided per Camp, and ships a built-in engine plus adapters. The capability/resource surface targets **parity with Nitric and Vercel** — APIs, schedules, AI, websites, storage, secrets/config, databases/caching, messaging, feature flags, and functions/workflows — all expressed as resources behind ports ([Plan 21](../authoring-resources-wiring.md#plan-21)). This delivers portability with no hard engine dependency, at the cost of building and maintaining the built-in engine plus a conformance suite for the runtime ports ([Plan 2](../sdk-api.md#plan-02)).

**The portability/no-dependency guarantee is only real if the suite asserts the durability invariants** — otherwise a backend (`runtime-postgres`/`-temporal`/`-restate`/`-cloudflare`) can be "conformant by name" while silently breaking exactly-once or split-brain safety. The runtime-port suite **enumerates hard assertions** (mirroring the `component-host` suite, [ADR-0031](#adr-0031) §5): **fencing-token rejection** (a stale-fence append fails — single-writer/split-brain), **idempotency-key dedup** (exactly-once *effects* over at-least-once), **`seq`-conditional append** (optimistic concurrency / no lost updates), and **deterministic replay == live state**. A backend that doesn't pass these may not back a Camp — *no durability guarantee without a conformance assertion that enforces it* ([Plan 9](../forge-generated-stack.md#plan-09)).

## ADR-0003
**Event sourcing + CQRS as the foundation.**

An append-only event log is the single source of truth for both planes. This gives free replay/audit/time-travel and recovery, at the cost of CQRS discipline, projections, and schema upcasting ([Plan 11](../data-plane.md#plan-11)).

## ADR-0004
**Choreography sagas + virtual actors for orchestration.**

Orchestration is per-resource virtual actors (grains) reconciling desired↔actual, coordinating via events; compensation by choreography. **Compensation is robust under crash/failure, not just the happy path:** (a) a `deployment.RolledBack` flips each already-provisioned resource's **desired state to Destroyed**, so a crashed actor **re-derives the rollback on replay** (it's reconciliation, not a one-shot event it can miss); (b) reverse-dependency destroy order is **gated on observing dependents' `resource.Destroyed`** (a resource won't destroy while a dependent still exists); (c) a destroy that itself fails has an explicit **`Compensating → CompensationFailed`** terminal that **escalates to an incident** ([Plan 40](../operators-sre.md#plan-40)) rather than leaving the saga silently half-rolled-back. This gives no coordinator SPOF and per-resource isolation, at the cost of a harder "see the whole flow" — mitigated by the DeploymentView projection ([Plan 4](../control-plane.md#plan-04)).

## ADR-0005
**One ports/adapters shape for cloud, IaC, and build/VM.**

`CloudProvider`, `IacProvider`, `BuildProvider` are all swappable ports; a cloud provider composes the other two. The default **`BuildProvider` is a dagger-adjacent programmable build engine** — a DAG of containerized build steps — that **packages wasm components as OCI images by default (wasm-on-OCI)**, so `addContainer(...)` both wires *and builds* the container from one syntax. This gives uniform extensibility and one build mechanism for wasm-first and container workloads, at the cost of a provider implementing more surface to be "complete" ([Plan 4](../control-plane.md#plan-04)). The build *engine* runs on a **`build-machine`** host (self-hosted/GitHub/Blacksmith/Depot) the **Dispatcher** cost-routes per build ([ADR-0071](05-config-matching-environments.md#adr-0071)).

## ADR-0006
**IaC mechanism: pluggable adapters (Pulumi · Crossplane · Terraform · OpenTofu); no single primary.**

The `IacProvider` port ships first-class built-in adapters for **Pulumi (Automation API), Crossplane, Terraform, and OpenTofu** out of the box — none is "the primary." A self-hosted deployment **configures which IaC provider(s) it uses**, and the choice can be made per-workload / per-Camp via Matching ([ADR-0033](05-config-matching-environments.md#adr-0033)). Adapters are **distributed and consumed like plugins from an external git registry**, and the port is **extensible using git repositories as importable modules**, so new IaC backends and shared modules install without forking HoBo. Regardless of adapter, **each resource owns an isolated IaC stack**: the unit of state is the resource, not the deployment.

Per-resource stacks give blast-radius isolation and rollback that reaches **what stack state records** — but a mid-apply failure (provider created an object, then the state-write failed: the classic "created-but-not-in-state" window) leaves an **orphan no destroy will reach**. So rollback is "destroy recorded state **plus a tag-based orphan sweep**": every provider object is tagged with `tenant/deployment/resource`, and reconciliation sweeps tagged objects absent from state (rather than re-creating duplicates on the next `refresh()`). "Clean compensation" is thus scoped honestly to recorded-state + orphan-sweep, at the cost of more state objects to manage ([Plan 4](../control-plane.md#plan-04)).

## ADR-0007
**Provider-specific options via an idiomatic typed-options builder (`.with(...)`).**

Per-provider optimization is additive, typed, and inert for non-resolved providers, so one Bindle targets many clouds unedited; `require`/`prefer` controls strictness. Provider options use an **idiomatic typed-options builder pattern** — the same shape .NET uses for middleware/service configuration (`addX(options => { … })` with a strongly-typed, per-provider options object) — so options are discoverable, validated, and composable. The agnostic promise and escape hatch coexist, at the cost of provider packages exporting accurate typed option builders ([Plan 2](../sdk-api.md#plan-02)).

## ADR-0011
**Scopes are first-class SDK objects (`bindle`/`camp`/`yard`/`junction`), not config files.**

The four scopes are constructed and composed **programmatically in the SDK**, not declared in separate `*.config.ts` files. `bindle(name)` declares the provider-agnostic app (`.addContainer(...)`, abstract deps); `camp(name)` imports Bindles and maps them to one provider's resources (`camp.import(app)`); `yard(name, provider)` groups Camps under one provider and holds cross-Camp policy/gateways (`yard.setup(camp1, camp2)`); `junction(name)` connects Yards across clouds (`junction.add(azureYard, awsYard)`). The objects **are** the topology; config is data on them, not a parallel file. This gives one composable, typed, testable surface, keeping the Bindle provider-agnostic while Camp/Yard/Junction carry provider + cross-cloud specifics ([Plan 2](../sdk-api.md#plan-02)/[Plan 7](../developer-experience.md#plan-07)).

## ADR-0026
**Scope model: `Bindle ⊂ Camp ⊂ Yard ⊂ Junction`.**

Four nested scopes, each owning a distinct kind of "what varies":

1. **Bindle = the app, provider-agnostic.** App-level abstractions only — service boundaries and **abstract dependencies** (a SQL/data store, a message bus, a bucket) — with **no cloud-provider specifics**. A Bindle deploys *into* Camps unchanged.
2. **Camp = a provider-specific deployment target (≈ a Pulumi stack).** It maps the Bindle's abstract deps onto **one provider's** concrete resources in one provider-specific grouping (e.g. an Azure resource group in one region); two Camps can be the same Bindle on the same provider but differ by group/region. A Camp **provides the durable runtime** (EventStore + Queue + Streamer + ActorHost + Clock, behind the `Runtime` interface; built-in `runtime-local`, backends `runtime-postgres`/`-temporal`/`-restate`/`-cloudflare`) and carries **camp-local networking constraints**.
3. **Yard = cross-Camp scope, still provider-specific.** A Yard groups Camps under **one** provider and applies **cross-Camp constraints**: policies, provider-global networking (e.g. a vWAN), and global gateways (e.g. Azure Front Door). It runs the control plane for its provider.
4. **Junction = cross-cloud / hybrid.** A Junction connects **Yards** (each provider-specific) for multi-cloud and hybrid scenarios — federating trust + signed artifacts + cross-cloud policy, never a shared-state controller ([ADR-0043](07-portability-extensibility.md#adr-0043)).

**Environments are a matching dimension, not a layer** — a Camp carries an `environment type` ([Plan 25](../platform-engineering.md#plan-25)/[Plan 25](../platform-engineering.md#plan-25)).

**WIT interface** is the WebAssembly Component Model term ([Plan 20](../wasm-runtime-wit.md#plan-20)/[Plan 20](../wasm-runtime-wit.md#plan-20)) — the contract shape for ports.

### Consequences
- **(+)** Each level maps to a real concern: portable app (Bindle) / provider stack (Camp ≈ Pulumi stack) / provider-global cross-Camp policy + gateways (Yard) / cross-cloud + hybrid (Junction), with no overloaded noun.
- **(−)** Four nested scopes are more model to learn than a flat app/environment split.

## ADR-0031
**wasm host of record: self-hosted wasmCloud (default), wasm-in-container floor.**

HoBo is **wasm-first, OCI-container fallback** ([Plan 20](../wasm-runtime-wit.md#plan-20)), with WIT interfaces as the port contracts and late-bound **links** binding a component's imports to a provider's exports. The **host of record** — *what actually executes components* locally and in prod — is concrete so the "any language, one artifact, runs anywhere" claim holds and [ADR-0026](#adr-0026)'s "a Camp selects its runtime backend" has an answer at the wasm execution layer.

1. **The wasm host is a port, not a mandate.** Introduce a **`component-host`** capability/port (the WASI interface impls + the link table + the component lifecycle). The host is a **property of a Camp** ([ADR-0026](#adr-0026)) — a Camp selects its `component-host` the same way it independently selects its runtime backend and infra Provider. Camps stay heterogeneous ([ADR-0028](05-config-matching-environments.md#adr-0028)): one Camp may run SpinKube while another runs provider-native.
2. **Default = self-hosted wasmCloud.** The default host is the **wasmCloud lattice** (CNCF; hosts mesh over **NATS/JetStream**), **self-hosted on your own infrastructure** — **Kubernetes** (the `wasmcloud-operator` + Helm-bundled NATS), **Coolify/Docker**, or **bare metal/VPS** — with no managed-cloud dependency. wasmCloud is the deliberate default because its lattice **speaks wRPC natively** — exactly HoBo's membrane ([ADR-0069](#adr-0069)) — so the whole stack (WIT ports + wRPC links + cross-host late binding) is coherent end-to-end, and it **embeds Wasmtime**, preserving dev/prod parity. Self-hosting keeps it portable: any k8s (Hetzner/k3s/Talos/AKS/EKS/GKE) or any Docker host runs it.
3. **wasm-in-container is the zero-infra portable floor; other hosts are opt-in.** For the simplest "runs anywhere a container runs" case (and Coolify/Docker deploys), the component host runs **inside an OCI container** via the existing OCI pipeline ([Plan 21](../authoring-resources-wiring.md#plan-21)) with **zero new infra** — the floor every Camp can fall back to. **SpinKube / containerd-wasm** (k8s shim density) and **provider-native wasm** (e.g. **Cloudflare Workers**) are opt-in adapters chosen per Camp, each certified against the `component-host` conformance suite ([Plan 9](../forge-generated-stack.md#plan-09)).
4. **Local/dev + the `runtime-local` host = Wasmtime.** The canonical Bytecode Alliance Component-Model engine is the host of record for `hobo dev` and the built-in runtime, so **local semantics match prod** (the in-container default also embeds Wasmtime). **jco-in-Node is rejected** as the dev host — a second, divergent wasm semantics surface would undermine dev/prod parity.
5. **One conformance boundary, version-pinned.** A `component-host` adapter may only be selected by a Camp if it passes the **`@hobo/conformance/component-host`** suite ([Plan 9](../forge-generated-stack.md#plan-09)) — the same trust machinery as provider/runtime-port conformance. The suite asserts the exact properties HoBo's guarantees depend on: **deterministic-Clock trace replay** (same run → identical state across hosts, for event-sourced replay [Plan 11](../data-plane.md#plan-11)), **`wasi:*` interface round-trip** (vendored/pinned interfaces behave identically), **link late-binding semantics** (an imported interface resolves to a provider export the same way everywhere), and **capability-handle isolation** (deny-by-default; an un-linked capability call fails). The chosen host **kind + version is pinned in the manifest IR** ([Plan 21](../authoring-resources-wiring.md#plan-21)): a Bindle records what it was built/certified against, and a Camp whose host is incompatible fails planning with a precise reason (mirroring the `wasi:*`/runtime version policy in [ADR-0024](07-portability-extensibility.md#adr-0024) §5). Host upgrades go through an explicit gated path with an **upcaster** where semantics change — no silent rewrite of component behavior. Host-specific capabilities (e.g. wasmCloud lattice link-migration) are typed as host-`.with()` options, inert on hosts that don't offer them, and flagged by `hobo doctor` as host lock-in (same model as provider `.with()`).

### Consequences
- **(+)** The default is a coherent, **self-hostable, CNCF** stack (self-hosted **wasmCloud** + the **wRPC** membrane + **Wasmtime**, on any k8s / Coolify / bare metal, no managed-cloud dependency), with **wasm-in-container** as the zero-infra portable floor and provider-native/SpinKube hosts opt-in — every component conformance-verified across hosts.
- **(−)** Self-hosted wasmCloud means operating **NATS/JetStream + the wasmCloud hosts** (more than a bare container, though the `wasmcloud-operator` + Helm bundle make it turnkey), and several host adapters mean conformance surface to build and maintain.

## ADR-0069
**The runtime & membrane: WIT-interface providers over wRPC, wrapped by a thin SDK.**

HoBo realizes the "runtime + membrane + provider" shape (proven by Nitric: app code → SDK → local runtime/membrane → provider plugin) natively on the WebAssembly **Component Model** rather than on a language-specific plugin SDK and a hand-rolled gRPC wire. The membrane is the component model — built on WIT ports ([Plan 20](../wasm-runtime-wit.md#plan-20)), late-bound **links**, and the `component-host` ([ADR-0031](#adr-0031)) — not a parallel mechanism.

1. **The runtime provides a full building-block set (Nitric parity), each as a WIT interface** ([Plan 20](../wasm-runtime-wit.md#plan-20)): APIs/HTTP, schedules, topics & subscriptions (pub/sub), queues, key/value, storage/blob, secrets, SQL, and websockets — alongside HoBo's own durable workflow/actors, reactive materializations, auth, and AI/training. A "building block" is just a **port** ([ADR-0005](#adr-0005)).
2. **Providers implement the WIT interfaces directly — not a Go/TS plugin SDK.** A provider is a WASM **component** (or WIT-conformant adapter) that *exports* the building-block interfaces; there is no HoBo-specific provider language or plugin API to learn — the contract **is** the WIT world, and the Forge can generate it ([ADR-0010](06-ai-generation-operators.md#adr-0010)/[ADR-0010](06-ai-generation-operators.md#adr-0010)). This is the key departure from Nitric's per-language provider plugins.
3. **The membrane is wRPC, not plain gRPC.** App-component imports are bound to provider-component exports by **links** and invoked over **wRPC** (wasmCloud's WIT-native RPC; transport-agnostic, NATS by default), so the same WIT contract drives in-process, cross-process, and cross-host (lattice) invocation — consistent with the `component-host` adapters ([ADR-0031](#adr-0031), incl. the wasmCloud-lattice host). No separate IDL or hand-maintained protobuf: the wire is generated from WIT. **The three invocation modes have different failure modes, so the membrane specifies them, not just the happy path** ([Plan 20](../wasm-runtime-wit.md#plan-20)): a **caller-supplied deadline propagates** with the call (every link is a Plan 5 timeout boundary, `link.Called` carrying the deadline); **backpressure** maps to NATS/JetStream flow-control so a saturated provider sheds rather than collapses; a **partial/ambiguous failure** (hung, severed mid-stream for the long-lived `wasi:io` streaming interfaces, ambiguous return) is classified into the Plan 5 failure taxonomy and reconciled by the idempotency-key rule (exactly-once for EventStore-append effects; **at-least-once + provider-side idempotency for provider RPC**, [Plan 5](../reliability-observability-cost.md#plan-05)); and a **runtime wire-version mismatch** (caller and provider built against different pinned wRPC/WIT minors meeting across a lattice link) is resolved by a defined rule — **negotiate the highest shared minor at or above a declared compatibility floor; below the floor, reject the *link* (not silently the call) with a typed `version-incompatible` error** surfaced at deploy/link-time — never silently coerced. These are gated by `@hobo/conformance/component-host` ([Plan 9](../forge-generated-stack.md#plan-09)).
4. **A thin SDK wraps the runtime.** The TS SDK ([Plan 2](../sdk-api.md#plan-02)) is ergonomic sugar over the generated WIT bindings — typed clients for the runtime's imported interfaces. It holds **no cloud logic**; all behavior lives behind the WIT ports in the runtime + providers, so the SDK stays small and every language with a Component-Model binding can host the same app. The SDK is itself **WIT-first**: a canonical `hobo:sdk` world `wit-bindgen`'d per language + a conformance-gated idiom layer — TS is the first idiom layer, not the source of truth ([ADR-0072](#adr-0072)).
5. **Deny-by-default is structural.** An imported interface with no link / no `.allow()` grant cannot be invoked — wRPC only routes linked interfaces and capability handles are deny-by-default ([ADR-0023](02-identity-security.md#adr-0023)/[Plan 21](../authoring-resources-wiring.md#plan-21)). Capability is granted by linking, not by ambient reachability.
6. **The contract is WIT/WASM, not a language.** The entire programmable surface — Bindles, services, providers — targets the Component Model and runs on wasmCloud; HoBo requires **WIT + WASM**, with **TypeScript as the first reference implementation, not a requirement**. Any language with a Component-Model toolchain authors against the same WIT worlds.

### Consequences
- **(+)** One contract everywhere: a building block is a WIT interface, a provider is a WIT component, the wire is wRPC generated from that WIT — local dev, cross-process, and lattice all use the same mechanism ([ADR-0031](#adr-0031)), with conformance ([Plan 9](../forge-generated-stack.md#plan-09)) as the single trust boundary and no language lock-in for provider authors.
- **(−)** wRPC is younger than gRPC (HoBo pins/vendors its wRPC + WIT versions and ships a membrane conformance suite), and "everything is a WIT interface" demands disciplined interface design + versioning ([ADR-0024](07-portability-extensibility.md#adr-0024)).

## ADR-0072
**The SDK is WIT-first: a canonical `hobo:sdk` world built against per-language, with conformance-gated idiom layers.**

HoBo treats WIT as the contract for providers ([ADR-0069](#adr-0069)), domain schema ([ADR-0051](03-data-plane.md#adr-0051)), and app-developer bindings ([ADR-0037](05-config-matching-environments.md#adr-0037)); typed clients are generated from WIT (jco guest-types, [Plan 20](../wasm-runtime-wit.md#plan-20)). WIT cleanly expresses function signatures + records + imported interfaces — but **not** fluent builders, IfC collection-mode, decorators, or `.allow()` chaining, which are inherently language-side. The model splits the WIT-expressible *contract* from the language-native *ergonomics* without letting the ergonomics drift into new semantics.

1. **A canonical `hobo:sdk` world is the SDK contract.** Beyond the capability + data interfaces ([Plan 20](../wasm-runtime-wit.md#plan-20)) and domain records ([ADR-0051](03-data-plane.md#adr-0051)), the SDK's **runtime primitives are pinned as WIT** — `workflow`/`step`/`actor`/`saga`/`agent`/`command`/`subscribe` signatures (the `hobo:workflow`/`hobo:actor`/`hobo:saga`/`hobo:agent` interfaces, [Plan 20](../wasm-runtime-wit.md#plan-20)) aggregated into a **`hobo:sdk` world**. This world *is* the standard contract; its semantics are identical in every language.
2. **Each language SDK is built against WIT = generated bindings + a thin idiom layer.** A language SDK is produced by **`wit-bindgen`/jco against `hobo:sdk`** (the mechanical, low-level bindings) plus a **thin, language-native idiom layer** that adds ergonomics — TS builder chains + IfC collection ([Plan 21](../authoring-resources-wiring.md#plan-21)), Rust traits/builders, Python decorators/context-managers, Go option structs — and **nothing else**. The idiom layer lowers to the same generated bindings + emits the same **manifest IR** ([Plan 21](../authoring-resources-wiring.md#plan-21)); it carries **no cloud logic and no new semantics** ([ADR-0069](#adr-0069)'s thin-SDK rule, now made precise). The TS `@hobo/sdk` is therefore *the first idiom layer*, not a privileged source of truth.
3. **The WIT/idiom seam is the honest split.** WIT owns the **contract** (primitive + capability + data signatures, the `.allow()` verb set, the manifest-IR shape); the idiom layer owns the **ergonomics** (fluent surface, IfC collection-mode side-effects, decorators) that can't be expressed in WIT. This is why the IfC fluent surface ([Plan 21](../authoring-resources-wiring.md#plan-21)) and the WIT contract coexist — the fluent/IfC surface *is* the idiom layer, compiling down to the contract. **Hobo Code** ([ADR-0049](05-config-matching-environments.md#adr-0049)) and every language SDK are **front-ends over the one `hobo:sdk` contract**.
4. **The idiom layer is conformance-gated to *lowering-equivalence over a corpus* — not a proof of zero semantics.** A `@hobo/conformance/sdk` suite ([Plan 9](../forge-generated-stack.md#plan-09)) asserts that, for the conformance corpus, an idiom layer's inputs **lower to identical WIT calls + identical manifest IR** across languages (golden-IR equivalence + replay) — bounded by the corpus, like every conformance suite, *not* a universal proof. The behaviors an idiom layer **legitimately owns and that lowering-equivalence can't constrain** — **error mapping** (a Rust `result`-unwrap vs a TS throw vs a Go `(T,err)` are the same WIT `result<>` at the boundary but different in-language control flow), **async/cancellation**, and **IfC collection-mode side-effects/order** — are governed by a per-language **semantics annex** with **negative/error-path + cancellation test vectors**, not by the happy-path corpus. So an idiom layer with a missing/wrong error or cancellation mapping **fails the annex**, not the golden-IR check. The honest claim is *lowering-equivalence + an enumerated semantics annex*, not "no semantics."
5. **Idiom layers may be hand-authored *or* SWE-operator/Forge-generated — both conformance-gated.** A language SDK's idiom layer is normally hand-authored for genuine taste, but may also be **generated by the SWE operator** ([Plan 40](../operators-sre.md#plan-40)/[ADR-0054](06-ai-generation-operators.md#adr-0054)) via the Forge loop ([Plan 23](../forge-generated-stack.md#plan-23)) from `hobo:sdk`: `wit-bindgen` produces the bindings, the SWE agent writes the idiomatic wrapper, and `@hobo/conformance/sdk` gates it exactly as for a human author. There is no trusted-by-convention path — generated or hand-written, the parity gate is the same.
6. **Reverse compiling is a first-class direction.** **Forward** = `hobo:sdk` → bindings → idiom layer → a component imports the worlds. **Reverse** = a component/artifact → its **extracted WIT world** (what it actually imports/exports) → an idiom-layer skeleton (the SWE operator's starting point) **or** a parity/adoption report. The two directions share one contract.

### Consequences
- **(+)** One `hobo:sdk` world is the contract: every language SDK is `wit-bindgen`'d against it + a thin idiom layer, so multi-language SDKs become a generation+conformance task, not N re-implementations, and "thin SDK" becomes testable (*thin = generated bindings + a semantics-free idiom layer*).
- **(−)** Pinning primitive signatures in `hobo:sdk` makes them a maintained public contract subject to WIT versioning ([ADR-0024](07-portability-extensibility.md#adr-0024)), and a `@hobo/conformance/sdk` golden-IR/replay suite per language is new test surface to keep current.
