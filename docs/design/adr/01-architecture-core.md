# Core architecture, scope model & runtime substrate — consolidated decisions

> Consolidated ADR decisions for **core architecture, scope model & runtime substrate**. Each section is one architecture decision; see [`README.md`](./README.md) for the full ADR index.

## ADR-0001
**TS-native control-plane core (Kubernetes optional).**

**Context:** the control plane could be built on Kubernetes/Crossplane or as a bespoke TS service. **Decision:** TS-native core (actor runtime + Pulumi Automation API); Crossplane is one optional execution adapter. **Consequences:** maximal TS cohesion + self-host simplicity; we own reconciliation/HA we'd otherwise inherit from k8s ([Plan 4](../control-plane.md#plan-04), [Plan 5](../reliability-observability-cost.md#plan-05)).

## ADR-0002
**Pluggable durable ports + a built-in engine (the Camp runtime).**

**Context:** adopt one durable engine (Temporal/Restate) vs define our own ports. **Decision:** HoBo defines runtime ports (EventStore+Queue+Streamer+ActorHost+Clock), provided per Camp, and ships a built-in engine plus adapters. The capability/resource surface targets **parity with Nitric and Vercel** — APIs, schedules, AI, websites, storage, secrets/config, databases/caching, messaging, feature flags, and functions/workflows — all expressed as resources behind ports ([Plan 21](../authoring-resources-wiring.md#plan-21)). **Consequences:** portability + no hard dependency; we must build/maintain the built-in engine and a conformance suite for the runtime ports ([Plan 2](../sdk-api.md#plan-02)).

## ADR-0003
**Event sourcing + CQRS as the foundation.**

**Context:** state-based store vs event log. **Decision:** append-only event log is the single source of truth for both planes. **Consequences:** free replay/audit/time-travel and recovery; cost is CQRS discipline, projections, and schema upcasting ([Plan 11](../event-model.md#plan-11)).

## ADR-0004
**Choreography sagas + virtual actors for orchestration.**

**Context:** central orchestrator vs choreography. **Decision:** per-resource virtual actors (grains) reconciling desired↔actual, coordinating via events; compensation by choreography. **Consequences:** no coordinator SPOF, natural parallelism, per-resource isolation; harder "see the whole flow" — mitigated by the DeploymentView projection ([Plan 4](../control-plane.md#plan-04)).

## ADR-0005
**One ports/adapters shape for cloud, IaC, and build/VM.**

**Decision:** `CloudProvider`, `IacProvider`, `BuildProvider` are all swappable ports; a cloud provider composes the other two. The default **`BuildProvider` is a dagger-adjacent programmable build engine** — a DAG of containerized build steps — that **packages wasm components as OCI images by default (wasm-on-OCI)**, so `addContainer(...)` both wires *and builds* the container from one syntax. **Consequences:** uniform extensibility (incl. Forge); one build mechanism for wasm-first and container workloads; a provider must implement more surface to be "complete" ([Plan 4](../control-plane.md#plan-04)). The build *engine* runs on a **`build-machine`** host (self-hosted/GitHub/Blacksmith/Depot) the **Dispatcher** cost-routes per build ([ADR-0071](05-config-matching-environments.md#adr-0071)).

## ADR-0006
**IaC mechanism: pluggable adapters (Pulumi · Crossplane · Terraform · OpenTofu); no single primary.**

**Decision:** the `IacProvider` port ships first-class built-in adapters for **Pulumi (Automation API), Crossplane, Terraform, and OpenTofu** out of the box — none is "the primary." A self-hosted deployment **configures which IaC provider(s) it uses**, and the choice can be made per-workload / per-Camp via Matching ([ADR-0033](05-config-matching-environments.md#adr-0033)). Adapters are **distributed and consumed like plugins from an external git registry**, and the port is **extensible using git repositories as importable modules**, so new IaC backends and shared modules install without forking HoBo. Regardless of adapter, **each resource owns an isolated IaC stack**: the unit of state is the resource, not the deployment. **Consequences:** real-language compositions (Pulumi/TS), HCL ecosystems (Terraform/OpenTofu), and k8s control planes (Crossplane) coexist behind one port; HoBo maintains the adapter contract + conformance suite, not a favored engine. Per-resource stacks give blast-radius isolation and clean compensation (a failed resource rolls back alone), at the cost of more state objects to manage ([Plan 4](../control-plane.md#plan-04)).

## ADR-0007
**Provider-specific options via an idiomatic typed-options builder (`.with(...)`).**

**Decision:** per-provider optimization is additive, typed, and inert for non-resolved providers, so one Bindle targets many clouds unedited; `require`/`prefer` controls strictness. Provider options use an **idiomatic typed-options builder pattern** — the same shape .NET uses for middleware/service configuration (`addX(options => { … })` with a strongly-typed, per-provider options object) — so options are discoverable, validated, and composable. **Consequences:** the agnostic promise + escape hatch coexist; provider packages must export accurate typed option builders ([Plan 2](../sdk-api.md#plan-02)).

## ADR-0011
**Scopes are first-class SDK objects (`bindle`/`camp`/`yard`/`junction`), not config files.**

**Decision:** the four scopes are constructed and composed **programmatically in the SDK**, not declared in separate `*.config.ts` files. `bindle(name)` declares the provider-agnostic app (`.addContainer(...)`, abstract deps); `camp(name)` imports Bindles and maps them to one provider's resources (`camp.import(app)`); `yard(name, provider)` groups Camps under one provider and holds cross-Camp policy/gateways (`yard.setup(camp1, camp2)`); `junction(name)` connects Yards across clouds (`junction.add(azureYard, awsYard)`). The objects **are** the topology; config is data on them, not a parallel file. **Consequences:** one composable, typed, testable surface; the Bindle stays provider-agnostic while Camp/Yard/Junction carry provider + cross-cloud specifics ([Plan 2](../sdk-api.md#plan-02)/[Plan 7](../developer-experience.md#plan-07)).

## ADR-0026
**Scope model: `Bindle ⊂ Camp ⊂ Yard ⊂ Junction`.**

### Decision
Four nested scopes, each owning a distinct kind of "what varies":

1. **Bindle = the app, provider-agnostic.** App-level abstractions only — service boundaries and **abstract dependencies** (a SQL/data store, a message bus, a bucket) — with **no cloud-provider specifics**. A Bindle deploys *into* Camps unchanged.
2. **Camp = a provider-specific deployment target (≈ a Pulumi stack).** It maps the Bindle's abstract deps onto **one provider's** concrete resources in one provider-specific grouping (e.g. an Azure resource group in one region); two Camps can be the same Bindle on the same provider but differ by group/region. A Camp **provides the durable runtime** (EventStore + Queue + Streamer + ActorHost + Clock, behind the `Runtime` interface; built-in `runtime-local`, backends `runtime-postgres`/`-temporal`/`-restate`/`-cloudflare`) and carries **camp-local networking constraints**.
3. **Yard = cross-Camp scope, still provider-specific.** A Yard groups Camps under **one** provider and applies **cross-Camp constraints**: policies, provider-global networking (e.g. a vWAN), and global gateways (e.g. Azure Front Door). It runs the control plane for its provider.
4. **Junction = cross-cloud / hybrid.** A Junction connects **Yards** (each provider-specific) for multi-cloud and hybrid scenarios — federating trust + signed artifacts + cross-cloud policy, never a shared-state controller ([ADR-0043](07-portability-extensibility.md#adr-0043)).

**Environments are a matching dimension, not a layer** — a Camp carries an `environment type` ([Plan 25](../platform-engineering.md#plan-25)/[Plan 25](../platform-engineering.md#plan-25)).

**WIT interface** is the WebAssembly Component Model term ([Plan 20](../wasm-runtime-wit.md#plan-20)/[Plan 20](../wasm-runtime-wit.md#plan-20)) — the contract shape for ports.

### Consequences
- **(+)** Each level maps to a real concern: portable app (Bindle) / provider stack (Camp ≈ Pulumi stack) / provider-global cross-Camp policy + gateways (Yard) / cross-cloud + hybrid (Junction).
- **(+)** Multi-region within a provider = several Camps under one Yard; multi-cloud = several Yards under a Junction — no overloaded noun.
- **(+)** Cross-cloud is an explicit first-class scope (the Junction), not a property smuggled into the control plane.

## ADR-0031
**wasm host of record: self-hosted wasmCloud (default), wasm-in-container floor.**

### Context
[Plan 20](../wasm-runtime-wit.md#plan-20) commits HoBo to **wasm-first, OCI-container fallback**, with WIT interfaces as the port contracts and late-bound **links** binding a component's imports to a provider's exports. The **host of record** — *what actually executes components* locally and in prod — must be concrete for the "any language, one artifact, runs anywhere" claim to hold and for [ADR-0026](#adr-0026)'s "a Camp selects its runtime backend" to have an answer at the wasm execution layer.

### Decision
1. **The wasm host is a port, not a mandate.** Introduce a **`component-host`** capability/port (the WASI interface impls + the link table + the component lifecycle). The host is a **property of a Camp** ([ADR-0026](#adr-0026)) — a Camp selects its `component-host` the same way it independently selects its runtime backend and infra Provider. Camps stay heterogeneous ([ADR-0028](05-config-matching-environments.md#adr-0028)): one Camp may run SpinKube while another runs provider-native.
2. **Default = self-hosted wasmCloud.** The default host is the **wasmCloud lattice** (CNCF; hosts mesh over **NATS/JetStream**), **self-hosted on your own infrastructure** — **Kubernetes** (the `wasmcloud-operator` + Helm-bundled NATS), **Coolify/Docker**, or **bare metal/VPS** — with no managed-cloud dependency. wasmCloud is the deliberate default because its lattice **speaks wRPC natively** — exactly HoBo's membrane ([ADR-0069](#adr-0069)) — so the whole stack (WIT ports + wRPC links + cross-host late binding) is coherent end-to-end, and it **embeds Wasmtime**, preserving dev/prod parity. Self-hosting keeps it portable: any k8s (Hetzner/k3s/Talos/AKS/EKS/GKE) or any Docker host runs it.
3. **wasm-in-container is the zero-infra portable floor; other hosts are opt-in.** For the simplest "runs anywhere a container runs" case (and Coolify/Docker deploys), the component host runs **inside an OCI container** via the existing OCI pipeline ([Plan 21](../authoring-resources-wiring.md#plan-21)) with **zero new infra** — the floor every Camp can fall back to. **SpinKube / containerd-wasm** (k8s shim density) and **provider-native wasm** (e.g. **Cloudflare Workers**) are opt-in adapters chosen per Camp, each certified against the `component-host` conformance suite ([Plan 9](../verification.md#plan-09)).
4. **Local/dev + the `runtime-local` host = Wasmtime.** The canonical Bytecode Alliance Component-Model engine is the host of record for `hobo dev` and the built-in runtime, so **local semantics match prod** (the in-container default also embeds Wasmtime). **jco-in-Node is rejected** as the dev host — a second, divergent wasm semantics surface would undermine dev/prod parity.
5. **One conformance boundary, version-pinned.** A `component-host` adapter may only be selected by a Camp if it passes the **`@hobo/conformance/component-host`** suite ([Plan 9](../verification.md#plan-09)) — the same trust machinery as provider/runtime-port conformance. The suite asserts the exact properties HoBo's guarantees depend on: **deterministic-Clock trace replay** (same run → identical state across hosts, for event-sourced replay [Plan 11](../event-model.md#plan-11)), **`wasi:*` interface round-trip** (vendored/pinned interfaces behave identically), **link late-binding semantics** (an imported interface resolves to a provider export the same way everywhere), and **capability-handle isolation** (deny-by-default; an un-linked capability call fails). The chosen host **kind + version is pinned in the manifest IR** ([Plan 21](../authoring-resources-wiring.md#plan-21)): a Bindle records what it was built/certified against, and a Camp whose host is incompatible fails planning with a precise reason (mirroring the `wasi:*`/runtime version policy in [ADR-0024](07-portability-extensibility.md#adr-0024) §5). Host upgrades go through an explicit gated path with an **upcaster** where semantics change — no silent rewrite of component behavior. Host-specific capabilities (e.g. wasmCloud lattice link-migration) are typed as host-`.with()` options, inert on hosts that don't offer them, and flagged by `hobo doctor` as host lock-in (same model as provider `.with()`).

### Alternatives considered
- **Mandate a single managed host (e.g. a cloud's wasm/k8s service).** Rejected: couples HoBo to one vendor and breaks "the host is a Camp property" ([ADR-0026](#adr-0026)). wasmCloud-as-default does **not** mandate managed k8s — it self-hosts on any k8s, Coolify/Docker, or bare metal, and any Camp can fall back to the container floor or pick provider-native.
- **wasm-in-container as the *sole* default (no default lattice).** Rejected as the default (kept as the portable floor): it runs anywhere a container runs with zero infra but offers no cross-host late-bound links/lattice and doesn't match the wRPC membrane natively. Defaulting to self-hosted wasmCloud makes the WIT+wRPC stack coherent, while self-hosting + the container floor keep it portable.
- **jco-in-Node for the local host.** Rejected: convenient for a JS shop but a second wasm semantics surface vs Wasmtime in prod; "works on `hobo dev`" would stop predicting "works in a Camp."
- **No abstraction — just pick one host and hard-wire it.** Rejected: the entire Plan 20 model is link-based ports/adapters; the host must be swappable like every other capability, or multi-cloud/edge heterogeneity breaks.

### Consequences
- **(+)** The default is a coherent, **self-hostable, CNCF** stack: self-hosted **wasmCloud** + the **wRPC** membrane + **Wasmtime**, on any k8s / Coolify / bare metal — no managed-cloud dependency, with lattice cross-host links available by default.
- **(+)** Portability preserved: **wasm-in-container** is the zero-infra floor any Camp can drop to, and **provider-native** hosts (Cloudflare Workers) or SpinKube are opt-in — the same component is conformance-verified across hosts. The `multi-cloud-shop` E2E ([ADR-0024](07-portability-extensibility.md#adr-0024)) runs **Wasmtime local → self-hosted wasmCloud → wasm-in-container → (opt-in) provider-native** with identical behavior under trace replay. Reuses the OCI pipeline ([Plan 21](../authoring-resources-wiring.md#plan-21)), the conformance boundary ([Plan 9](../verification.md#plan-09)), and the Firecracker sandbox ([ADR-0012](02-identity-security.md#adr-0012)).
- **(+)** Dev/prod parity is *verified*, not assumed: Wasmtime runs locally **and inside wasmCloud**, one semantics surface; cold-start stays ms-scale, improving failover/rollback windows ([Plan 5](../reliability-observability-cost.md#plan-05)).
- **(+)** Camps remain heterogeneous ([ADR-0028](05-config-matching-environments.md#adr-0028)); a regulated/edge Camp can pick a different host than a cloud Camp under the same Yard.
- **(−)** Self-hosted wasmCloud means operating **NATS/JetStream + the wasmCloud hosts** — the `wasmcloud-operator` + Helm bundle make this turnkey on k8s, and Coolify/Docker covers lighter setups, but it is more than a bare container; the **wasm-in-container floor** exists for teams that want zero lattice ops. Several host adapters also mean conformance surface to build/maintain (deterministic-Clock + WASI fidelity assertions).
- **(−)** Advanced lattice features (cross-host late-bound links, live multi-region link migration) live in the **wasmCloud adapter**, not the portable default — apps that need them must select that host per Camp, and host-`.with()` options reintroduce a typed, `hobo doctor`-flagged lock-in surface.

## ADR-0069
**The runtime & membrane: WIT-interface providers over wRPC, wrapped by a thin SDK.**

### Context
Nitric proves the "runtime + membrane + provider" shape: app code calls an SDK → a local **runtime/membrane** (Nitric uses **gRPC**) → a **provider plugin** (written in **Go**) that implements each building block against a specific cloud. HoBo wants Nitric's full building-block runtime, but realized natively on the WebAssembly **Component Model** rather than on a language-specific plugin SDK and a hand-rolled gRPC wire. The pieces already exist — WIT ports ([Plan 20](../wasm-runtime-wit.md#plan-20)), late-bound **links**, the `component-host` ([ADR-0031](#adr-0031)) — so the membrane should be the component model, not a parallel mechanism.

### Decision
1. **The runtime provides a full building-block set (Nitric parity), each as a WIT interface** ([Plan 20](../wasm-runtime-wit.md#plan-20)): APIs/HTTP, schedules, topics & subscriptions (pub/sub), queues, key/value, storage/blob, secrets, SQL, and websockets — alongside HoBo's own durable workflow/actors, reactive materializations, auth, and AI/training. A "building block" is just a **port** ([ADR-0005](#adr-0005)).
2. **Providers implement the WIT interfaces directly — not a Go/TS plugin SDK.** A provider is a WASM **component** (or WIT-conformant adapter) that *exports* the building-block interfaces; there is no HoBo-specific provider language or plugin API to learn — the contract **is** the WIT world, and the Forge can generate it ([ADR-0010](06-ai-generation-operators.md#adr-0010)/[ADR-0010](06-ai-generation-operators.md#adr-0010)). This is the key departure from Nitric's per-language provider plugins.
3. **The membrane is wRPC, not plain gRPC.** App-component imports are bound to provider-component exports by **links** and invoked over **wRPC** (wasmCloud's WIT-native RPC; transport-agnostic, NATS by default), so the same WIT contract drives in-process, cross-process, and cross-host (lattice) invocation — consistent with the `component-host` adapters ([ADR-0031](#adr-0031), incl. the wasmCloud-lattice host). No separate IDL or hand-maintained protobuf: the wire is generated from WIT. **The three invocation modes have different failure modes, so the membrane specifies them, not just the happy path** ([Plan 20](../wasm-runtime-wit.md#plan-20)): a **caller-supplied deadline propagates** with the call (every link is a Plan 5 timeout boundary, `link.Called` carrying the deadline); **backpressure** maps to NATS/JetStream flow-control so a saturated provider sheds rather than collapses; a **partial/ambiguous failure** (hung, severed mid-stream for the long-lived `wasi:io` streaming interfaces, ambiguous return) is classified into the Plan 5 failure taxonomy and reconciled by the existing idempotency-key exactly-once-*effects* rule; and a **runtime wire-version mismatch** (caller and provider built against different pinned wRPC/WIT minors meeting across a lattice link) is **negotiated or rejected**, never silently coerced. These are gated by `@hobo/conformance/component-host` ([Plan 9](../verification.md#plan-09)).
4. **A thin SDK wraps the runtime.** The TS SDK ([Plan 2](../sdk-api.md#plan-02)) is ergonomic sugar over the generated WIT bindings — typed clients for the runtime's imported interfaces. It holds **no cloud logic**; all behavior lives behind the WIT ports in the runtime + providers, so the SDK stays small and every language with a Component-Model binding can host the same app. The SDK is itself **WIT-first**: a canonical `hobo:sdk` world `wit-bindgen`'d per language + a conformance-gated idiom layer — TS is the first idiom layer, not the source of truth ([ADR-0072](#adr-0072)).
5. **Deny-by-default is structural.** An imported interface with no link / no `.allow()` grant cannot be invoked — wRPC only routes linked interfaces and capability handles are deny-by-default ([ADR-0023](02-identity-security.md#adr-0023)/[Plan 21](../authoring-resources-wiring.md#plan-21)). Capability is granted by linking, not by ambient reachability.
6. **The contract is WIT/WASM, not a language.** The entire programmable surface — Bindles, services, providers — targets the Component Model and runs on wasmCloud; HoBo requires **WIT + WASM**, with **TypeScript as the first reference implementation, not a requirement**. Any language with a Component-Model toolchain authors against the same WIT worlds.

### Alternatives considered
- **Plain gRPC membrane (Nitric's choice).** Rejected: not WIT-native — needs a separate `.proto` IDL + codegen parallel to WIT, and a non-component wire that breaks the "one contract = the WIT world" model. wRPC gives the same RPC ergonomics generated straight from WIT.
- **Language-specific provider plugin SDK (Go/TS).** Rejected: forces a provider author into one language and a bespoke plugin API, and fragments the trust/conformance boundary. Requiring providers to code against the **WIT interface** makes the Component Model the single contract and lets the Forge generate providers.
- **A fat SDK with cloud logic.** Rejected: re-introduces per-cloud code on the client, breaking portability and the thin-client model; the SDK must be a typed shell over the runtime.

### Consequences
- **(+)** One contract everywhere: a building block is a WIT interface, a provider is a WIT component, the wire is wRPC generated from that WIT — local dev, cross-process, and lattice all use the same mechanism ([ADR-0031](#adr-0031)).
- **(+)** Provider breadth via the Component Model + Forge, with no language lock-in for provider authors; conformance ([Plan 9](../verification.md#plan-09)) is the single trust boundary.
- **(+)** Thin SDK → small client, easy multi-language hosting, and deny-by-default falls out of linking.
- **(−)** wRPC is younger than gRPC; HoBo pins/vendors its wRPC + WIT versions ([ADR-0031](#adr-0031)) and ships a conformance suite for the membrane.
- **(−)** "Everything is a WIT interface" demands disciplined interface design + versioning ([ADR-0024](07-portability-extensibility.md#adr-0024)); the building-block WIT set is now a maintained public contract.

## ADR-0072
**The SDK is WIT-first: a canonical `hobo:sdk` world built against per-language, with conformance-gated idiom layers.**

- **Origin:** [ADR-0069](#adr-0069) made the SDK "a thin wrapper over the generated WIT bindings" and named TS "the first reference implementation, not a requirement," and [ADR-0037](05-config-matching-environments.md#adr-0037) generates the *app developer's* bindings from WIT — but the **SDK's own surface** was never itself declared as WIT, and there was no explicit model for **producing a per-language SDK** (only "any Component-Model language can author"). The ask: provide the SDK *through WIT* — build/`wit-bindgen` each language SDK *against* WIT, with language-specific implementations that add idioms on top of the standard contract. Designed via brainstorming.

### Context
HoBo already treats WIT as the contract for providers ([ADR-0069](#adr-0069)), domain schema ([ADR-0051](03-data-plane.md#adr-0051)), and app-developer bindings ([ADR-0037](05-config-matching-environments.md#adr-0037)); typed clients are generated from WIT (jco guest-types, [Plan 20](../wasm-runtime-wit.md#plan-20)). What stayed implicit is the SDK *itself*: the runtime primitives (`workflow`/`step`/`actor`/`saga`/`agent`/`command`/`subscribe`) + capability clients (`kv`/`bucket`/`queue`/`data`/`search`/`notify`/…) were described as TS that's "sugar over generated bindings," but not pinned to a canonical WIT contract, and there was no story for how Rust/Go/Python SDKs come to exist beyond "author against the worlds." WIT cleanly expresses function signatures + records + imported interfaces — but **not** fluent builders, IfC collection-mode, decorators, or `.allow()` chaining, which are inherently language-side. The decision must split the WIT-expressible *contract* from the language-native *ergonomics* without letting the ergonomics drift into new semantics.

### Decision
1. **A canonical `hobo:sdk` world is the SDK contract.** Beyond the capability + data interfaces ([Plan 20](../wasm-runtime-wit.md#plan-20)) and domain records ([ADR-0051](03-data-plane.md#adr-0051)), the SDK's **runtime primitives are pinned as WIT** — `workflow`/`step`/`actor`/`saga`/`agent`/`command`/`subscribe` signatures (the `hobo:workflow`/`hobo:actor`/`hobo:saga`/`hobo:agent` interfaces, [Plan 20](../wasm-runtime-wit.md#plan-20)) aggregated into a **`hobo:sdk` world**. This world *is* the standard contract; its semantics are identical in every language.
2. **Each language SDK is built against WIT = generated bindings + a thin idiom layer.** A language SDK is produced by **`wit-bindgen`/jco against `hobo:sdk`** (the mechanical, low-level bindings) plus a **thin, language-native idiom layer** that adds ergonomics — TS builder chains + IfC collection ([Plan 21](../authoring-resources-wiring.md#plan-21)), Rust traits/builders, Python decorators/context-managers, Go option structs — and **nothing else**. The idiom layer lowers to the same generated bindings + emits the same **manifest IR** ([Plan 21](../authoring-resources-wiring.md#plan-21)); it carries **no cloud logic and no new semantics** ([ADR-0069](#adr-0069)'s thin-SDK rule, now made precise). The TS `@hobo/sdk` is therefore *the first idiom layer*, not a privileged source of truth.
3. **The WIT/idiom seam is the honest split.** WIT owns the **contract** (primitive + capability + data signatures, the `.allow()` verb set, the manifest-IR shape); the idiom layer owns the **ergonomics** (fluent surface, IfC collection-mode side-effects, decorators) that can't be expressed in WIT. This is why the IfC fluent surface ([Plan 21](../authoring-resources-wiring.md#plan-21)) and the WIT contract coexist — the fluent/IfC surface *is* the idiom layer, compiling down to the contract. **Hobo Code** ([ADR-0049](05-config-matching-environments.md#adr-0049)) and every language SDK are **front-ends over the one `hobo:sdk` contract**.
4. **The idiom layer is conformance-gated to *lowering-equivalence over a corpus* — not a proof of zero semantics.** A `@hobo/conformance/sdk` suite ([Plan 9](../verification.md#plan-09)) asserts that, for the conformance corpus, an idiom layer's inputs **lower to identical WIT calls + identical manifest IR** across languages (golden-IR equivalence + replay) — bounded by the corpus, like every conformance suite, *not* a universal proof. The behaviors an idiom layer **legitimately owns and that lowering-equivalence can't constrain** — **error mapping** (a Rust `result`-unwrap vs a TS throw vs a Go `(T,err)` are the same WIT `result<>` at the boundary but different in-language control flow), **async/cancellation**, and **IfC collection-mode side-effects/order** — are governed by a per-language **semantics annex** with **negative/error-path + cancellation test vectors**, not by the happy-path corpus. So an idiom layer with a missing/wrong error or cancellation mapping **fails the annex**, not the golden-IR check. The honest claim is *lowering-equivalence + an enumerated semantics annex*, not "no semantics."
5. **Idiom layers may be hand-authored *or* SWE-operator/Forge-generated — both conformance-gated.** A language SDK's idiom layer is normally hand-authored for genuine taste, but may also be **generated by the SWE operator** ([Plan 40](../operators-sre.md#plan-40)/[ADR-0054](06-ai-generation-operators.md#adr-0054)) via the Forge loop ([Plan 23](../forge-generated-stack.md#plan-23)) from `hobo:sdk`: `wit-bindgen` produces the bindings, the SWE agent writes the idiomatic wrapper, and `@hobo/conformance/sdk` gates it exactly as for a human author. There is no trusted-by-convention path — generated or hand-written, the parity gate is the same.
6. **Reverse compiling is a first-class direction.** **Forward** = `hobo:sdk` → bindings → idiom layer → a component imports the worlds. **Reverse** = a component/artifact → its **extracted WIT world** (what it actually imports/exports) → an idiom-layer skeleton (the SWE operator's starting point) **or** a parity/adoption report. The two directions share one contract.

### Alternatives considered
- **Hand-write each language SDK independently (the status quo implied by "any language can author").** Rejected: SDKs would drift in semantics, there is no parity guarantee, and every language re-implements behavior — re-introducing exactly the per-language fragmentation [ADR-0069](#adr-0069) rejected for providers.
- **Express the *entire* SDK (incl. fluent builders/IfC) in WIT.** Rejected: WIT can't express fluent builders, collection-mode side-effects, or decorators; forcing it yields an unidiomatic, lowest-common-denominator surface — the opposite of the goal. The idiom layer is the deliberate, conformance-bounded escape hatch for ergonomics.
- **Fully generate the idiom layer from WIT (no hand-authoring).** Rejected as the *only* mode: generated wrappers rarely feel native; kept as the SWE-operator/Forge *option* (decision 5), but human authorship for taste stays first-class.
- **Trust the idiom layer by convention (no conformance gate).** Rejected: without the golden-IR/replay gate an idiom layer could silently add behavior and break cross-language parity — the gate is what makes "WIT is the contract" true rather than aspirational.

### Consequences
- **(+)** "Provide the SDK through WIT" becomes literal: one `hobo:sdk` world is the contract, every language SDK is `wit-bindgen`'d against it + a thin idiom layer, and TS is just the first one — multi-language SDKs become a generation+conformance task, not N re-implementations.
- **(+)** Reuses the existing machinery — WIT worlds ([Plan 20](../wasm-runtime-wit.md#plan-20)), jco/`wit-bindgen` codegen ([ADR-0037](05-config-matching-environments.md#adr-0037)), the conformance trust boundary ([Plan 9](../verification.md#plan-09)), the Forge + SWE operator ([Plan 23](../forge-generated-stack.md#plan-23)/[ADR-0054](06-ai-generation-operators.md#adr-0054)) — net-new is the `hobo:sdk` world, a `@hobo/conformance/sdk` suite, and per-language idiom packages.
- **(+)** Sharpens [ADR-0069](#adr-0069)'s "thin SDK" into a testable definition: *thin = generated bindings + a semantics-free idiom layer*, enforced by conformance.
- **(−)** Pinning primitive signatures in `hobo:sdk` makes them a maintained public contract subject to WIT versioning ([ADR-0024](07-portability-extensibility.md#adr-0024)) — primitive evolution now costs a contract change, not just a TS refactor.
- **(−)** A `@hobo/conformance/sdk` golden-IR/replay suite per language is new test surface to build and keep current; an idiom layer that needs a genuinely new capability must add it to WIT first (by design, but a speed bump).
- **(−)** Idiom layers still need per-language toolchain maturity (`wit-bindgen` for Go/Python/Rust, jco for TS); where a toolchain lags, that language's SDK lags — bounded by the Component-Model ecosystem's pace.
