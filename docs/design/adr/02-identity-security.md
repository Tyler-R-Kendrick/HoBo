# Identity, security & secrets — consolidated decisions

> Consolidated ADR decisions for **identity, security & secrets**. Each section is one architecture decision; see [`README.md`](./README.md) for the full ADR index.

## ADR-0008
**Keyless agent identity (SVID/OIDC federation) + token broker.**

**Context:** static keys vs federated identity. **Decision:** agents get short-lived SVIDs; the broker exchanges them for resource-scoped provider tokens (OIDC federation preferred, OAuth-OBO for human delegation). **The broker is the top confused-deputy target, so scope is bound to an *attested* workload, not self-asserted claims:** before honoring a `{run-id, tenant, parent-principal, code-version}` request, Identity **verifies a workload attestation** — the wasm component-image digest + a **host-signed launch measurement** (Firecracker/host attestation, [ADR-0012](#adr-0012)) — so a generated/forked provider in tenant A's executor **cannot mint a tenant-B token by asserting B's claims** (the SVID binds to the measured workload, not to attacker-supplied attributes). **Identity genesis is specified:** the SVID-CA / OIDC issuer **signing key is generated in the target KMS *before* the seed Yard self-deploys**, with a **stable issuer URL from genesis** (providers federate against it once), so the discarded local seed never holds the durable root and self-deploy doesn't rotate the key out from under established provider trust. **Broker availability:** the broker is the sole credential path, so it runs **HA** with a **bounded credential-cache + renewal-grace window** — broker unavailability degrades gracefully (cached tokens renew within grace) instead of instantly bricking the data plane (a stated SPOF mitigation). **Consequences:** no static secrets, full credential audit; we must run an HA OIDC IdP + attestation verification + per-provider trust setup ([Plan 6](../ai-native-agent-auth.md#plan-06), [Plan 12](../security-networking.md#plan-12)).

## ADR-0009
**Capability Manifest capability/auth standard + Registry.**

**Decision:** providers publish machine-readable signs (`capabilities/auth/cost.json`) at a well-known path; the Registry indexes them. The **`capabilities` declaration is the statically-evaluable Capability Spec** ([ADR-0075](07-portability-extensibility.md#adr-0075)): it lists the exact WIT **`interface@semver` + stability tier (`stable`/`preview`/`experimental`/`deprecated`) + the `@hobo/conformance` suite version passed**, so the SDK/Matching can **statically determine availability** of a specific capability (e.g. the preview `wasi:websocket`) before deploy. **A provider/resource also declares an availability SLA** here (a sibling of `cost.json`'s cost facts) — the design-time input the architecture-availability model composes through the dependency graph ([ADR-0078](04-governance-verification.md#adr-0078)); a missing SLA is treated as "unrated," never assumed 100%. **Consequences:** agents self-discover + self-provision; static availability + preview-awareness fall out of the spec; we must define, version, and possibly standardize the schema ([Plan 6](../ai-native-agent-auth.md#plan-06)).

## ADR-0012
**Credential-scoped executors; isolation tier chosen per workload.**

**Decision:** IaC/build and untrusted/generated code run with **no ambient creds and a single scoped token**, in a sandbox whose **isolation tier is selected per workload/trust level** via Matching ([ADR-0033](05-config-matching-environments.md#adr-0033)) — gVisor or container tiers where the workload allows. **But the floor for Forge-generated / unattested code is a non-overridable invariant: it MUST run in a microVM (Firecracker).** This is *not* a Matching default a Resource Definition or `.with()` can downgrade — it's a **mandatory guardrail** ([ADR-0074](#adr-0074)) keyed on the attestation state (no valid workload attestation, [ADR-0008](#adr-0008) ⇒ microVM), so a mis-classification can't drop generated code into a weaker shared tier. The tier is optimized per workload *above* that floor, not below it. **Consequences:** strong isolation where it's needed without paying microVM cost for every workload, and generated/unattested code is contained by construction; the executor manages several isolation backends behind one contract ([Plan 4](../control-plane.md#plan-04), [Plan 12](../security-networking.md#plan-12)).

## ADR-0023
**Security posture commitments.**

### Context
The design (esp. [security-networking.md#plan-12](../security-networking.md#plan-12)) names the right threats — runaway/confused-deputy agents, Forge prompt-injection, supply-chain, cross-tenant access. The posture is **secure-by-default, zero-trust, defense-in-depth**: nothing is trusted by location or network position, every request authenticates and is authorized at each hop, and controls are layered so no single failure is fatal. For an agent-facing control plane that holds other people's cloud credentials and runs AI-generated code, the mitigations are **verifiable requirements**, not threat-model prose — backed by industry-standard scanning, monitoring, and best-practice adherence.

### Decision
HoBo commits the following security requirements (each is an `NFR`/`TR` with a verification method):
1. **Bound the static-key escape hatch** — any static API key carries a **maximum TTL (default ≤ 7 days)** and an enforced rotation schedule (expiry fails closed, does not hang), is **fully audited on every fetch** (not just grant/revoke), and is only reachable behind an explicit opt-in; federation is always preferred. (TR-051, NFR-005)
2. **Rate-limit & quota the Gateway/MCP surface** — per-principal (SVID/OIDC) and per-tenant limits with backpressure; exceeds return a typed throttle error. Protects against runaway agents and DoS. (TR-071, NFR-019)
3. **Forge generation is hardened against prompt injection** — source docs/OpenAPI fed to Forge are scanned/sanitized; the signed provenance includes a scrub report; conformance runs with **no egress** as a hard requirement. (TR-083)
4. **Confused-deputy default-deny** — before any agent obtains a scoped token, the policy engine checks `{principal, tenant, resource, action}`; cross-tenant issuance is denied unless explicitly delegated. (TR-053)
5. **Quantified audit retention** — `token.*`/`resource.*`/policy-decision streams are retained for a defined minimum and never compacted. (NFR-018, TR-052)
6. **Encryption everywhere it matters** — envelope encryption at rest for event streams across **all** runtimes (not just `runtime-local`); per-run payload decryption requires log-read **and** explicit authorization (run-owner / `decrypt:run`). (TR-111)
7. **Supply-chain specifics** — all published artifacts carry CycloneDX SBOMs; CI blocks publishing on CVSS ≥ 7.0 (with a documented waiver path); plugins signed with SLSA-style provenance. (TR-112)
8. **Redaction at capture, not export** — secret/PII values are scrubbed **before** a span/event is stored, so a value never enters the event log, OTel/OpenInference spans, error messages, or **training trajectories** ([Plan 21](../authoring-resources-wiring.md#plan-21)/[Plan 23](../forge-generated-stack.md#plan-23)). (TR-054, TR-111)
9. **Continuous scanning & monitoring** — supply-chain (SBOM/CVE), IaC/policy, and secret-leak scanners run in CI and continuously in production, wired to the audit/observability plane; controls map to recognized standards so adopters can assess them against their own frameworks.

Defense-in-depth: these layer — federation removes most secrets, the policy engine default-denies what remains, encryption protects data at rest, rate-limits cap blast radius, and continuous scanning catches regressions.

### Consequences
- **(+)** The security promises are verifiable gates, not prose; regulated adopters (BR-010) can assess them.
- **(−)** Some requirements (e.g. encryption on every runtime) depend on the runtime adapter's capabilities — opt-in-where-unsupported with the gap documented.

## ADR-0027
**Secretless-first configuration & secrets.**

### Context
HoBo issues keyless workload identities (SVIDs) and brokers short-lived provider tokens ([ADR-0008](#adr-0008)), and forbids static secrets at rest ([Plan 12](../security-networking.md#plan-12)). An **app** also needs a defined way to declare and load configuration and secrets — otherwise teams default to the antipattern: static secrets in env files/images/IaC, or worse, in the event log.

### Decision
HoBo defines a **secretless-first** config/secrets model ([Plan 21](../authoring-resources-wiring.md#plan-21)):
1. **References, not values, declared in a varlock-style typed schema.** `config()`/`secret()`/`env()` declarations resolve to **references**, resolved **per Camp at use-time** — a value never lives in the Bindle, the Camp config, or the event log. The declaration surface is a **typed, annotation/decorator-driven schema** in the spirit of varlock's `.env.schema`: each config/secret item declares its **type**, **required-ness**, **sensitivity** (secret vs non-secret config), and **source** (bound resource / provider-federated store / Camp value / static escape hatch). The schema is the committed, agent-readable *shape* (validated, coerced, and codegen'd to typed `ctx.config`, [ADR-0037](05-config-matching-environments.md#adr-0037)) while the *values* stay out of reach — going beyond varlock's vault-resolution by preferring no secret at all (the brokered path in (2)).
2. **Resolution ladder (secretless-first):** (a) **bound resource** → SVID-brokered short-lived token (no secret exists); (b) **secret with provider federation** → broker a scoped token and read from the provider's secret store at use-time; (c) **non-secret config** → typed value from the Camp's Deployment Set; (d) **static-secret escape hatch** → only where no federation exists, **bounded** by TTL + rotation + audit + opt-in ([ADR-0023](#adr-0023)).
3. **IaC state and provisioning outputs are a secret sink — closed explicitly.** IaC providers materialize secrets *into stack state* (a generated RDS master password, connection strings); those must not leak the way app config can't. So: **IaC state is encrypted at rest** (in the Yard's object store), and **secret-typed provisioning outputs are reference-ized — never captured as plaintext into `resource.Provisioned`** ([Plan 4](../control-plane.md#plan-04)): a connection string with an embedded credential lands as a brokered **reference** (ladder (a)/(b)), so the credential never enters the event log (upholding [ADR-0023](#adr-0023) §6/§8). Conformance asserts **no plaintext secret in IaC state or any event**.
4. **Provider resolution is a pluggable adapter, scoped to the Camp.** The default identity/secrets model (SVID/SVID-brokered tokens, OIDC federation) stays the default, but cloud-specific IAM, keys, and certs plug in through a **`secrets` port adapter / extension** per provider. The Bindle declares *what it needs*; each Camp supplies *where it comes from* (Key Vault vs Secrets Manager vs Vault) via the matching adapter — so swapping clouds, or overriding the default identity path with a cloud-native one, is a Camp + extension change, not an app edit ([ADR-0024](07-portability-extensibility.md#adr-0024)).
5. **Audit + redaction.** Resolution is `config.Resolved` (ref → source, not value); secret reads are `secret.Accessed` joined to `token.Used`; values are redacted from logs/OTel/OpenInference spans and per-run-encrypted if they must transit a step's I/O ([TR-111](../../requirements/requirements.md)).

### Consequences
- **(+)** The common case has **no secret to steal** (brokered tokens); secrets that do exist are referenced, short-lived, and audited (strengthens the zero-secret KPI, NFR-005), and config/secret sourcing is portable (declared in Bindle, sourced per Camp).
- **(−)** Requires a `secrets` port adapter per provider and a config-resolution path in the runtime; providers lacking federation fall back to the bounded static hatch.

## ADR-0038
**End-user / application auth.**

### Context
[Plan 6](../ai-native-agent-auth.md#plan-06) is a deep treatment of **agent/workload** auth (SVIDs, the token broker, Capability Manifest, OBO). An app deployed on HoBo also needs to authenticate its **end users** (humans), and `auth()` ([Plan 2](../sdk-api.md#plan-02) §53) covers sign-in, sessions, JWT/JWKS verification, IdP integration. HoBo has the substrate — it issues + verifies OIDC/JWTs via JWKS for agents, is secretless-first, has a policy plane + `.allow()` for authorization, and the event envelope's `actor: PrincipalRef` admits a `user`. End-user auth is assembled from that substrate without reinventing a full identity provider.

### Decision
1. **`auth()` is a federation + verification port (`hobo:auth`), not a homegrown IdP.** It verifies OIDC/JWT from any provider — Google / GitHub / Clerk / Auth0 / **custom JWT** (the shoo/Convex-`customJwt` pattern) — reusing HoBo's **OIDC + JWKS + secretless** machinery. The IdP is a **swappable adapter**, with a default set of **WorkOS · Auth0 · Supabase Auth · Microsoft Entra ID** (+ Google/GitHub/Clerk/customJwt) selected per Camp/Yard by Matching — only registered adapters are considered, and the set is non-limiting + Forge-extensible ([ADR-0073](07-portability-extensibility.md#adr-0073)). A **thin optional built-in** (passkey / email magic-link) covers zero-config dev and runs offline/air-gap ([ADR-0036](07-portability-extensibility.md#adr-0036)). HoBo does **not** build a full hosted IdP; identity is federation + verification, with cloud-native IdPs plugged in as adapters.
2. **Unified principal model.** An end-user is a **`PrincipalRef`** (the event `actor` already admits `user`), exposed as **`ctx.user`** alongside `ctx.identity` (SVID). **Authorization is the same policy plane** ([Plan 29](../contracts-policy-flags.md#plan-29)) **+ `.allow()`-style declarative rules** keyed on user claims (record-level), and **audit rides the existing event `actor`** ([Plan 11](../event-model.md#plan-11)). One identity/authz/audit path for users + agents + services; agent **OBO** ([Plan 6](../ai-native-agent-auth.md#plan-06)) carries the same user principal.
3. **Stateless JWKS verify per request + optional event-sourced sessions.** JWTs are verified via JWKS on each request (edge-friendly, matches `customJwt`); optional **`session.*`** records provide revocation / "sign out everywhere" + audit, and reactive queries ([Plan 32](../data-plane.md#plan-32)) re-evaluate on auth-state change.
4. **Surface:** client `useAuth()`/`signIn()`/`signOut()` (peer to `useQuery()`); server `ctx.user` (typed verified claims). **Events:** `user.Authenticated` · `session.Started/Refreshed/Revoked` (authz decisions ride `policy.Decided`).

### Consequences
- **(+)** HoBo apps get real end-user auth (sign-in/sessions/verification/IdP integration) reusing OIDC/JWKS, the policy plane, `.allow()`, and the event audit rather than new machinery; the unified `PrincipalRef` model keeps users, agents, and services on one authz + audit path, and OBO chains (user → agent → resource) are one identity story.
- **(−)** Federation-first means HoBo depends on external IdPs for production-grade user management (the thin built-in is dev-grade); orgs needing a fully self-contained IdP supply one through the IdP adapter.

## ADR-0070
**Dev-mode auth bypass via integrated contract testing.**

### Context
Local dev needs to skip real authentication — no IdP round-trips, works offline — without the dev code path **diverging** from production. The usual "set `AUTH_DISABLED=true`" flag runs untested logic in dev and silently differs from prod. HoBo already treats every boundary as a consumer-driven **contract** ([ADR-0015](04-governance-verification.md#adr-0015)) and authenticates principals via the `auth` port ([ADR-0008](#adr-0008)/[ADR-0038](#adr-0038)); the dev bypass should ride that machinery, not a bespoke flag.

### Decision
**Dev auth is a contract-satisfied fixture, not a disabled check.**
1. The `auth` port carries a **consumer-driven contract** describing the principal/claims the app expects (subject, roles, tenancy, scopes). It is the same contract the app declares for prod.
2. In **`hobo dev`**, the runtime satisfies that contract with a **contract-asserted dev principal** — a fixture identity generated to match the contract — instead of calling a real IdP. Auth still "runs"; it's just fulfilled by the contract fixture. The developer can override claims per-request/session (e.g. assume a role/tenant) within what the contract allows, making role/tenancy testing first-class.
3. **The same contract is enforced at `can-deploy`** ([ADR-0015](04-governance-verification.md#adr-0015)): a real IdP/Camp must satisfy the identical `auth` contract, so dev and prod are **contract-equivalent** — the bypass cannot drift from production semantics.
4. **Deny-by-default still holds** ([ADR-0069](01-architecture-core.md#adr-0069)): the dev principal only obtains the capabilities granted by `.allow()`/links. Bypassing *authentication* never bypasses *authorization*.

### Consequences
- **(+)** Fast, offline inner loop with **authorization faithful to prod** — the dev identity is defined by the same contract that gates deploys; role/claim/tenancy testing is built in, reusing the contract plane + `auth` port with no new mechanism.
- **(−)** **Scope of "cannot drift" is authorization, not authentication.** The `auth` contract constrains the **principal/claims shape** — it does *not* exercise JWKS verification, signature/`alg`/issuer/audience checks, expiry, or revocation, the parts that actually break in prod auth. So `hobo dev` proves authz, not the verification path; the **verification path is exercised against a fixture IdP at `can-deploy`/CI** (real JWKS validate, reject `alg:none`/wrong-issuer/expired — [Plan 9](../verification.md#plan-09) end-user-auth test), so a verification misconfig fails the gate even though `hobo dev` never authenticates.

## ADR-0074
**Organizational governance: RBAC + mandatory guardrails over HoBo's own control-plane surface.**

### Context
Enterprises must be able to **lock down** cloud capabilities, policy config, and resource access **not only on deployed infra (which HoBo governs) but on HoBo itself**: who may register a provider, change policy, set the Dispatcher objective, run the Forge, approve a deploy, read the audit log. HoBo's policy plane ([Plan 29](../contracts-policy-flags.md#plan-29)) is the universal decision engine: `request = { subject{kind,id,roles?,scopes?,delegatedBy?}, action, resource, phase, context } → { effect, obligations }`, deny-by-default, signed/versioned **policy packs**, every decision an event. It governs *deploy/runtime* actions and carries `subject.roles` + phases spanning `author→plan→apply→runtime`. Enterprise governance extends this to: (1) HoBo's **own control-plane operations** (register a provider, edit a Resource Definition, change a policy pack, set the Dispatcher objective, run the Forge, approve a Delta, read the audit log, manage roles) as **first-class policy subjects/resources** so they can be uniformly locked down; (2) **org-level RBAC** and a **mandatory hierarchical guardrail** model. This is platform governance (what enterprises require of any control plane), **not** an app-business/SaaS function — the [ADR-0064](08-scope-and-requirements.md#adr-0064) cut (no billing/monetization) is unaffected; the *hosted-operator-as-a-business* stays out, the governance *mechanism* comes in.

### Decision
1. **HoBo's own control-plane operations are first-class policy subjects/resources.** A `hobo:*` **admin action/resource taxonomy** makes every control-plane action a governed, deny-by-default, event-sourced policy decision — the same engine as deploys, at the `author/plan/apply/...` phases. "Govern the deployed cloud" and "govern HoBo" are the same policy plane over two resource namespaces. **The full action list + default role→action matrix is enumerated once, canonically, in [Plan 29](../contracts-policy-flags.md#control-plane-action-taxonomy-and-default-role-bindings)** (NIST RBAC / INCITS 359, least privilege + SoD, cloud-IAM `hobo:<resource>:<verb>` naming) — this ADR records the *decision*, not the table.
   - **Completeness is a hard gate, not a "should."** Deny-by-default only protects an *enumerated-but-unbound* `(role,action,resource)` — it does **not** catch a control-plane operation that was never given an action id (that code path has no check). So **every control-plane CLI/MCP verb must map to a `hobo:*` action id or the build fails** (`@hobo/conformance`), and the taxonomy explicitly includes the easily-missed high-privilege actions: **`derivative upgrade`** ([ADR-0057](07-portability-extensibility.md#adr-0057), swaps engines/patches), **`registry` bundle-import** ([ADR-0036](07-portability-extensibility.md#adr-0036), a supply-chain trust action), and **`relay` register/attach** ([Plan 12](../security-networking.md#plan-12)).
   - **Evaluation point + latency.** A control-plane decision is evaluated by the **in-Yard `policy-engine`** ([Plan 29](../contracts-policy-flags.md#plan-29)) — no management-plane round-trip on the hot path — with decisions async-shipped to the management-plane audit log; it carries a **control-plane-authz p99 NFR** ([ADR-0021](08-scope-and-requirements.md#adr-0021)) and a **bounded decision-cache TTL + revocation-propagation bound** so a revoked role stops acting promptly (the Crew operators are high-frequency principals — `operator:dispatch`/`forge:execute` in a repair loop must not pay an unbounded hop).
2. **Governance attaches to the existing Yard & Junction scopes — no new scope noun.** RBAC roles, SSO/SCIM org identity, and guardrail policy packs are carried by the **Yard** (single-provider estate) and the **Junction** (cross-cloud estate). Org-wide rules that span Junctions are **shared signed guardrail packs**, distributed by the **Junction's existing "federates signed policy packs"** mechanism ([ADR-0043](07-portability-extensibility.md#adr-0043)) — so a multi-Junction org stays consistent without a new top-level scope (honoring [ADR-0026](01-architecture-core.md#adr-0026)/[ADR-0028](05-config-matching-environments.md#adr-0028)'s resistance to extra scope nouns). "The org" is realized as the governance config a Yard/Junction carries, not a fifth deploy noun.
3. **RBAC binds principals to roles that populate `subject.roles`.** Built-in roles — **Org-Admin · Security/Policy-Admin · Platform-Engineer · Deployer · Operator-Supervisor · Auditor (read-only)** — plus **custom roles** composed from the action taxonomy (1). Roles bind to principals via **SSO/SCIM groups** through the existing `auth` port ([ADR-0038](#adr-0038)/[ADR-0073](07-portability-extensibility.md#adr-0073)); the resolved roles populate the policy `subject.roles` already in the model. **Operator Agents (the Crew) are principals under the same RBAC** ([Plan 40](../operators-sre.md#plan-40)) — an operator can never exceed its assigned role.
4. **Guardrails are per-rule `mandatory | default` (default mandatory), composed by a defined algebra.** **`mandatory`** = a **hard deny-ceiling** a lower scope may only **further restrict, never widen**; **`default`** = an **overridable recommendation**. The "can only restrict" property needs an explicit **composition algebra** (deny-by-default alone does *not* resolve two conflicting *explicit* rules): across all matching packs (Junction shared → Yard → Camp → Bindle), the decision is **deny-overrides** (any `mandatory` deny wins), **scope-monotonic** (a child pack's effective deny-set ⊇ its parent's — a child cannot *un-deny* a parent `mandatory`, only add denies), with a deterministic **most-restrictive-wins** tie-break — so two federated `mandatory` packs that disagree resolve to the union of their denies, identically on every Yard. Examples: providers only from an allow-list, prod only in approved regions, **no `.with()` escape hatches in prod**, **no `preview`/`experimental` interfaces in prod** ([ADR-0075](07-portability-extensibility.md#adr-0075)), no external-egress integration ports, agents capped at `$N`, air-gap can't be disabled, **2-person approval** for policy changes.
5. **Separation of duties via approval obligations; org-scoped, event-sourced audit.** Sensitive control-plane actions carry **approval obligations** ([Plan 29](../contracts-policy-flags.md#plan-29) — the durable obligation mechanism), with the org setting which role approves (e.g. a Platform-Engineer's policy change needs Security-Admin approval). Every control-plane decision is a `policy.Decided` event; role/guardrail/membership changes ride the existing policy-pack + `identity.*`/`token.*` families — **no new event families** — and the **OCSF audit export** ([ADR-0046](04-governance-verification.md#adr-0046)) feeds the org's GRC tooling. Audit is org-scoped and (per [ADR-0023](#adr-0023)) retained + never compacted.
6. **Honest enforceability boundary: mandatory guardrails bind *honest* Yards; cross-Yard assurance is by attestation, not control.** The Junction **federates** signed packs, it is **not a controller** ([ADR-0043](07-portability-extensibility.md#adr-0043)) and the `policy-engine` seam is itself swappable ([ADR-0057](07-portability-extensibility.md#adr-0057)) — so a **compromised or rogue Yard that forks/ignores its policy-engine cannot be *stopped* from above**. The guarantee is therefore stated honestly: a `mandatory` guardrail is enforced **within a Yard's own honest enforcement**, and **cross-Yard assurance is detective, by attestation** — each Yard ships **signed decision logs + a remote attestation of its policy-engine build** to the management-plane log, reconciled centrally so a Yard that drops/forks enforcement is **detected and flagged** (a `policy`-violation/attestation-gap signal), not silently trusted. Orgs needing prevention scope the estate to **attested Yards under a shared trust root**; a Yard outside that root is outside the guarantee, and `hobo doctor` says so.
7. **Genesis + break-glass are explicit.** The first principal is a bootstrap **Org-Admin** seeded at Yard genesis (`hobo yard up`, [Plan 4](../control-plane.md#plan-04)) via a one-time, audited **`identity.GenesisAdmin`** fact (immediately rotatable) — resolving the chicken-and-egg that `role:bind`'s no-self-escalation rule ([Plan 29](../contracts-policy-flags.md#plan-29)) otherwise creates. A **break-glass path** — an **offline-signed emergency override**, fully audited, distinct from the IdP-dependent normal path — recovers the estate when the IdP is down *and* a mis-authored `mandatory` guardrail would otherwise brick all changes (the waiver path needs a live approver; break-glass doesn't).

### Consequences
- **(+)** Orgs can lock down **HoBo itself**, not just the infra: who registers providers, changes policy, runs the Forge, sets cost routing, approves deploys, or reads audit — each a deny-by-default, role-gated, audited decision, with mandatory guardrails a lower scope can't widen, reusing the policy plane + signed packs + obligations, the `auth` port for SSO/SCIM, the Junction's pack federation, and the event log + OCSF export. **No new scope noun, no new event families.**
- **(−)** The `hobo:*` admin taxonomy is a new maintained surface (every control-plane action needs an action id + default role mapping) and must stay complete or an ungoverned action is a hole; mandatory guardrails can also over-restrict if mis-authored, with the gated **waiver** path ([Plan 29](../contracts-policy-flags.md#plan-29) `policy.WaiverRequested/Approved`) the audited escape valve.

## ADR-0079
**App multi-tenancy as a first-class capability: the app-tenant model, the tenancy-model spectrum & tenant lifecycle.**

Full surface in [Plan 50](../multi-tenant-apps.md#plan-50).

### Context
HoBo is a multi-tenant platform with a deep isolation model ([Plan 12](../security-networking.md#plan-12): data/compute/credential/network/wasm dimensions, per-tenant streams, a dedicated tier). A developer building a **SaaS on HoBo** also needs to make **their** application multi-tenant — isolate each customer's data, route per customer, configure/quota/meter per customer, honor per-customer residency, and run the customer's lifecycle (onboard → suspend → export → delete). End-user auth ([ADR-0038](#adr-0038)) gives `ctx.user` (a person) and the `auth` contract carries a latent **tenancy** claim; app multi-tenancy **exposes HoBo's own tenancy machinery one level up** — without conflating the two tenants, with **honest isolation guarantees per model**, and respecting the business-scope cut ([ADR-0064](08-scope-and-requirements.md#adr-0064)).

### Decision
1. **Two tenants, explicitly distinct, enforced at two distinct points.** The **platform tenant** (`EventEnvelope.tenant`, [Plan 12](../security-networking.md#plan-12)) is the HoBo account/org — HoBo's own hard isolation boundary, enforced at the **envelope level + store partitioning**. The **app tenant** (new) is the developer's customer, surfaced as **`ctx.tenant`**, enforced at the **`streamId` prefix + the projection auto-filter** *within* one platform tenant ([ADR-0080](#adr-0080)). They are **two axes, not one chain**: infra containment is `Bindle ⊂ Camp ⊂ Yard ⊂ Junction` ([ADR-0026](01-architecture-core.md#adr-0026)); **project** ([ADR-0077](04-governance-verification.md#adr-0077), a non-containment rollup dimension) and **app-tenant** are **application/organizational dimensions** — an app-tenant is a partition **within one app (Bindle)**, in a project, inside one platform tenant; it is **never a sixth infra scope noun**. An `AppTenant` is an event-sourced aggregate (`tenant:<id>`). **`ctx.tenant` has a defined source in every context:** the gateway resolves it from the verified end-user **tenancy claim** ([ADR-0038](#adr-0038)) and/or routing ([ADR-0035](07-portability-extensibility.md#adr-0035)) on the request path; an **async/system unit** (workflow/saga/cron/topic-subscriber) carries it **captured at enqueue time, propagated like `causationId`**; a **projection fold** derives it from the event's `streamId` prefix — and a unit with **no captured tenant fails closed**, never all-tenants ([ADR-0080](#adr-0080)).
2. **A declared tenancy-model spectrum, realized by Matching, with per-model guarantees.** The app declares a model — **pooled** (shared infra, stream-per-tenant, *logical* isolation; default), **siloed** (dedicated resources or a **Camp-per-tenant**, *physical* isolation; bounded to few large/regulated tenants), **bridge/tiered** (pooled long-tail + promote-to-silo), **region-pooled** (pooled in-region, siloed across regions — for per-tenant residency). The model (and a per-tenant override) is a **Matching decision** ([ADR-0033](05-config-matching-environments.md#adr-0033)) recorded in `match.Decided`, so **promotion pooled→siloed is a config change**, never an app rewrite (access is always via `ctx.tenant`). The data move is **not** the blue/green managed-store move ([ADR-0032](03-data-plane.md#adr-0032)) verbatim — re-keying one tenant's streams out of a shared append-only single-writer log needs a **defined zero-loss cutover**: `tenant.Suspended` freezes the tenant's aggregates → drain to a quiescent `seq` → export → import into the silo → **fence the old streams** → `tenant.Resumed`; a conformance test asserts **zero lost/duplicated events** (source quiescent `seq` == silo head). Only that one tenant is briefly write-frozen.
3. **Tenant lifecycle is first-class + event-sourced** (`tenant.Provisioned/Suspended/Resumed/Offboarded/Exported/Erased`, [Plan 11](../event-model.md#plan-11)) — explicitly the **app's** customer tenant (the platform tenant has no lifecycle). **Erase = per-tenant crypto-shred via a key *hierarchy*, reconciled with [ADR-0051](03-data-plane.md#adr-0051):** since ADR-0051's forgetting key is per-subject and forbids invariants over shreddable fields, a tenant is **not** wholesale-encrypted under one key; instead a **tenant key envelops the tenant's per-subject keys**, so erasing the tenant destroys the tenant key → all wrapped subject keys become unrecoverable in one act (≡ batch-destroy). **Routing/identity fields (the `streamId` prefix, ids, invariant keys) stay cleartext**; only PII is encrypted — so **aggregate invariants survive** the erase. Whole-tenant right-to-erasure **without rewriting the forward-only log** ([ADR-0060](04-governance-verification.md#adr-0060)); **export** is a portable dump of the tenant's streams (no lock-in, [ADR-0024](07-portability-extensibility.md#adr-0024)).
4. **Per-tenant cross-cutting reuses existing planes** — routing ([ADR-0035](07-portability-extensibility.md#adr-0035)), config/flags ([ADR-0044](04-governance-verification.md#adr-0044) targeting on `ctx.tenant`), quotas + noisy-neighbor control + per-tenant **showback** ([ADR-0039](04-governance-verification.md#adr-0039)), residency ([ADR-0040](05-config-matching-environments.md#adr-0040)/[ADR-0060](04-governance-verification.md#adr-0060)), and per-tenant observability/status ([Plan 49](../dashboards-status-availability.md#plan-49)) — almost no new runtime.
5. **Scope boundary (honors [ADR-0064](08-scope-and-requirements.md#adr-0064)):** isolation / routing / config / quota / **showback** / residency / lifecycle / observability are **in**; **billing the app's tenants** (per-tenant invoicing / subscriptions / plans-as-a-product) is **out** — HoBo gives the developer the showback + quota inputs to run *their own* billing, not a billing engine.

### Consequences
- **(+)** A developer builds a real multi-tenant SaaS on HoBo with first-class primitives — `ctx.tenant`, a declared model, per-tenant routing/config/quota/residency/lifecycle/observability — reusing the planes HoBo already has; pooled→siloed is a config+migration, so a tenant can be upgraded to isolation without an app rewrite, and whole-tenant erasure (crypto-shred) + export give clean GDPR/offboarding + no-lock-in stories.
- **(−)** Two "tenant" notions are an inherent confusion risk (mitigated by the strict naming `ctx.tenant` = app-tenant vs `EventEnvelope.tenant` = platform), and siloed/Camp-per-tenant is bounded (doesn't scale to many tenants) with per-tenant residency forcing region-pooling/silo.

## ADR-0080
**Tenant isolation by construction + the cross-tenant-leak conformance gate.**

The load-bearing safety half of app multi-tenancy ([ADR-0079](#adr-0079)) — the cross-tenant data leak is the #1 multi-tenant failure. Full surface in [Plan 50 §C](../multi-tenant-apps.md#plan-50).

### Context
In a pooled app-tenancy model the classic catastrophe is a cross-tenant leak — a query that forgot its `WHERE tenant_id`, a projection that folded the wrong stream, a subscription that pushed another tenant's data. "Be careful" is not a guarantee. HoBo can do better because data access already flows through platform-owned seams (the event log + stream keys, the projection/`repo`/`view` boundary, `.allow()` + the policy plane, [Plan 32](../data-plane.md#plan-32)/[Plan 29](../contracts-policy-flags.md#plan-29)).

### Decision
1. **The app-tenant is a `streamId` *prefix*, not a change to the aggregate model.** `streamId` is already the aggregate key (one aggregate = one stream, [ADR-0053](03-data-plane.md#adr-0053)); for a multi-tenant app the grammar is **`<app-tenant>/<aggregateType>:<id>`** (e.g. `acme/order:01H…`) — the app-tenant **partitions the keyspace**, distinct from the platform `EventEnvelope.tenant`. **Per-aggregate optimistic `seq` semantics are unchanged**; tenancy multiplies which streams exist, not how one stream serializes. A fold/command is therefore *structurally* tenant-scoped — a key with another tenant's prefix is one you weren't given.
2. **The projection/`repo`/`view` filter is platform-owned, deny-by-default, and composes with platform-tenant scoping.** Tenant scoping is applied by HoBo at the data-access boundary ([Plan 32](../data-plane.md#plan-32)), **not** a developer-written predicate; a tenant-scoped read with **no resolved `ctx.tenant` fails closed** — never all tenants. **Two enforcement points, both applied:** platform-tenant on `EventEnvelope.tenant` (envelope + store partition, [Plan 12](../security-networking.md#plan-12)); app-tenant on the `streamId` prefix + `ctx.tenant`. They **compose** — an app-tenant leak can neither cross nor be *masked* by platform-tenant scoping (a conformance assertion). **`ctx.tenant` provenance is defined for async/system contexts** (workflow/saga/cron/topic-subscriber capture it at enqueue, propagated like `causationId`; a projection fold derives it from the `streamId` prefix), so "fail closed on no tenant" holds for background work without defaulting to all-tenants.
3. **Cross-tenant access is an explicit multi-tenant *scope token*, a distinct code path from "unresolved."** App-developer staff who legitimately span tenants act as a **cross-tenant-admin** role ([ADR-0074](#adr-0074)/[Plan 29](../contracts-policy-flags.md#plan-29)) carrying an explicit **`ctx.tenants` set (or `*`) granted by a `policy.Decided`** — **not** an unresolved `ctx.tenant` (which fails closed). Keeping them separate code paths ensures a dropped-tenant bug reads as deny, never as admin. Every cross-tenant read/write is gated + audited; an ordinary `ctx.user` reaches **only** its own tenant.
4. **`.raw()` is *denied by default* on a pooled store, not merely flagged.** On a pooled (shared) store the raw escape hatch ([Plan 32](../data-plane.md#plan-32)) bypasses the auto-filter and is an *active cross-tenant read*, so flag-as-debt would be detective, not preventive — silently downgrading "by construction." Pooled `.raw()` is therefore **denied** unless the developer supplies an explicit hand-scoped tenant predicate the gate verifies (or runs as cross-tenant-admin); it is free on a **siloed** store (the silo is the boundary). Either way surfaced as isolation debt alongside the portability-debt flag ([ADR-0024](07-portability-extensibility.md#adr-0024)).
5. **A cross-tenant-leak conformance gate with a runnable oracle.** Seed tenants **A** and **B** with distinct **sentinel** records; under an ordinary `ctx.user` of A, every surface (command/query/**subscription**/**search**/projection) querying B's sentinel **denies/returns-empty** *and* (positive control) **A's own sentinel is present** — so an all-deny-because-broken impl can't pass; the no-tenant case fails closed. **Search is covered explicitly** (vector/graph search is a `step` with a developer predicate, not the auto-filter): the **search index is tenant-partitioned** (per-tenant index/namespace or a non-bypassable platform-injected filter at the `hobo:search` port). **Subscriptions** carry `ctx.tenant` + tenant-lifecycle state in their **read-set**, so `tenant.Suspended`/`Erased`/claim-change **re-scope or close** the live subscription (no stale cross-tenant push). A **siloed** model additionally asserts **physical** separation. **Honest guarantee per model:** pooled = **logical** isolation; siloed = **physical**. The docs never claim pooled gives physical isolation.

### Consequences
- **(+)** The cross-tenant leak is structurally prevented (stream-key scoping + platform-owned deny-by-default filter), not left to developer care; the conformance gate proves it, and the honest pooled-vs-siloed guarantee lets a buyer choose isolation knowingly (siloed/regulated tenants get a provable physical boundary).
- **(−)** App-tenant scoping must reach **every** seam — request, async/system context, projection fold, search step, and live subscription re-eval — or it leaks; the breadth is real surface to build and conformance-cover.
