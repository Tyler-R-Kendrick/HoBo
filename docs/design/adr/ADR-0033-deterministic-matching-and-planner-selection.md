# ADR-0033 — Deterministic Matching & Planner selection (+ default objective)

- **Status:** Accepted
- **Date:** 2026-06-22
- **Deciders:** Engineering, Product
- **Related:** [Plan 25 — Resource Definitions & Matching](../25-resource-definitions-matching.md) · [Plan 3 — Providers/IaC](../03-providers-iac.md) (the Planner; `require`/`prefer`) · [Plan 16 — Cost/FinOps](../16-cost-finops.md) (objective signal) · [Plan 11 — Event model](../11-event-model.md) (`match.Decided`) · [Plan 9 — Verification](../09-verification-open-questions.md) (Q3; determinism test) · [Plan 33 — Forge generation](../33-forge-generation-pipeline.md) (advisory candidate-def generation) · [ADR-0024](./ADR-0024-portability-conformance-guarantee.md) · resolves open **ADR-P4** (default Planner objective) in [18-adr-log](../18-adr-log.md) · [competitors/gap-analysis](../../../competitors/gap-analysis.md) (#3 matching credibility)
- **Origin:** the gap analysis asked, of HoBo's Humanitec-parity Matching, *"which algorithm — rules, constraint solver, or LLM — and is it deterministic enough to trust in prod?"* ([Q3](../09-verification-open-questions.md)). Designed via brainstorming + grill-with-docs.

## Context
[Plan 25](../25-resource-definitions-matching.md) introduced **Resource Definitions** + **specificity-scored Matching** and the auditable **`match.Decided`** event; [Plan 3](../03-providers-iac.md) made the **Planner a pure function** with capability negotiation (`require` hard / `prefer` soft), region/colocation, and an *optional* cost-shaping step. But three things were left open and they are what make Matching trustworthy in prod: (1) the **algorithm class** — pure rules vs a constraint solver vs LLM-assisted, and whether selection is **deterministic/replayable**; (2) the **default objective** when several candidates fully satisfy (Plan 3 §122 iteration hook; the open **ADR-P4**); (3) **tie behaviour** when definitions are equally specific. Humanitec's selection is specificity-based but **opaque**; HoBo's differentiator is an auditable, replayable decision — which only holds if selection is deterministic.

## Decision
1. **Selection on the deploy path is deterministic rules — a pure function.** Selection is a pure function of `(catalog snapshot, deploy context, objective setting)` — **no clock, RNG, network, or model** — so it is unit-testable without a cloud and **identical on replay** (the property [Plan 9](../09-verification-open-questions.md) already asserts of the Planner). **AI and cost/constraint *solvers* are advisory only, off the deploy path:** `hobo plan` may *surface* a cheaper alternative; the **Forge** may *generate* candidate definitions ([Plan 33](../33-forge-generation-pipeline.md)); an LLM may *suggest* definitions at authoring time. None select at deploy time, so replay + `match.Decided` stay honest.
2. **The pipeline is gather → filter → rank → record:**
   - **Filter** to candidates whose criteria match the context **and** whose provider satisfies the resource's hard **`require`** capabilities (`Capability.satisfies` = `full` → accept; `prefer` may degrade with a `PlanWarning`; `require` miss → reject). If none satisfy `require` → **`deployment.PlanRejected`** with a precise, agent-correctable reason.
   - **Rank lexicographically:** (a) **specificity score** ([Plan 25](../25-resource-definitions-matching.md)) → (b) **explicit platform priority** (a new optional `priority` field on a definition, for deliberate override) → (c) the **default objective** (soft) → (d) a **stable deterministic tiebreak** (definition id, lexicographic).
3. **The default objective is configurable, defaulting to min-cost within constraints** (resolves **ADR-P4**). The objective is a Yard/Camp setting — `cost` | `latency` | `single-provider` | `carbon` — defaulting to **lowest cost subject to satisfying `require`/`prefer`/region/colocation**. The region/colocation step ([Plan 3](../03-providers-iac.md) §4) already minimizes cross-provider egress, so cost is the natural remaining optimizer; the chosen objective is recorded in `match.Decided`/`deployment.Planned`.
4. **A true tie gets a stable tiebreak + a warning, never a block.** When candidates are equal on specificity, priority, and objective, break by the stable key (definition id) so the result is always deterministic + replay-stable, **and** emit a `PlanWarning` + flag the tie in `match.Decided` so a platform engineer can add an explicit `priority` to disambiguate.
5. **Enrich `match.Decided`; add no new event types.** Its payload carries the winner, the full ranking, the rejected candidates (with reasons), the objective used, and the tie flag.

## Alternatives considered
- **Constraint solver (e.g. ILP) on the deploy path.** Rejected: solver outputs can be unstable across versions, are harder to explain in `match.Decided`, and risk non-determinism on replay unless heavily pinned — overkill for the indie/agent ICP. (Cost optimization survives as the *soft objective* and as an *advisory* `hobo plan` suggestion.)
- **LLM-assisted selection on the deploy path.** Rejected: non-deterministic → breaks replay and makes `match.Decided` unauditable; unacceptable for prod infra selection. Retained only as an authoring-time *suggester*.
- **Error out on a true tie (require disambiguation).** Rejected as the default: blocks deploys/iteration on an ambiguous catalog (bad for agents + ephemeral previews); the stable-tiebreak-plus-warning keeps deploys moving while surfacing the ambiguity. (A Yard may still opt into strict mode via policy, [Plan 30](../30-policy-plane.md).)
- **Most-recently-updated wins.** Rejected: not replay-stable (timestamp isn't a clean deploy input) and changes silently as the catalog is edited.
- **A fixed, non-configurable objective.** Rejected: teams legitimately want latency- or single-cloud-first; configurability with a sane default serves both.

## Consequences
- **(+)** Matching becomes **demonstrably deterministic + auditable** — "why did this resource land on this infra?" is answerable and reproducible, closing the credibility gap vs Humanitec's opaque selection.
- **(+)** Reuses the **pure Planner** ([Plan 3](../03-providers-iac.md)), specificity scoring + `match.Decided` ([Plan 25](../25-resource-definitions-matching.md)/[Plan 11](../11-event-model.md)), and cost signals ([Plan 16](../16-cost-finops.md)); little new machinery (an optional `priority` field + an enriched event payload).
- **(+)** AI keeps adding value (Forge-generated + LLM-suggested definitions) **without** compromising determinism, because it sits off the deploy path.
- **(−)** Pure rules can pick a sub-optimal option a full solver might improve on; mitigated by the soft cost objective + the advisory `hobo plan` suggestion + explicit `priority`.
- **(−)** Platform engineers must occasionally add a `priority` to silence a tie warning — a small, explicit authoring cost in exchange for predictability.
