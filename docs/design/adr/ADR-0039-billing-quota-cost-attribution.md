# ADR-0039 — Billing, quota & cost attribution (hosted Yard)

- **Status:** Accepted
- **Date:** 2026-06-22
- **Deciders:** Engineering, Product, Business
- **Related:** [ADR-0020 — Monetization model](./ADR-0020-monetization-model.md) (showback OSS / chargeback hosted) · [Plan 16 — Cost/FinOps](../16-cost-finops.md) (budgets, spend-caps) · [Plan 30 — Policy plane](../30-policy-plane.md) (quota gates + obligations) · [Plan 5 — Reliability/HA](../05-reliability-ha.md) (circuit-breaker pattern) · [Plan 6](../06-ai-native-agent-auth.md) (agent spend-caps) · [Plan 11 — Event model](../11-event-model.md) (projections, events) · [Plan 12](../12-security-multitenancy.md) (per-tenant isolation) · [competitors/gap-analysis](../../../competitors/gap-analysis.md) (#18) · [BRD §Business model](../../requirements/BRD.md)
- **Origin:** open question #18 — "billing, quota enforcement & cost attribution for the hosted Yard (go/no-go for the SaaS)." ADR-0020 stated the *model* (showback OSS, chargeback hosted); this ADR makes the *mechanism* concrete. Designed via brainstorming + grill-with-docs.

## Context
[ADR-0020](./ADR-0020-monetization-model.md) committed to a hosted-Yard SaaS as the primary revenue line, with **showback in the OSS core and chargeback/billing in the hosted tier**, and two hard constraints: **no cloud-spend markup** and **never gate portability behind a paid tier**. [Plan 16](../16-cost-finops.md) already has plan-time cost estimation, soft/hard **budgets**, **agent spend-caps**, and a **provider-resilience circuit-breaker** — but it had no **metering** model (what's billable + how it's measured), no **quota** enforcement beyond budget alerts, no **runaway-spend** safeguard, and no **cost-attribution/chargeback** pipeline. Without these the SaaS can't bill, can't protect itself or tenants from runaway cost, and can't attribute spend — the #18 go/no-go.

## Decision
1. **Metering is an event-sourced projection.** A **`MeteringView`** folds **billable counters** from the event log HoBo already keeps — `deployment.*`, `run.*`, `resource.*`, `forge.*`, `token.*`, and egress ([Plan 13](../13-networking-connectivity.md)/[Plan 16](../16-cost-finops.md)) — across a small dimension set: **control-plane operations, runtime-compute-seconds, storage-GB, egress-GB, Forge-runs, and seats**. No new instrumentation; the view is auditable, replayable, and rebuildable from zero like every projection ([Plan 11](../11-event-model.md)), so **every bill traces to facts** ("why this charge").
2. **Quotas + a runaway-spend circuit-breaker run through the policy plane.** A metered counter crossing a plan-tier threshold produces a **`policy.Decided`** ([Plan 30](../30-policy-plane.md)): **soft** → warn/alert obligation; **hard** → **deny at the gate** (block the spend-incurring action — deploy / agent provisioning / Forge run). Excess **spend *velocity*** trips a **durable spend circuit-breaker** — a saga obligation reusing the breaker pattern from [Plan 5](../05-reliability-ha.md) — that **halts spend-incurring actions until acknowledged/reset**. The existing **agent spend-caps** ([Plan 6](../06-ai-native-agent-auth.md)/[Plan 16](../16-cost-finops.md)) generalize to **tenant / Camp / plan** quotas.
3. **OSS↔hosted boundary.** **Metering + quota + showback** (cost attributed by the dimensions already in the event envelope — **tenant → Camp → Bindle → run/agent/team**) are **OSS core**, self-hostable. **Chargeback** — moving money (metered billing / invoicing, e.g. Stripe) — is an adapter behind a **`billing` port** the hosted Yard wires. This realizes [ADR-0020](./ADR-0020-monetization-model.md) ("showback OSS, chargeback hosted") and the **never-gate-portability** rule: self-host gets full metering/quota/showback; only money-movement is hosted (self-host runs a no-op / showback-only billing provider).
4. **Events:** `spend.CircuitTripped` · `spend.CircuitReset` · `meter.PeriodClosed` (an immutable billing-period snapshot of the `MeteringView` — the invoice basis). **Quota decisions ride the existing `policy.Decided`**; metering itself is a projection (no per-usage events); `invoice.*` lives in the hosted `billing` adapter, not the core.

## Alternatives considered
- **A separate metering pipeline (independent instrumentation).** Rejected: duplicates what the log records and risks drift between "what happened" and "what was billed"; the projection is the source-of-truth-consistent answer.
- **Delegate to provider billing (cloud-spend passthrough/markup).** Rejected: covers only infra passthrough, not HoBo's SaaS value (control plane, hosted Forge, seats), and ADR-0020 explicitly rejects cloud-spend markup.
- **A bespoke quota subsystem** separate from the policy plane. Rejected: duplicates the decision model + gates and splits "why was this blocked" across two systems.
- **Soft alerts only (no hard enforcement).** Rejected: no protection against runaway spend (a looping agent racking up cost) — the exact safeguard #18 requires.
- **Billing baked into the core.** Rejected: would make the OSS core depend on a billing provider / gate behind paid — violates ADR-0020 and the portability thesis.

## Consequences
- **(+)** Closes #18: the hosted Yard can meter, quota, protect against runaway spend, and attribute/charge — all from the existing log + policy plane, with auditable bills.
- **(+)** Reuses the event log/projection model ([Plan 11](../11-event-model.md)), the policy plane + obligations ([Plan 30](../30-policy-plane.md)), the circuit-breaker pattern ([Plan 5](../05-reliability-ha.md)), and agent spend-caps ([Plan 6](../06-ai-native-agent-auth.md)) — little new machinery (a projection, a `billing` port, three events).
- **(+)** Honors ADR-0020 + portability: self-host gets metering/quota/showback; only chargeback is hosted, behind a port.
- **(−)** Metering fidelity depends on the billable-dimension model; mapping raw events → fair, intuitive counters (and pricing them) is ongoing product work — exact tiers/figures stay a BRD TBD.
- **(−)** A spend circuit-breaker that halts actions is a sharp safeguard: tuning its velocity thresholds to avoid false trips (vs missing real runaways) is an iteration hook.
