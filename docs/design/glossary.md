# HoBo Glossary

This is the canonical glossary for HoBo design terms. `docs:design-lint` treats this table as the single source of truth for canonical term definitions.

| Term | Definition |
|---|---|
| Agent-to-human handoff | A typed escalation package over `hobo:notify` that asks a human to apply a fix, re-bless output, or abort work before a deadline. |
| Aggregate | The write-model consistency boundary, realized as an actor over the event log. |
| Binding membrane | The only supported binding delivery path: WIT import → lattice/host **link** → provider export → generated `ctx.bindings.*` / capability call ([ADR-0141](./adr/02-identity-security.md#adr-0141)). Secret-shaped process env is not a binding document. |
| Bindle | App-level topology and bindings, provider-agnostic, deployed into one or more Camps. |
| App Kit (Kit) | Bindle-declared application surface kinds that host entrypoints or interactive runtime behavior: `api`, `web`, `service`, `ui`, `websocket`, `job`, `wasm-component`. Prefer **Kit** / **App Kit** over calling these "membrane types" at the Bindle authoring layer. Session Replay is default-supplied on every Kit ([ADR-0137](./adr/03-data-plane.md#adr-0137)). Distinct from the low-level WIT/WASM **membrane** (wRPC portability boundary, [ADR-0069](./adr/01-architecture-core.md#adr-0069)). |
| Infra Kit | Bindle-declared infrastructure/port resources that are not entrypoint hosts (`kv`, `bucket`, `queue`, `topic`, `secret`, `data`, …). No default Session Replay unless explicitly annotated. |
| Broker Catalog Snapshot | Versioned provider/catalog evidence set consumed by the Meta-cloud Broker when validating a Contract Manifest. |
| Broker Environment | Optional additional approved provider/catalog ceiling applied **in addition to** the active Rail. Not a setup path — Station + Rail are required. See Station / Rail rows. |
| Camp | Deployment target for a Bindle placement (for example `prod` or a Yard-attached name such as `prod-aws`). **Provider-neutral until attached to a Yard**; the **Yard owns provider selection**, and a Camp **infers** provider/runtime/IaC from its attached Yard (or from Yard placement policy when inferred). Camps do not own Bindles. A Camp can **move between Yards** via **Trails** (cross-cloud/cross-Yard re-home recipes). See [yard-first-placement ADR](./adr/yard-first-placement.md). |
| Camp tier | Which standard segment a Camp is — `edge` (internet-facing ingress), `app` (business logic, no inbound internet path), `data` (persistence and state), plus opt-in `untrusted` (risky-input / unattested-code workloads) and `ops` (operational surfaces off the workload path). Sourced from [Azure WAF SE:04 segmentation](https://learn.microsoft.com/en-us/azure/well-architected/security/segmentation) and [AWS WAF SEC05-BP01 network layers](https://docs.aws.amazon.com/wellarchitected/latest/security-pillar/sec_network_protection_create_layers.html), which group components by function, data sensitivity, and behaviour. A tier is a **Camp**, not a label on one, because a Camp is the placement target controls attach to. `DEFAULT_CAMP_TIERS` is the three-tier shape both frameworks reach for first; SE:04's over-segmentation risk is why the other two are opt-in. Tier is **orthogonal to environment** and is **stated, never inferred from a Camp's name**. Tiers buy *containment*, never trust — every hop still authenticates ([ADR-0023](./adr/02-identity-security.md#adr-0023)) — and availability clustering is a Yard/region concern (AWS REL10 fault isolation), deliberately not a tier. `CAMP_TIER_EGRESS` declares which tiers may reach which; it is a declared shape with tests, **not yet enforced** by any provider adapter. |
| Capability Manifest | Machine-readable provider manifest describing capabilities, auth flows, cost facts, and how an agent obtains scoped tokens. |
| Capability provider | A Provider acting as a wasm capability adapter that implements a WIT interface. |
| Component | WASM/WASI component, the default deployable unit for a HoBo service, with an OCI-container fallback. Two other senses are qualified, never bare: C4 "components" are control-plane *modules* ([architecture taxonomy](./architecture.md#plan-10)), and Dapr "components" are adapter-local to `runtime-dapr`. |
| Trait | Declaratively attached operational behavior that changes *how* a resource/component runs, never *what* it is; canonical attach point is the manifest `annotations` block. Kinds: author-inferred (`.allow()`), author-explicit (portable annotations, Camp/Yard `.with(...)`), platform-applied (Workload Profiles, policy packs, defaults, Trails recipes), distribution (Resource/App Packs) ([ADR-0145](./adr/01-architecture-core.md#adr-0145)). |
| Boundary | Overloaded on purpose; always qualify. The canonical disambiguation table (BoundaryContract, membrane, PACT integration, parse, consistency, capability, Station isolation, tenancy, trust/air-gap) lives in the [architecture taxonomy](./architecture.md#plan-10). |
| Component host | Camp capability that executes components; Wasmtime locally and wasm-in-container as the v1 production floor. |
| Conductor | Product branding for the HoBo Broker on user-facing surfaces; technical docs, code, and wire contracts keep the term "broker" ([hobo-broker.md](./hobo-broker.md)). The Conductor is a **pure runtime**: it mounts a Station client + active Rail(s), runs resolve/scale/deliver, and emits receipts that pin `stationId` + `railHash` + `catalogHash` + `policyHash`. It owns no durable Connections or policy packs. |
| Config and secrets | Secretless-first app configuration resolved through `ctx.config` to Camp-specific references rather than plaintext values. |
| Extension point | Named, versioned seam (`hobo.<name>/v<major>`) where a package other than the seam's owner supplies behavior; the normative catalog (one row per mechanism: owner, registration semantics, discovery, gate) is [extension-points.md](./extension-points.md) ([ADR-0156](./adr/07-portability-extensibility.md#adr-0156)). |
| Config capability | Linked `wasi:config/store` provider for non-secret deploy variance (value-ref + sensitivity); import-optional; not a residual vault ([ADR-0142](./adr/02-identity-security.md#adr-0142)). |
| Config sensitivity | Classification `public` \| `internal` \| `sensitive` controlling materialization; sensitive fields use delegated refs only ([ADR-0142](./adr/02-identity-security.md#adr-0142)). |
| Residual secrets | Optional classical secret stores (`hobo:secrets`, SecretsPort, optional OpenBao adapter) after federation/`fromBinding`; never default ambient env ([ADR-0027](./adr/02-identity-security.md#adr-0027), [ADR-0142](./adr/02-identity-security.md#adr-0142)). |
| Connector Registry | Broker-maintained, event-sourced registry of connector configurations (HoBo GitHub App, Pulumi, Azure, Vercel, Cloudflare, custom) whose `credentialRef` entries point into the token broker; required connector kinds gate broker resolutions ([hobo-broker.md](./hobo-broker.md)). |
| Contract | Typed expectation on a graph edge, declared, inferred, observed, or promoted, and checked by the compatibility gate. |
| Contract Manifest | Application contract artifact presented to the Meta-cloud Broker; names requested capabilities, constraints, and declared application facts for broker validation. |
| Jurisdiction | Legal district a region sits in (`eu`/`eea`/`us`/`us-gov`/`uk`/…): typed catalog with legal-basis citations plus a normalized region→jurisdiction mapping; regions are provider facts, jurisdictions are legal facts, the join is the platform's ([ADR-0146](./adr/02-identity-security.md#adr-0146)). |
| Residency constraint | Per-tenant/per-classification rule over allowed/denied jurisdictions, evaluated by the pure fail-closed `evaluateResidency` (unmapped region = conflict); feeds `can-trail`/`can-migrate` conflict inputs and the Gatekeeper `residency` gate ([ADR-0146](./adr/02-identity-security.md#adr-0146)). |
| Data classification | Typed label `public`\|`internal`\|`pii`\|`phi`\|`pci`\|`secret` on resources/WIT-record fields; the input residency and governance obligations key on ([Plan 46](./governance-planes.md), [ADR-0146](./adr/02-identity-security.md#adr-0146)). |
| Control→evidence pack | Declarative join from a compliance framework's controls to HoBo evidence refs (event streams, gates, artifacts, retention) with honest per-control status and computable coverage; OSCAL-aligned vocabulary, never OSCAL-dependent ([ADR-0146](./adr/02-identity-security.md#adr-0146), [ADR-0060](./adr/02-identity-security.md#adr-0060)). |
| BoundaryContract | The typed contract for one integration edge (13 edge kinds: http, event, message, resource-binding, capability-scope, agent-tool, provider-interface, …): required shape, content hash, optional EffectSpec + ResilienceProfile; `hobo.contract-ir/v1`, parse-don't-validate, consumed by can-deploy/Gatekeeper (ADR-0136). |
| EffectSpec | Optional Verse-inspired side-effect annotation on a BoundaryContract (purity lattice + capability + domain I/O effects); first-class Contract IR field (ADR-0136). |
| EffectManifest | Versioned exportable summary of a contract's EffectSpec for policy, SRE, MCP, and agent consumers. |
| ResilienceProfile | Optional secondary resiliency metadata on a BoundaryContract (retry/circuit-breaker/timeout/… strategies + never-retry classes); not a primary control-plane noun (ADR-0136). |
| DurableEventStore | Extended EventStore port with positioned catch-up (`readAll`), transactional `commit` (events + durable effects), and durable subscription checkpoints (ADR-0135). |
| EventPosition | Database-local monotonic position within one storage partition; distinct from per-stream `seq` and ULID event id (ADR-0135). |
| SQLite partition | One SQLite database file owned by one active storage writer at a time; scale by partitions, not multi-writer shared WAL (ADR-0135). |
| Crew | Alias for Operator Agents — the built-in autonomous Yard services roster; see the Operator Agents row and [operators-sre.md](./operators-sre.md#plan-40). |
| Cross-App Access | IdP-brokered, policy-governed access from a HoBo app or agent to an external app on a user's behalf, using ID-JAG token exchange. |
| Decision graph | Per-decision explainability artifact (`DecisionGraph`) emitted by the FinOps routing control plane, recording candidates generated/rejected, constraint results, policy outcomes, metric vectors, Pareto frontier, preference result, stability decision, rationale, and audit references; DX/OpsX/FinX surfaces read this same graph ([finops-budget-routing-control-plane.md](./finops-budget-routing-control-plane.md)). |
| Delta | Mutable diff applied to an immutable Deployment Set before promotion. |
| Deployment Set | Immutable resolved config of a Camp manifest. |
| Dispatcher | Credit-aware deterministic selector used for placement, dispatch, and traffic decisions. |
| Driver | Execution mechanism a Resource Definition uses, such as `terraform`, `template`, `echo`, `container`, or `custom-webhook`. |
| DX / OpsX / FinX surfaces | The three FinOps control-plane product surfaces over the same decision graph: DX (intent spec, dry-run preview, simulation, "why this placement?"), OpsX (override, freeze, rollback, migrate, incident reroute, blast-radius controls), and FinX (budgets, forecasts, attribution, anomaly signals, commitments, optimization recommendations). |
| Environment network isolation | Fail-closed walls between isolation classes (local-dev/preview/development/staging/production/ephemeral); elevated access uses short-lived capabilities; optional PAM Station capability ([ADR-0133](./adr/02-identity-security.md#adr-0133)). |
| Environment group | Member Camps of one logical environment, promoted or rolled back as a saga. |
| Environment type | Environment classification such as `production` or `ephemeral`, used as a matching dimension. |
| Event model | Durable append-only substrate where facts are `EventEnvelope` records and projections fold replayable streams. |
| Executor | Sandboxed runner that applies IaC or builds artifacts with scoped short-lived credentials. |
| Four-lens taxonomy | Contract means must not break; Eval means should improve; Policy means allowed or denied; Trace means what happened. |
| FinOps advisory plane | Deterministic MeteringView projections that emit advisory cost anomaly, forecast, and rightsizing/commitment recommendation facts; it proposes through gated obligations and never enforces. |
| Gatekeeper | Composite deploy gate combining contracts, policy, evals, conformance, cost, signing, and golden-suite decisions. |
| Golden Suite | Signed bundle of conformance, contract, eval, benchmark, chaos, SLO, and golden-master checks for a deployment. |
| Grain | Virtual actor, HoBo's default concurrency primitive. |
| Harness | Progressive delivery core over OpenFeature, HoBo-shaped OpenDelivery, HoBo-shaped OpenExperiment, and OpenTelemetry. Realized in `@hobo/identity` as `FeatureFlagStore` + `OpenDeliveryEngine` + `OpenExperimentEngine` composed by `Harness`. |
| Continuous Delivery plane | Workload-attested apply of a Gatekeeper-approved resolved Deployment Set (`@hobo/cloud` `src/cd/`), secret-free status/diff, progressive composition via Harness, failure default A2H or sandboxed self-heal in an ADR-0076 lane. |
| Resolved Deployment Set | Post-Matching, Gatekeeper-approved content-addressed plan + secret refs only; the sole CD plane input. |
| A2H | Ask-to-Human handoff: typed package + deadline obligation when progressive/apply/Golden/SLO fails and self-heal is not permitted. |
| SafetyEnvelope | Autonomous-action bounds (blast radius, reversibility, spend, self-causation, max attempts); unknown blast radius fails closed to A2H (ADR-0094). |
| OpenFeature | CNCF flag evaluation API; sole public evaluation surface for application code (`HoboOpenFeatureProvider` / `HoboFeatureClient`). |
| OpenDelivery | HoBo-shaped port (`hobo:delivery`) for canary, blue/green, staged rollouts, traffic shift, and auto-rollback obligations. |
| OpenExperiment | HoBo-shaped port (`hobo:experiment`) for sticky assignment, exposure tracking, and pluggable statistical analysis. |
| Feature flag | Bindle IfC declaration (`features()`) + event-sourced runtime values in the single built-in `FeatureFlagStore` (shared with continuous identity cohorts). |
| HoBo Broker | Runtime brokering authority (**Conductor**) that places Bindles/Camps/Yards/Junctions across providers under the active Rail's policies, wrapping the policy, contract, billing, delivery, and connector-registry planes; realized by `@hobo/broker`. Durable Connections and Rails live on the **Station**; the broker holds short-lived caches only. Distinct from the Identity token broker and the connector runtime broker ([hobo-broker.md](./hobo-broker.md)). |
| Hobo Code | Planned declarative plus generated-stub DSL that lowers to the same manifest IR and SDK constructs as TypeScript authoring. |
| ID-JAG | Identity Assertion JWT Authorization Grant used for Cross-App Access token exchange. |
| IfC | Infrastructure-from-Code, where resources are declared inline and collected by running the component. |
| Junction | Cross-cloud or hybrid scope that federates identity, signed policy packs, signed registry bundles, and inferred connectivity across autonomous Yards. |
| Layered scopes | Infra containment chain `Junction` contains `Yard` contains `Camp` contains `Bindle`; project and app-tenant are separate rollup axes. |
| Mapping Contract | Broker artifact that constrains provider/catalog/resource mapping inputs without giving providers unilateral selection authority. |
| Manifest IR | Deployment intermediate representation produced by authoring and consumed by the Planner. |
| Matching Criteria | Deterministic selector for Resource Definitions, ranked by hard requirements, specificity, priority, objective, and stable tiebreak. |
| Messaging | Unified backend-agnostic publish/subscribe surface over `wasi:messaging` / `topic()` with declared delivery guarantees, consumer groups, dead-letter, and audit events ([ADR-0138](./adr/01-architecture-core.md#adr-0138)). |
| Kafka capability provider | First-class `@hobo/provider-kafka` exporting `wasi:messaging` for durable log backends (Kafka / Redpanda / MSK / Confluent / Event Hubs Kafka protocol), secretless credentials, local Redpanda path ([ADR-0138](./adr/01-architecture-core.md#adr-0138)). |
| Dapr runtime adapter | Optional Camp runtime `@hobo/runtime-dapr` realizing ActorHost + messaging (+ partial workflows) over Dapr sidecars; never the default ([ADR-0031](./adr/01-architecture-core.md#adr-0031), [ADR-0138](./adr/01-architecture-core.md#adr-0138)). |
| Meta-cloud Broker | Hosted authority that validates Contract Manifests against approved Broker Environments and emits Resolution Receipts or Resolution Rejections for Yard consumption. |
| Metric contract | Governed definition (`MetricContract`) of a routing metric's semantics, units, source, normalization, and version under the three-tier model: Tier 0 immutable system metrics, Tier 1 derived metrics via approved transforms, Tier 2 composition-only approved user metrics. |
| MetricVector | Per-candidate vector of metric-contract values (cost, reliability, latency, risk, approved custom metrics) evaluated after constraint filtering and used to build the Pareto frontier. |
| Obligation | Durable HoBo effect required by an allow decision, such as approval, canary, auth middleware, or budget action. |
| Operator Agents | Built-in autonomous Yard services such as SRE, Endpoint Monitor, GitOps, Platform Engineer, UX Designer, SWE, and FinOps. |
| Pareto frontier | Non-dominated candidate set (`ParetoFrontier`) built across metric dimensions; preference weights select only within it — the router never uses one global weighted score, and a stability controller may still override the preferred candidate. |
| Planner | Pure function that turns a Bindle plus mapping into a DeploymentPlan DAG. |
| Planner objective | Soft ranking tiebreak such as `cost`, `latency`, `single-provider`, `carbon`, or `maximize-credits`. |
| Port | Contract boundary; may mean runtime substrate port, infra port, or capability WIT port depending on tier. |
| Pre-approved catalog | Trust-tiered listing set a Yard vouches for and production policy may require. |
| Project | Ownership and rollup axis spanning many Bindles, Camps, and Yards; not an infra containment noun. |
| Projection | Subscribable materialization built by folding the event log into a WIT-record read model. |
| Projection Sink | Optional queryable cache materialized through Matching; the event log remains authoritative. |
| Provider | Adapter implementing cloud, IaC, build, or capability ports for a backend. |
| Relay | Outbound-only proxy inside a private network so a hosted Yard can deploy without inbound access. |
| Resolution Receipt | Broker-issued evidence artifact proving a Contract Manifest was resolved against a specific Broker Environment and catalog snapshot. |
| Resolution Rejection | Broker-issued evidence artifact naming why resolution failed, such as stale, incompatible, ambiguous, or unsupported mapping state. |
| Resource Definition | Rule for realizing a port in a context, including provider, driver, and options. |
| Plugin (HoBo) | External package declaring a `hobo` key (`hobo.plugin/v1`) in its package.json: an entry module plus the `{point, export}` extensions it provides. Parsed by `@hobo/core`, authored via `@hobo/sdk` `definePlugin`, loaded by explicit specifier at the composition root; provider plugins go through the normal `provider.Registered`/`provider.Approved` lifecycle ([ADR-0156](./adr/07-portability-extensibility.md#adr-0156)). |
| Resource Pack | Shareable signed bundle of Resource Definitions. |
| ResourceActor | Controller-style grain that reconciles one resource's desired and actual state. |
| ResourceIntent | Provider-neutral infrastructure request that enters the FinOps routing pipeline as its canonical input, before candidate generation; the router core must not see provider names, SKUs, regions, account IDs, or backend API names. |
| Run | One durable workflow or agent execution represented by a `run.*` event stream. |
| Rightsizing | Advisory recommendation to shrink or scale-to-zero an over-provisioned workload, derived from observed utilization versus the provisioned Workload Profile and applied only through gated proposals. |
| Runtime | Reused term for the SDK primitives package, the `Runtime` interface, or a runtime backend; context names which one. |
| Runtime ports | Durable substrate ports a Camp provides: EventStore, Queue, Streamer, ActorHost, and Clock. Since [ADR-0156](./adr/07-portability-extensibility.md#adr-0156) each is a declared `@hobo/core` port — ActorHost included (`ports/actor-host.ts`), ending its per-package re-declaration. |
| Scope listing | Bindle, Camp, Yard, or Junction distributed as an npm package or structured git repo that exports the constructed scope. |
| SVID | SPIFFE-style workload identity issued by the Yard for keyless auth. |
| Stub | Typed recording placeholder behind a WIT port so an app runs before a real implementation exists. |
| Trainable signature | Signature-only trainable-method declaration (`training.define`): intent + contract + rubric with no body, served by a contract-derived stub until the training engine synthesizes an implementation ([ADR-0125](./adr/03-data-plane.md#adr-0125)). |
| Training artifact | Serialized optimized program (instructions + demos, provenance-pinned JSON) produced by a `training-engine` run and applied at instantiation as the low-risk promotion mode ([ADR-0125](./adr/03-data-plane.md#adr-0125)). |
| The `notify` port | Canonical cloud-messaging transport for email, sms, push, webhooks, ops alerts, app comms, status, and paging. |
| Token budget | Scoped **`TokenBudget`** object capping LLM inference input/output/total tokens per period (`per-run`, `daily`, `monthly`) for tenant/Camp/agent/model/run scopes; enforced by the pre-inference **`evaluateInferenceTokenBudget`** gate over a seq-pinned `MeteringView` ([governance-planes.md#per-token-inference-budgets](./governance-planes.md#per-token-inference-budgets)). Distinct from auth `token.*` credential events. |
| WIT interface | Canonical language-neutral contract form for a HoBo port. |
| WIT-first SDK | SDK model where each language uses generated `hobo:sdk` WIT bindings plus a thin idiom layer. |
| Workload Profile | How a service is realized, such as wasm component, container, serverless, or VM. |
| Continuous Identity Migration | Platform dual-path principal migration (Matching/policy-triggered; zero Bindle config; PrincipalRef continuity; dual fixtures offline). See [ADR-0132](./adr/02-identity-security.md#adr-0132). Composed into Trails as the `identity.continuous` platform recipe without requiring Trail authoring. |
| Trail | Versioned, app-owned continuous migration runbook/recipe pack (schema, data dual, identity dual, junction rebind, cutover). Platform engine in `@hobo/trails`; pure identity continuous remains hands-off. See [ADR-0134](./adr/02-identity-security.md#adr-0134). |
| can-trail | Gatekeeper-compatible dry-run dimension for Trails (compatible with can-migrate / upgrade-migration dry-run shapes). Offline-capable with contract-asserted fixtures. |
| Connection | Durable, **Station-owned** authorization handle for an external app (provider + subject + grantedScopes + opaque vault `credentialRef` + `stationId`). Authorize once; mint short-lived tokens thereafter via the token broker. Event family `connection.*`; CLI/MCP verb `connection`. Cross-Station use fails closed without federation grant. See [Plan 06 §6.9](./ai-native-agent-auth.md), [Connections ADR](./adr/02-identity-security-connections.md), and Station. |
| Rail | Station-owned, content-addressed, versioned policy/engine/billing/connector/guardrail **profile** (not the Guardrail effect language). Activation is an audited fact; receipts pin `railHash`. Bootstrap Rail is sealed least-privilege for `station init`. |

| Session Replay | Privacy-first DOM/session reconstruction for every **App Kit** in a Bindle (`@hobo/replay`, ADR-0137) — not only `web`. Uses rrweb-compatible capture; stores heavy blobs out-of-band; emits `replay.*` lifecycle events. Distinct from control-plane event-log replay and from auth `session.*` events. Local default-on; production sampling/flag gated; `HOBO_REPLAY=0` kill switch. |
| `@hobo/replay` | Package owning Session Replay tracker, privacy masks, dual-fixture storage ports, player/OpenUI descriptors, access policy, retention, metering, CLI/MCP surface, and PACT HTTP surface for all boundaries. |
| Station | Hard control-plane **isolation boundary** a Conductor occupies. One Station = one isolation domain (not multi-tenant by default). Owns Connections, Rails, Station identity, and control-plane event partition. **Not** app-topology containment (Bindle ⊂ Camp ⊂ Yard ⊂ Junction remains). Main setup path: `hobo station init`. Package `@hobo/stations`. Narrative home: [stations.md](./stations.md). |
| Station capability | Declared, schema-versioned facility a Station offers its occupants (`hobo.station-capability/v1`, [ADR-0155](./adr/01-architecture-core.md#adr-0155)): `capability:<kind>:<slug>` over a closed kind vocabulary, with provenance `default`/`discovered`/`declared` and a `required` bit. Formalizes the previously-prose "PAM/Replay/sidecars are Station capabilities". Matching against host evidence is fail-closed and produces a `hobo.station-capability-manifest/v1` beside the Station data. |
| Machine discovery (`hobo-code init`) | Evidence-based, injectable inspection of the machine hobo-code runs on (Node, git, isolation platform matrix, local model server, devenv/nix, harnesses), matched against the default localhost capability set declared on the dev-scenario Station ([ADR-0155](./adr/01-architecture-core.md#adr-0155)). Required-missing fails closed with remediation; report schema `hobo.code.machine-discovery/v1`. |
| Yard | Provider-specific topology and control-plane boundary. **Owns provider selection.** May declare zero Camps (requested shape before a live instance). See [yard-first-placement ADR](./adr/yard-first-placement.md). |
| Yard instance | Live, registered, attested control-plane inventory record (not a fifth topology primitive). |
| Yard runtime registration | Broker-approved template capable of hosting/generating a Yard for one provider/runtime family (not an app runtime backend). |
| Yard shape | Planning record comparing a requested Yard to live instances / generatable runtimes. |
| Yard manifest | Generated IR of a Yard's exposed endpoints, domains, cross-Yard links, residency, and trust requirements. |
| Bindle deployment request | Wire artifact attaching a provider-agnostic Bindle manifest to a requested Yard/shape (the Bindle itself is not mutated). |
| `@hobo/bindles` | App idiom layer for declaring resources, `.allow()` grants, and Bindles. |
| `@hobo/camps` | Topology idiom package for declaring Camps. |
| `@hobo/junctions` | Topology idiom package for declaring Junctions. |
| `@hobo/sdk` | Operator SDK used to configure and self-host a HoBo cloud; distinct from the `hobo:sdk` WIT contract/package. |
| `@hobo/yards` | Topology idiom package for declaring Yards. |
| `.allow(...)` | Capability permission surface that narrows or asserts usage-inferred grants, capped by policy deny ceilings. |
| `hobo:sdk` | WIT contract/package for app primitives and capability/data interfaces; distinct from the `@hobo/sdk` operator SDK. |
| Package namespace map | Canonical import-ownership table for `@hobo/*` packages; see [package-namespaces.md](./package-namespaces.md) (ADR-0087). |
| Capability implementation profile | Provider-neutral semantic contract between a Bindle primitive and a hosted product — `data.postgres/v1` states what PostgreSQL compatibility means without naming a vendor. Open, namespaced, versioned, and arranged in an acyclic refinement graph where a child adds guarantees and never erases a parent's ([ADR-0151](./adr/07-portability-extensibility.md#adr-0151)). |
| Implementation product | A hosted offering that implements one or more capability profiles (Neon Claimable Postgres, Cloudflare D1). Registered as a Resource Definition, never as a profile ([ADR-0151](./adr/07-portability-extensibility.md#adr-0151)). |
| Realization (`native`/`pack`/`bridge`) | How a product satisfies a profile: the provider exposes it directly (`native`), HoBo deploys a signed implementation on generic compute (`pack`), or the runtime fronts a capability in another data plane (`bridge`). A first-class selection fact, disclosed in the offer; widening across it requires explicit policy ([ADR-0151](./adr/07-portability-extensibility.md#adr-0151)). |
| Implementation pack | A signed, digest-pinned deployable that implements a capability profile on generic compute (`pack.postgres.oci/v1`). Ownership follows the Yard or a migrate-on-claim strategy; a pack is never provider-claimable ([ADR-0151](./adr/07-portability-extensibility.md#adr-0151)). |
| Capability binding | Portable, provider-neutral record a product emits for consumers: binding profile, protocol endpoints as non-secret refs, and credential/certificate `secretRef`s. Rotates independently of the logical resource identity ([ADR-0151](./adr/07-portability-extensibility.md#adr-0151)). |
| Connectivity implementation | Runtime-specific projection of a binding into a workload (Cloudflare Hyperdrive, the Neon serverless driver, Upstash REST, service-binding files, WASI config). Connectivity is not a provider of the capability it reaches ([ADR-0151](./adr/07-portability-extensibility.md#adr-0151)). |
| Guest lease | Durable aggregate for work nobody owns yet: bootstrap strategy, provider-reported expiry and claim deadline, renewal rules, quota/cost cap, cleanup policy, fencing token, and status. Restart-safe; expiry and compensation run through timers and the outbox ([ADR-0151](./adr/07-portability-extensibility.md#adr-0151)). |
| Claim item / claim bundle | An item is one subject's ownership transition (mode, deadline, continuity facts, verification, post-claim obligations); a bundle groups items with dependency edges and an atomicity class — `single-resource`, `provider-bundled`, or `best-effort-saga`.
