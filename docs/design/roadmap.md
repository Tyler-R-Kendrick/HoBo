### Success metrics (north-star signals — v1 targets)
- **Time-to-first-deploy** (scaffold → running on a real cloud) — target minutes, not hours.
- **"Same Bindle, N clouds"** — number of providers a single unedited example deploys to.
- **Zero-secret rate** — % of provider access via brokered/federated tokens vs static keys (target ~100%).
- **Agent-completable lifecycle** — % of deploy/operate tasks an agent can do via MCP unaided.
- **Forge yield** — % of requested providers auto-generated that pass conformance.
- **Recovery** — deploy resume time after node loss; projection-rebuild time.

### Sequencing rationale
One v1, built in dependency order. Stages 0–2 stand up the *agnostic deploy* core on one cloud (with governance gating it from the first deploy); stage 3 makes it *AI-native*; stage 4 proves *true multi-provider*; stage 5 adds *extensibility without a community* (Forge); stage 6 hardens for production and lands the breadth (HA, FinOps, full UX, SRE, the `notify` port + governance enforcement + AI-safety + Registry distribution). The risky/novel bets (Forge, multi-region HA) build on a demonstrably solid core, but all of it is v1 — the stages are *how* we deliver a large v1 quickly, not a schedule of separate releases.

### Per-stage build detail (stages 0–6)
The numbered workstreams below are the dependency-ordered build sequence of the single v1 — **not** separate releases. Each stage is independently demoable and must keep prior acceptance gates green (no regressions). Conventions: **port = WIT interface** ([Plan 20](./wasm-runtime-wit.md#plan-20), reference [Plan 24](./wasm-runtime-wit.md#plan-24)) · **provider = capability provider** · **bind = link** · **service = wasm component (default), OCI-container fallback**; every adapter ships against `@hobo/conformance` and examples double as E2E fixtures.

#### Stage 0 — Foundations
Realizes [Plan 1](./architecture.md#plan-01), [Plan 11](./event-model.md#plan-11), [Plan 20](./wasm-runtime-wit.md#plan-20), [Plan 24](./wasm-runtime-wit.md#plan-24), [Plan 9](./verification.md#plan-09). **Objective:** stand up the monorepo, the core contracts (types, ports-as-WIT, event envelope, Capability Manifest schema), the built-in local runtime, and the conformance harness. **Depends on:** nothing (greenfield). Also seeds Resource Definition + Matching types, the Driver interface ([Plan 25](./platform-engineering.md#plan-25)/[Plan 27](./platform-engineering.md#plan-27)) and a Driver conformance slot.
1. **Monorepo & tooling** — pnpm/Turborepo workspace, strict `tsconfig`, Biome, Vitest, Changesets; package skeletons from [Plan 1](./architecture.md#plan-01); enforce the dependency rule (adapters depend only on `core` interfaces); CI typecheck→lint→unit→conformance→build + SBOM/vuln-scan stub ([Plan 12](./security-networking.md#plan-12)).
2. **`@hobo/core` contracts** — EventEnvelope + append/read/idempotency rules ([Plan 11](./event-model.md#plan-11)); port interfaces as TS mirrors of canonical WIT ([Plan 24](./wasm-runtime-wit.md#plan-24)); Capability Manifest schema (`capabilities/auth/cost.json`) + validators ([Plan 6](./ai-native-agent-auth.md#plan-06)); DI/container + the durable `Runtime` interface.
3. **`@hobo/wit` (the ports)** — author the `hobo:*` WIT interfaces + vendor/pin reused `wasi:*` ([Plan 24](./wasm-runtime-wit.md#plan-24)); `jco guest-types` → typed TS bindings.
4. **`@hobo/runtime-local` (built-in engine)** — EventStore (append log + subscriptions/snapshots), Queue (at-least-once + dedup), Streamer, ActorHost (single-writer lease + fencing), deterministic Clock; `testRuntime()` mode for [Plan 9](./verification.md#plan-09).
5. **`@hobo/conformance` (trust boundary)** — harness that runs a suite against any adapter; first suites = the five runtime ports; wire conformance into CI as a required gate.
- **Acceptance gate:** `runtime-local` passes all runtime-port conformance in CI; an event log appends and replays to identical state; `jco`-generated types compile; dependency-boundary lint passes.
- **Key risk/hook:** wasm host of record (Wasmtime vs jco-in-Node) — decide here, it colors stage 1; `hobo:*` naming/versioning vs upstream `wasi:*` churn; built-in-engine scope vs external runtime in prod ([Plan 5](./reliability-observability-cost.md#plan-05)).

#### Stage 1 — SDK on the local runtime
Realizes [Plan 2](./sdk-api.md#plan-02), [Plan 21](./authoring-resources-wiring.md#plan-21), [Plan 22](./authoring-resources-wiring.md#plan-22), [Plan 20](./wasm-runtime-wit.md#plan-20), [Plan 15](./developer-experience.md#plan-15). **Objective:** author an app IfC-style, run it as a wasm component on `runtime-local` (workflows/actors/sagas/agents), collect resources into a manifest — all offline, with replay. **Depends on:** stage 0. Resources gain a `class`; local Planner resolves Resource Definitions by Matching ([Plan 25](./platform-engineering.md#plan-25)) and `hobo dev` exercises Deltas→Sets + env types ([Plan 26](./platform-engineering.md#plan-26)).
1. **Authoring & resources (`@hobo/sdk`)** — resource builders for the full catalog ([Plan 21](./authoring-resources-wiring.md#plan-21)); the `.allow(verbs)` model (IAM + links + token scope); handler/trigger registration; the explicit `bindle()` topology escape hatch.
2. **IfC resource-collection → manifest IR** — resource-collection mode (capture resources + `.allow()` without running handlers, [Plan 21](./authoring-resources-wiring.md#plan-21)); emit the manifest IR ([Plan 22](./authoring-resources-wiring.md#plan-22)), content-address + record `bindle.ManifestProduced` ([Plan 11](./event-model.md#plan-11)); lazy Aspire-style bindings → typed `ctx.bindings.<name>`.
3. **Runtime primitives (`@hobo/runtime`)** — `step`/`workflow`/`emit`/`sleep`/`cron`/hooks/streams; `actor`/grain + `saga`; `agent()` skeleton + `stub()` placeholders ([Plan 23](./forge-generated-stack.md#plan-23)); determinism (seeded RNG/clock) verified by replay.
4. **Components (`@hobo/componentize`, `@hobo/build-wasm`)** — TS service → wasm component via jco/componentize; run on the local wasm host wired to `runtime-local` providers; produce/load OCI artifacts locally.
5. **CLI & local dashboard (`@hobo/cli`)** — `hobo new`/`dev`/`collect`/`inspect`/`logs`/`stub`; local dashboard MVP (topology, run inspector, resource browsers, triggers) ([Plan 7](./developer-experience.md#plan-07)).
- **Acceptance gate:** `hello-bindle` runs offline as a wasm component exercising workflow+actor+saga+stubbed port; `hobo collect` matches a manifest fixture; replay==live-state determinism test green; dashboard shows topology + a run trace + triggers.
- **Key risk/hook:** directive (`"use workflow"`) compiler transform vs runtime wrappers ([Plan 2](./sdk-api.md#plan-02)); IfC collection fidelity for non-TS; jco/StarlingMonkey build ergonomics + cold-start.

#### Stage 2 — First real deploy
Realizes [Plan 3](./control-plane.md#plan-03), [Plan 4](./control-plane.md#plan-04), [Plan 10](./architecture.md#plan-10), [Plan 11](./event-model.md#plan-11). **Objective:** take a collected manifest and deploy it to one real cloud through a minimal Yard, with the event-sourced deployment lifecycle + crash-resume. **Depends on:** stage 1. The Planner resolves via Resource Definitions + Matching ([Plan 25](./platform-engineering.md#plan-25)), IaC apply is the `terraform` Driver ([Plan 27](./platform-engineering.md#plan-27)), deployment runs Delta→Set ([Plan 26](./platform-engineering.md#plan-26)); the **Gatekeeper** lands at Delta→Set — `contract-engine` + `can-deploy` ([Plan 29](./contracts-policy-flags.md#plan-29)) and `policy-engine` ([Plan 30](./contracts-policy-flags.md#plan-30)) block an unsafe first deploy with an explainable, event-sourced reason.
1. **IaC adapter (`@hobo/iac-pulumi`)** — wrap the Pulumi Automation API (preview/apply/destroy/refresh); per-resource stack model + state backend + outputs ([Plan 3](./control-plane.md#plan-03)).
2. **First CloudProvider (Cloudflare *or* Fly)** — a few capability ports (`web`/`service`, `kv`, `objectStore`) as a capability provider; equivalence-class mappings + `.with(...)`; publish its Capability Manifest ([Plan 6](./ai-native-agent-auth.md#plan-06)) + link wiring ([Plan 20](./wasm-runtime-wit.md#plan-20)).
3. **Production runtime (`@hobo/runtime-postgres`)** — the five runtime ports on Postgres (graphile-worker queue, NOTIFY/LISTEN streams, snapshots); pass runtime-port conformance.
4. **Yard (first cut) (`@hobo/cloud`)** — Gateway (RPC+REST, authn/z, commands→events); Planner (manifest IR → `DeploymentPlan` DAG, [Plan 3](./control-plane.md#plan-03)); Orchestrator + ResourceActors (reconciliation FSM + choreography, [Plan 4](./control-plane.md#plan-04)); Executors (Firecracker-sandboxed IaC apply + build, scoped creds); event store = Postgres runtime; OCI artifact push.
5. **CLI deploy path** — `hobo plan`/`deploy`/`destroy`/`inspect deploy`; `hobo login` (dev SVID stub).
- **Acceptance gate:** `hello-bindle` deploys to one real cloud and serves traffic; kill the Yard mid-deploy → resumes from the event log; a provisioning failure → saga compensation rolls back in reverse-dependency order; the deployment timeline projection reconstructs the run.
- **Key risk/hook:** default first provider (Cloudflare vs Fly vs local Docker); per-resource vs grouped IaC stacks + drift policy ([Plan 3](./control-plane.md#plan-03)); deployed wasm host target.

#### Stage 3 — AI-native core
Realizes [Plan 6](./ai-native-agent-auth.md#plan-06), [Plan 12](./security-networking.md#plan-12), [Plan 14](./reliability-observability-cost.md#plan-14). **Objective:** agents become first-class principals — keyless identity + token brokering, a Capability Manifest registry, durable agents, an MCP control surface — so an agent deploys with zero static secrets + a full audit trail. **Depends on:** stage 2. Also lands the **HoBo Relay** (outbound-only private-network deploys) + the **GitOps publisher** ([Plan 28](./platform-engineering.md#plan-28)), both leaning on the SVID work; the Registry begins accepting Forge-generated Definitions/Packs.
1. **Identity (`@hobo/identity`)** — SVID issuance (SPIFFE-style JWT-SVID, attestation + rotation, [Plan 6](./ai-native-agent-auth.md#plan-06)); OIDC provider (federation); token broker (SVID → resource-scoped provider token via OIDC federation/OBO/MCP-OAuth2.1); `identity.*`/`token.*` → CredentialAudit projection ([Plan 14](./reliability-observability-cost.md#plan-14)).
2. **Registry (`@hobo/registry`)** — ingest/verify provider Capability Manifest, index capabilities/auth/cost; capability search API + plugin records (provenance, conformance report).
3. **`.allow()` → scope wiring** — connect `.allow()` ([Plan 21](./authoring-resources-wiring.md#plan-21)) to least-privilege IAM + wasm links + brokered token scope (one declaration, three effects); policy gates for high-risk actions ([Plan 12](./security-networking.md#plan-12)).
4. **Durable agents (`@hobo/runtime` `agent()`)** — model/instructions/tools, tools execute as steps, runs event-sourced + replayable; inject `ctx.identity` + `ctx.token(...)` + guardrails (`spendCapUsd`).
5. **MCP control surface (`@hobo/mcp`)** — tools (`list/get_bindle`, `plan`, `deploy`/`promote`/`rollback`/`destroy`, `inspect_run`/`tail_logs`, `search_registry`, `request_token`, `get_drift`/`heal`); MCP auth via SVID; publish `llms.txt`/`docs.json`.
- **Acceptance gate:** an agent deploys a bindle via MCP using only brokered short-lived tokens (no static secrets), `token.*` events exist + run replayable; a high-risk action blocks on a policy gate until approved; Registry serves capabilities from an ingested Manifest, `request_token` returns a scope bounded by `.allow()`.
- **Key risk/hook:** Capability Manifest as an open spec (MCP-auth/OAuth-OBO/SPIFFE/AIP); delegation chains (agent→sub-agent); policy language for guardrails/ABAC (typed TS vs Rego/CEL).

#### Stage 4 — Multi-provider + wiring depth
Realizes [Plan 3](./control-plane.md#plan-03), [Plan 13](./security-networking.md#plan-13), [Plan 22](./authoring-resources-wiring.md#plan-22), [Plan 2](./sdk-api.md#plan-02). **Objective:** prove the agnostic thesis — the same bindle deploys to multiple clouds via mapping rules, with cross-provider connectivity + typed provider-specific optimization, no app edits. **Depends on:** stage 2 (benefits from stage 3 for cross-cloud identity/links). Resource Definitions shine here (per-`envType`/`class` definitions, [Plan 25](./platform-engineering.md#plan-25)/[Plan 26](./platform-engineering.md#plan-26)); add echo/container/custom-webhook Drivers + Packs + Relay + GitOps publisher ([Plan 27](./platform-engineering.md#plan-27)/[Plan 28](./platform-engineering.md#plan-28)); deepen the contract plane (observed/promoted contracts, version-skew `can-deploy`, [Plan 29](./contracts-policy-flags.md#plan-29)) + capability contracts + region/data-classification obligations ([Plan 30](./contracts-policy-flags.md#plan-30)/[Plan 12](./security-networking.md#plan-12)).
1. **Additional CloudProviders (AWS, Azure)** — capability ports for the full catalog on AWS + Azure; equivalence classes per port; per-provider Capability Manifest + typed `.with(...)` builders.
2. **Mapping rules & resolution** — the three mapping styles in `hobo.config.ts` (whole-app/per-tier/per-binding, [Plan 2](./sdk-api.md#plan-02)); Planner resolution order + `prefer`/`require` negotiation (rationale on `deployment.Planned`); `.with(...)` inert for non-resolved providers.
3. **Cross-provider networking ([Plan 13](./security-networking.md#plan-13))** — service identity via SVIDs; links resolve across providers; connectivity tiers (native private → interconnect → overlay mesh → public + mTLS); annotate `bind` edges with tier + estimated egress.
4. **Wiring/manifest parity ([Plan 22](./authoring-resources-wiring.md#plan-22))** — Aspire-style reference/config injection for the container/wasm-host fallback; uniform `AddContainer`-style config applied to components + containers.
- **Acceptance gate:** `multi-cloud-shop` deploys the same bindle to two providers via mapping rules; cross-cloud services connect over mTLS keyed by SVIDs; a `require`d-but-unoffered capability → `deployment.PlanRejected` with a precise reason; switching a resource's provider touches only `hobo.config.ts`.
- **Key risk/hook:** overlay-mesh tech (WireGuard vs eBPF/Cilium vs Tailscale-style); Planner objective when multiple providers satisfy (cost vs latency vs stay-on-one-cloud, [Plan 16](./reliability-observability-cost.md#plan-16)); Crossplane coexistence.

#### Stage 5 — Forge
Realizes [Plan 6](./ai-native-agent-auth.md#plan-06), [Plan 23](./forge-generated-stack.md#plan-23), [Plan 9](./verification.md#plan-09). **Objective:** break the human bottleneck on breadth — AI generates providers (new backends) + implementations (components behind WIT ports), certified by conformance + trace replay, promoted through gates. **Depends on:** stage 3 (identity/registry/sandbox) + stage 4 (reference adapters). The promotion gate is explicit — conformance(contract) + eval thresholds + policy ([Plan 23](./forge-generated-stack.md#plan-23)/[Plan 29](./contracts-policy-flags.md#plan-29)/[Plan 30](./contracts-policy-flags.md#plan-30)) with champion/challenger + shadow traffic; Forge can also generate Resource Definitions/Packs ([Plan 25](./platform-engineering.md#plan-25)/[Plan 27](./platform-engineering.md#plan-27)).
1. **Full conformance coverage** — `@hobo/conformance` suites per WIT interface (every capability port, the trust boundary, [Plan 9](./verification.md#plan-09)); coverage report; gate publishing on per-interface pass.
2. **Forge: provider generation** — ingest backend docs/OpenAPI/Terraform-provider/Capability-Manifest → candidate `@hobo/provider-x`; sandbox (Firecracker + wasm sandbox, no egress) → run conformance; on pass sign+publish to the Registry with provenance + report (`forge.PluginCertified`), on fail feed errors back ([Plan 6](./ai-native-agent-auth.md#plan-06)).
3. **Stubs & implementation generation** — stub system (any WIT port backed by a recording/typed stub, [Plan 23](./forge-generated-stack.md#plan-23)); Forge generates stub→full implementation from WIT + conformance + recorded traces, validated sandboxed + replay-as-tests.
4. **Auto-evolve & gated live-fix** — policy engine classifies low-risk(auto) vs high-risk(human-approval hook) ([Plan 12](./security-networking.md#plan-12)); auto-evolve on new traces/SLO/cost; live-fix via the gated canary/rollback saga ([Plan 5](./reliability-observability-cost.md#plan-05)), failing trace → permanent regression test; record every generation/validation/gate/apply as events ([Plan 11](./event-model.md#plan-11)).
- **Acceptance gate:** `hobo forge <provider-url>` yields a certified provider that passes conformance + appears (signed) in the Registry; a stubbed port gets an AI-generated implementation that passes conformance + reproduces recorded traces, promoted through a gate; a simulated SLO regression triggers a gated live-fix that auto-rolls-back on failure + keeps the failing trace as a test.
- **Key risk/hook:** "low-risk auto" threshold ([Plan 5](./reliability-observability-cost.md#plan-05)/[Plan 12](./security-networking.md#plan-12)); Forge model/eval design + human-certification threshold for high-trust ports; plugin signing/provenance (SLSA) + supply-chain trust ([Plan 12](./security-networking.md#plan-12)).

UI-layer generation + marketplace monetization are **out of scope** ([ADR-0064](./adr/08-scope-and-requirements.md#adr-0064)). Also adds Pipelines + Workload Profiles ([Plan 28](./platform-engineering.md#plan-28)/[Plan 27](./platform-engineering.md#plan-27)); the Operator Crew on the HA substrate — Endpoint Monitor + SRE operator with incident management/runbooks/self-healing ([Plan 40](./operators-sre.md#plan-40)/[Plan 44](./operators-sre.md#plan-44), on [ADR-0045](./adr/04-governance-verification.md#adr-0045)); gates hardening (obligations as durable effects + remediation/auto-fix loop, [Plan 30](./contracts-policy-flags.md#plan-30)/[Plan 23](./forge-generated-stack.md#plan-23)); portability/patchability hardening (component-host conformance [ADR-0067](./adr/01-architecture-core.md#adr-0031)/[Plan 22](./authoring-resources-wiring.md#plan-22) + derivative upgrade paths [ADR-0068](./adr/07-portability-extensibility.md#adr-0057) over [ADR-0024](./adr/07-portability-extensibility.md#adr-0024)/[Plan 43](./forge-generated-stack.md#plan-43)).
1. **Reliability & HA ([Plan 5](./reliability-observability-cost.md#plan-05))** — actor leases + fencing tokens + placement/failover; control-plane HA (quorum event-store replication, leader election); provider resilience (circuit breakers, retry budgets, bulkheads); drift loop (resync + `heal`/`propose`/`ignore`).
2. **Deployment strategies ([Plan 5](./reliability-observability-cost.md#plan-05))** — saga templates (recreate/blue-green/canary/progressive) with health-gated promotion + auto-rollback; wire data-plane + provider health signals into the gates.
